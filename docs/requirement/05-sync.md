# 05 — クラウド同期（optin・Freemium 有料軸）

> ## ⚠️ 2026-08 追補：同期と全置換の排他・競合通知の廃止・退避の上限
>
> 実運用（MCP 併用）で挙がった 3 点への対応。上位の設計（CAS＋三方向差分）は変えない。
>
> ### 1. 全置換（復元・AI の変更の取り込み・ファイル取り込み）と同期の排他（D-SYNC2-EXCL）
>
> 全置換は「ローカル全体を差し替え、同期 base を全消しする」操作だが、自動同期は 5〜10 秒おきに
> 走るため両者が重なりうる。重なると **base 全消しの後に in-flight の reconcile が base を書き戻し**、
> 次の同期が「base はあるのにローカルに無い」＝ケース6と誤認して **purgeRemote（サーバから削除）**を
> 出す — 取り込んだ作品が全端末から消える経路があった。対策は `src/ui/sync/sync-gate.ts`：
> 全置換を排他区間として実行し、①区間中は新しい reconcile を走らせない ②区間の開始で世代
> （epoch）を進め、実行中の reconcile は以後の**あらゆる書き込み（push・pull・base 更新）を停止**し
> 結果も破棄する（`null` を返す＝画面も書き換えない）。区間は `createLocalBackupIO().replaceAll`
> に置き、クラウド復元・AI の取り込み・ファイル取り込みの全経路を一括で覆う。
>
> ### 2. 競合はトーストで知らせない（D-SYNC2-QUIET）
>
> 旧：競合のたびに「別端末の変更と競合したため新しい方を採用しました（N件・負けた版は端末内に退避済み）」を
> トースト表示。同期は編集のたびに走るので通知が鳴り続け、しかも **ローカルが勝った場合は退避が
> 起きていない**のに「退避済み」と出ており、退避先も示していなかった（不安だけが残る）。新：
>
> - **ヘッダーに「同期中…」**（`sync-status` → `TopAppBar`）だけを淡々と出す。軽量 poll では点灯せず、
>   点滅防止に最低 900ms は灯す。マイライブラリの保存状態インジケータにも「クラウド同期」行を追加。
> - 競合の報告は**実際に決着したものだけ**にする。従来は計画段階の競合をそのまま報告していたため、
>   オフラインで pull できなかった・往復中の編集で再計画に回した・開いている作品で見送った場合にも
>   通知が出ていた（＝何も起きていないのに鳴る）。再計画ぶんの二重計上も畳む。
> - 退避先は **データ管理 →「同期で退避した版」**（`SyncLostDialog`）から辿れる。作品の競合は
>   履歴（`snap:<workId>`）に `origin='sync'` 付きで入り、履歴パネルに「同期で退避」と表示される。
>
> ### 3. 退避の上限と置き場所（D-SYNC2-LOSTCAP）
>
> `synclost:<syncId>` は 1 アイテム 1 世代のまま、**全体で最大 20 件**に制限し、超過分は古いものから
> 押し出す（`SyncLostRepository`）。一覧・書き出し・削除の UI を持たせ、旧形式（`{at,json}` だけ）も
> 表示できるようにした。他端末の削除が届いたときの作品の退避先は履歴から**この一覧へ変更**した：
> 作品が消えると履歴を開く画面が無くなり、本人に見えないまま `snap:<workId>` が端末に溜まり続けるため
> （内容は画像を除いた JSON で持ち、ファイルへ書き出せる。履歴側は消す）。
> 保持数の全体像＝**クラウドバックアップ 20 世代（押し出し）／作品の履歴 20 版／退避 20 件**。
>
> ### 4. AI が読むライブスナップショットの鮮度
>
> ライブへの push 契機に **sync-touch（構造・プロット・ネタ帳の編集）**を追加し、送信失敗時は
> 未送信状態へ戻して次の契機で送り直すようにした。プロットだけを直した状態が AI に届かないと、
> AI が古い前提で書き、その取り込みで手元の編集が押し戻される（同期が D1 から取り戻すが、
> 退避が無用に増える）ため。

> ## ⚠️ 2026-08 改訂：CAS＋三方向差分による自動同期の再導入（Phase A＋B）
>
> 2026-07 改訂（直下）で自動双方向同期を廃止し「バックアップ/復元モデル」へ一本化したが、実運用で
> **スマホ/PC を使い分けるたびに手動バックアップ→復元を往復するのは不便**であり、会員（クラウド束の
> 購入者）はそもそもクラウド前提で使うことが分かった。そこで、廃止の根本原因だった**「黙った上書き」を
> 構造的に排除できる形**に設計し直したうえで、自動同期を再導入する。直下の 2026-07 改訂ブロックは
> 廃止判断の経緯（歴史）としてそのまま残すが、**現行の挙動は本ブロックが優先**する。
>
> ### 旧設計の 3 失敗と対策の対応表
>
> | 旧設計の失敗 | 原因 | 今回の対策 |
> |---|---|---|
> | ログアウト中のローカル編集がログイン後の pull で上書き | 自動 pull が LWW で**黙って**無条件上書き | **CAS push**（`x-base-hash` がサーバ現況と不一致なら 409）＋**三方向差分**（端末ごとの base 記録 `syncbase:<workId>` と突き合わせ、pull でローカルを自動上書きするのは **clean（未編集）のときだけ**）。真の競合（両側変更）は LWW で解決するが、**敗者は必ず snapshot（`snap:<id>`）へ退避しトーストで通知**する（黙らない） |
> | 別端末で削除した作品が pull で復活 | 削除がローカル状態のみで、pull が知らずに作品を戻す | **共有ゴミ箱**（D1 `works.trashed_at`・migration `0003_trash_sync`）＝ active / trashed / purged の 3 状態を端末間で伝播。purge は**トゥームストーン**（`deleted=1`・blob 削除・行は残す）で「削除したこと」自体を同期する。編集 vs 削除は LWW（編集が新しければ復活） |
> | 各端末でゴミ箱が増殖 | trashed が端末ローカルで非同期 | 同上（共有ゴミ箱）。trash / restore は `PATCH`（blob 不変・`updatedAt` LWW）で即時伝播する |
>
> なお旧設計の前提だった**単一アクティブセッション（別端末押し出し）は復活させない**
> （D-SYNC2-NOSESSION）。同時編集の衝突はセッションで排除するのではなく CAS＋三方向差分が検出して
> 安全に解決する。複数端末の常時ログイン可は 2026-07 改訂のまま維持する。
>
> ### 同期スコープ（D-SYNC2-SCOPE 改：Work＋構造＋ネタ帳＋執筆の記録＋プロフィール）
>
> 当初（D-SYNC2-SCOPE）は自動同期のスコープを **Work（＋共有ゴミ箱の状態）だけ**に絞っていたが、
> スコープを拡張し、自動同期が運ぶのは **Work＋共有ゴミ箱＋構造レイヤー（アウトライン/相関図/
> マインドマップ）＋ネタ帳＋執筆の記録（activity）＋プロフィール（ペンネーム・アバター）**とする。
> 構造・ネタ帳・プロフィールは Work と同じ CAS＋三方向差分（D-SYNC2-ITEMS・下記）、執筆の記録は
> 性質が異なるため max マージの別方式（D-SYNC2-ACTIVITY-DB・下記）で運ぶ。これで端末間で
> 行き来しない状態は残らず、自動クラウドバックアップ（Phase A）は純粋な世代付き保険となる。
> 3 つのクラウド書き込みの住み分け：
>
> | 機構 | 目的 | 発火 |
> |---|---|---|
> | 自動同期（Phase B） | Work＋構造＋ネタ帳＋執筆の記録＋プロフィールを端末間で行き来（差分・双方向） | 下記トリガ参照 |
> | 自動バックアップ（Phase A） | 全状態の世代付き遠隔バックアップ（保持世代 20）＝誤操作・破損からの復元用の保険 | 編集静止 5 分・ただし前回クラウドバックアップから 60 分以上 |
> | ライブスナップショット（MCP） | AI に読ませる最新 1 オブジェクト（版は増えない） | MCP 接続中の編集をデバウンス |
>
> ### 構造・ネタ帳・プロフィールの同期（D-SYNC2-ITEMS）
>
> 構造レイヤー・ネタ帳・プロフィールは **Work と同じ CAS＋三方向差分**で同期する。D1 `works`
> テーブル・既存 `/api/sync/*` API をそのまま流用し、行キーに種別プレフィックス付き id
> （`structure:<id>` / `idea:<id>` / `profile:me`）を使う＝**新規 migration・サーバ改修なし**。
> これらにはゴミ箱概念がないため trash 系の状態遷移は使わず、削除は**トゥームストーン直行**。
> 競合の敗者は snapshot 機構が無い代わりに **`synclost:<syncId>`（1 世代）へ退避しトーストで
> 通知**する（「黙って消えない」原則の維持）。構造の pull は執筆画面で開いている作品に紐づく
> ものでも適用する（構造ビューは自前 state 表示で IDB 上書きと衝突しない。見送ると /write 内で
> 待つ端末が永遠に受信できない）。
> プロフィールは端末に 1 件の singleton（`profile:me`）で、`updatedAt`（設定時に刻印）の LWW。
> **一度も設定していない端末（updatedAt なし）は push しない**＝新端末はリモートから pull される
> だけで、「ローカル欠落」と誤認した purgeRemote も起きない。リモートのトゥームストーンでも
> ローカルのプロフィールは消さない（防御・プロフィールに削除操作はない）。
>
> ### 執筆の記録の同期（D-SYNC2-ACTIVITY-DB）
>
> 執筆の記録（activity＝日別カウンタ date/added/removed/saves）は性質が異なるため別方式とする。
> 原稿・PII を一切含まないため、R2 暗号化ブロブではなく **D1 `activity` テーブルに平文の行で保持**
> する（migration `0006_activity_sync`）。同期は `POST /api/sync/activity`＝クライアントが全日分を
> 送り、サーバが**日付ごと・フィールドごと max マージ**（UPSERT）して全量を返す。加算的データなので
> 衝突が原理的に起きない＝LWW/CAS/base/409 は不要。net は保存せず added−removed から導出する。
> 制約＝同一日に複数端末で書いた場合は合算ではなく大きい方が残る（過少方向・草/ストリーク用途で
> 実害なし）。退会時の reaper は activity 行も削除する。**プライバシー注記**：サーバに平文で置くのは
> 日付と文字数カウンタのみで、原稿・タイトル・図鑑・PII は含まれない。
>
> ### API（`/api/sync/*`・全エンドポイント `verifyMember`）
>
> | エンドポイント | 役割 | 主な応答 |
> |---|---|---|
> | `GET /api/sync/version` | 同期世代の軽量チェック（works の MAX(synced_at)・activity の MAX(updated_at)）。前回値から動いていなければクライアントは本同期を省略＝~15 秒ポーリングを安くする | 200 |
> | `GET /api/sync/manifest` | 全 work のメタ一覧（`RemoteWorkMeta[]`＝updatedAt / trashedAt / deleted / docHash / docSize / syncedAt） | 200 |
> | `GET /api/sync/work?id=` | 平文 Work JSON を復号して返す（`x-doc-hash` / `x-updated-at` / `x-trashed-at` ヘッダ付き） | 200／404 |
> | `PUT /api/sync/work?id=` | **CAS push**。受理条件＝①行なし：`x-base-hash === ''` のみ ②行 live：`x-base-hash === row.doc_hash` のみ ③トゥームストーン：`x-updated-at > row.updated_at` のみ（編集勝ち＝復活）。不一致は 409 `{error:'conflict', meta}` | 200／409 |
> | `PATCH /api/sync/work?id=` | ゴミ箱状態の伝播（blob 不変）。`updatedAt` の LWW で古い patch は棄却 | 200／404／409 |
> | `DELETE /api/sync/work?id=&at=` | purge＝トゥームストーン化（R2 削除・D1 行は残して削除を伝播）。行なし/トゥームストーン済みは冪等 200。**古い purge（`at < row.updated_at`＝purge 後に別端末が編集）は 409 で棄却**＝削除で新しい編集を消さない（編集勝ち） | 200／409 |
> | `POST /api/sync/activity` | 執筆の記録の同期。クライアントが全日分の日別カウンタを送り、サーバが**日付ごと・フィールドごと max マージ**（D1 `activity` へ UPSERT）して全量を返す。加算的データゆえ CAS/base 不要・409 なし（D-SYNC2-ACTIVITY-DB） | 200 |
>
> 制限は 2026-06 決定（D-SYNC-CAPACITY）を踏襲：変更系 60 req/min/user（429）・25 MB/work（413）・
> 1 GB/user（507）。超過は同期だけ停止・ローカルは無制限（D-PLAN-LOCALDATA）。
>
> ### トリガ
>
> 会員のみ・手動操作不要：①mount/ログイン時の全体 reconcile ②store 変更・構造/ネタ帳編集
> （sync-touch シグナル）の **1.5 秒 coalesce**（素早くタブを閉じても取り残しにくい長さ。
> 変更系 fetch には keepalive を付け、閉じる直前の送信も本文 60KB 未満なら生き残る。
> 本文はさらに自動保存デバウンス 1 秒が直列に先行＝編集停止から約 2.5 秒でサーバ着）
> ③foreground 復帰・window focus・画面遷移で即 poll（最小 5 秒間隔）④表示中の軽量 poll
> （`/api/sync/version` の世代が動いたときだけ本同期）は**アダプティブ 2 段変速**＝
> マウント・画面遷移・復帰の直後 30 秒は 5 秒間隔（端末切替直後がいちばん急ぐ）、
> それ以外は 10 秒間隔＋ 5 分ごとの完全同期 ⑤pagehide flush。
> 409（CAS 敗北）は 1 回だけ再 reconcile・多重実行ガードあり。
> 執筆の記録の POST は「ローカルが前回送信から不変・かつ poll の activity 世代も不動」なら
> スキップし、coalesce 短縮ぶんの変更系リクエスト増を相殺する（60 req/min の余裕を保つ）。
> **執筆画面で開いている作品への pull は下書きが未保存（dirty）の間だけ見送り**、確定後は開いた
> まま反映して `store.refreshOpenWork()` でエディタ状態を追随させる（図鑑・本文もページ遷移
> なしで届く）。**trash／purge は開いている間は常に見送り**、画面を離れた後の reconcile に
> 委ねる（エディタ表示との食い違い防止＝旧「編集中に他端末の変更を引っ張らない」の継承）。
> pull は実行直前にローカル内容ハッシュを再検証し、往復中に編集が入っていたら上書きせず再計画へ。
> purge の伝播（DELETE）に失敗したときは base を温存し、消した作品の pull 復活を防ぐ。
>
> 決定 ID は §5 の **D-SYNC2-CAS / D-SYNC2-3WAY / D-SYNC2-SCOPE / D-SYNC2-AUTOBACKUP /
> D-SYNC2-NOSESSION / D-SYNC2-ITEMS / D-SYNC2-ACTIVITY-DB**。受け入れ条件は §8 末尾
> 「2026-08 追補（Phase A/B）」に追記した。

> ## ⚠️ 2026-07 改訂：自動双方向同期を廃し「バックアップ/復元モデル」へ一本化
>
> 実運用で「ログアウト中のローカル編集がログイン後 pull で上書きされる」「別端末で削除した作品が復活・
> ゴミ箱が増殖する」という問題が判明。根本原因は**自動の双方向 pull が LWW で黙って上書きする**こと
> だったため、**自動 pull と自動双方向同期を全廃**し、以下のモデルへ移行した（本文以降の §2〜§5 の
> 「双方向 LWW / 単一アクティブセッション / 共有ゴミ箱 / autosave push」等は**旧設計**で、下記が現行）。
>
> - **ローカル IndexedDB が常に唯一の正本**。クラウドへは push しかせず、**自動 pull でローカルを上書き
>   しない**（ローカルファースト原則 §0 を文字通り実装）。
> - **クラウド＝全体バックアップ**：全状態（全作品＋ゴミ箱＋プロフィール）を1スナップショットに直列化→
>   gzip→AES-GCM 暗号化して **R2 に時刻付きで保存**（`/api/backup`・`src/core/backup`・
>   `src/ui/backup/backup-service`・`CloudBackupDialog`）。**手動「今すぐバックアップ」のみ**（自動
>   バックアップは将来）。保持世代 20・R2 一覧で管理（新規 migration 不要）。
> - **復元＝全置換**：バックアップ時点を選び、**ローカル全体をその時点で置換**（`repo.replaceAll`）。
>   置換前に現在をクラウドへ退避するかは任意（既定オフ）。version/スキーマ検証を通らないものは復元しない。
> - **複数端末**：明示バックアップ/復元なので同時編集の衝突が無く、**単一アクティブセッション（別端末
>   押し出し）は撤去**（token/claim/status/superseded/`X-Session-Token`・per-work sync/manifest API を
>   退役）。複数端末に常時ログインできる。失効時の全端末ログアウトは Clerk `deleteUser` で担保。
> - **課金ゲート**：member 判定・402 は `/api/backup`（`verifyMember`）に集約（旧 `/api/sync/*` は退役）。
> - **ゴミ箱**：ローカルのみ（同期しない）。全体バックアップには含まれ、復元で一緒に戻る。
> - **作品ごとの版履歴（クラウド版）** は将来の enhancement（本改訂では全体スナップショットのみ）。
> - **AI・MCP アクセス（read-only リモート MCP）**：手動バックアップとは別に、接続した会員の編集を
>   デバウンスで **1 オブジェクト `${userId}/live` に上書き**する「ライブスナップショット」を自動保存し
>   （`PUT /api/backup`・版は増えない・`use-live-snapshot`）、MCP エンドポイント `/api/mcp`
>   （Streamable HTTP・JSON-RPC 2.0・`functions/api/_lib/mcp-server`）がこれを復号して読む。
>   認証は **AI クライアント用の専用トークン**（`Authorization: Bearer mcp_…`・`mcp_tokens`／migration 0004・
>   SHA-256 ハッシュのみ保存・`/api/mcp/token` で発行/失効）で、Clerk JWT ではない（AI クライアントは
>   Clerk 認証を張れないため）。データ源が「同期済み作品」ではなく**接続時だけ上げるライブスナップショット**
>   な点が、自動同期廃止に伴う本改訂での差分。ツールは read-only 3種（`list_works`/`get_work`/`get_glossary`）。
>   未接続・非会員は一切 push しない＝opt-in した会員のデータだけが上がる（漏洩境界＝§1.2）。UI は
>   「AI に接続」（`McpConnectDialog`・会員のみ）。
>
> 以降の本文は設計の経緯として残すが、**現行の挙動は上記が優先**する。

## 0. 位置づけ

- **optin**：既定は完全ローカル（サーバへ何も送らない）。ユーザーがアカウントを作り「同期する」と選んだときだけ有効。
- **Freemium の有料軸＝「クラウド束」**：無料＝ツール本体（書く＋出す＋ローカル保存）。有料＝**我々のサーバを使う機能の束**＝クラウド同期（アンカー）／複数端末／自動バックアップ／AI・MCP アクセス／（将来）容量・クラウド版履歴。原則は「サーバが要るもの＝有料、純ローカル＝無料」。アカウント＝課金接点。詳細は §1.2。
- ローカルファースト原則は不変：同期は IndexedDB 正本の**上に乗る複製**であって、置き換えではない。オフラインでも全機能が動く。

## 1. 確定事項

| 項目 | 決定 |

| 競合解決 | **単一セッションで同時編集を構造的に排除**するため通常は競合が起きない。残余（オフライン編集の取り残し）への保険として **Work 単位 LWW（`updatedAt`）＋負け版を local snapshot へ退避**のみ。話/ブロック単位マージ・CRDT は持たない。 |
| 暗号化 | **サーバ側 at-rest 暗号化・鍵はサーバ管理（＝パスワード忘れでも復旧可）**。E2E/ゼロ知識は将来の上級オプションへ温存。 |
| アカウント | **有料会員のみが持つ**（クラウド同期の identity ＋ 課金接点）。ゲストはアカウント不要・完全ローカルで全機能。 |
| セッション | **単一アクティブセッション（重複ログイン禁止・後勝ち）＋ログイン状態の永続化**。新端末でログインすると旧端末は自動ログアウト。ログアウトは①明示的ログアウト②別端末ログインの押し出しのみ → 同時編集を構造的に排除。 |
| 同期単位 | **Work 単位**（バンドル全体ではなく作品ごとに差分同期）。 |

## 1.1 アカウント・プラン境界と未ログイン時の挙動

アカウント＝**有料会員（＝同期する人）だけ**が持つ。ゲストはアカウント不要で、ローカルファースト哲学（書くのは無料・無制限）を一切損なわない。課金が守るのは「書く行為」ではなく「運ぶ・守る（同期／複数端末／自動バックアップ）」。

### プラン（2段）
- **ゲスト（未登録・無料）**：ローカルで **作品数無制限**に書く／出す（EPUB・なろう・カクヨム）／ローカル保存。同期なし。アカウント不要。
- **会員（登録・有料）**：上記すべて＋**自動同期／複数端末／自動バックアップ／AI・MCP アクセス**（クラウド束・§1.2）。ログイン＝同期の identity ＋ 課金接点。

> 「書くのは無制限・無料、運ぶ／守るのが有料」。1 作品ゲートのようなソフトゲートは置かない（書き始める前に離脱させない＝まず使われることを最優先）。

### ローカルデータ主権（最重要）
ログイン状態に関わらず、**ローカル（IndexedDB）にある作品は常に全件・閲覧/編集/書き出しできる**。アプリは未ログインを理由に既存データを隠さない・消さない。プラン境界がかかるのは **「同期」だけ**。

### 未ログイン時の挙動（会員がログアウト/セッション切れ/別端末ログインで押し出された場合）
- ローカルの作品は**全部そのまま見える・書ける・出せる**。
- **3 経路（①別端末ログインで押し出された／②サブスク失効／③そもそも未ログイン）はすべてゲストに収束し、同じ表示になる**。ヘッダーのアカウント表示を一律「**同期オフ（ログインで同期）**」にし、クリックでログイン。会員はすべて課金者なので「課金してないのに停止」という誤解は起きない（無料の中間会員を持たない 2 段構成の利点）。
- **別端末ログインで押し出された瞬間だけ**は、強制サインアウト（→ゲスト化）と同時に**トースト1回**「別の端末でログインされたためサインアウトしました」で理由を伝える（常駐バナーは出さない＝D-SYNC-SESSION／Slice A）。
- **同期**：未ログインでは止まる。再ログインで pull → 再開。
- **新規作成・編集・書き出し**：ゲスト・会員とも制限なし。

### 利用者数の把握
会員＝課金者数は正確に分かるが、無料ゲストは匿名のため会員登録だけでは全体規模が見えない。全体像は **Cloudflare Web Analytics**（エッジ計測・Cookie レス・原稿/PII 非送信）で概数を取る（D-SYNC-TELEMETRY）。

## 1.2 有料クラウド束（cloud bundle）

有料会員は単一プランのまま、**我々のサーバを使う機能をまとめて束**で提供する（段を増やさない）。原則＝**「サーバが要るもの＝有料、純ローカルで完結＝無料」**。

| 機能 | 位置づけ | 我々のコスト |
|---|---|---|
| **クラウド同期**（アンカー） | 端末間で Work を行き来（§3） | Workers＋D1＋R2 |
| **複数端末** | 同期の自然な帰結（単一アクティブセッション・§1） | 同上 |
| **自動バックアップ** | 同期済みデータがそのまま遠隔バックアップ | R2 |
| **AI・MCP アクセス** | 同期済み作品を**自分の AI**に読ませる（D-PLAN-AI） | 軽（保存テキストを返すだけ。**推論コストはユーザー持ち**） |
| 容量・クラウド版履歴（将来） | 同期容量上限の引き上げ・遠隔の版履歴 | R2 |

無料に残すもの（純ローカル＝ゲートしない）：書く・図鑑・ローカル保存・**ローカル版履歴（snapshot）**・**全書き出し（EPUB/なろう/カクヨム）**・**ファイル往復での AI 連携**（`01 §3.1`）。書き出しは MVP の核「出す」なので決してゲートしない。

### AI・MCP アクセス（read-only リモート MCP）
- **自前 AI は用意しない**（資金的制約）。AI 推論は全てユーザーの AI（ユーザーの課金）が行い、我々は**同期済み作品の保存テキストを返すだけ**。
- 形 = **リモート MCP（Streamable HTTP）**。同期インフラ（Workers＋R2＋auth＋サーバ鍵復号）上に**認証付き MCP エンドポイント**を生やす。Claude Desktop / claude.ai / Claude Code 等のリモート MCP に対応。
- UX = アプリが **MCP 設定（URL＋トークン）をコピー**できるボタンを出し、各自の AI クライアントに貼る。
- スコープ = **read-only**（`list_works` / `get_work` / `get_glossary`）。AI の編集結果は当面 import 往復で戻す（書き込み tool は将来）。
- **常駐プロセス不要**なので **Tauri を待たず同期サーバと同時期に出せる**（ローカル stdio MCP は Tauri 後段のまま）。
- 漏洩境界 = MCP で読ませた瞬間、本文はユーザーの AI プロバイダへ出る。**明示的 opt-in＋「あなたの AI に送られます」表示**を必須にする。無料ユーザーにはファイル往復（`01 §3.1`）を案内＝漏洩境界が自分で見える。

## 2. データモデル

### ローカル（IndexedDB・既存に追加）
- 正本は従来どおり Work JSON（`repo.saveWork`）。
- 各 Work の `updatedAt`（既存）を同期判定に流用。
- 端末ごとに `lastSyncedAt`（最後にサーバと突き合わせた時刻）を保持。
- 各 Work の**ローカル状態** active／trashed（ゴミ箱・起動時チェックで30日後に自動 purge）。**trashed も同期する（共有ゴミ箱・D-SYNC-TOMBSTONE 改）**：削除・復元が端末間で伝播する。
- 同期スキップ用に、最後に送った **doc_hash / media_hash** をローカルに保持（変更検知・D-SYNC-MEDIA）。

### サーバ（Cloudflare 前提）
- **D1**（メタ・同期判定の真実）：
  ```
  works(user_id, work_id, updated_at, deleted,
        doc_key, doc_hash, media_key, media_hash, size, synced_at)
    PRIMARY KEY (user_id, work_id)
  sessions(user_id, session_token, rotated_at)   -- 単一アクティブ強制（新ログインで回転）
  ```
- **R2**（本体）：Work を**2オブジェクト**で格納（D-SYNC-MEDIA）＝`doc`（テキスト/構造）＋`media`（画像 data URL 群）。各オブジェクトは **gzip → at-rest 暗号化**。変わった側だけ更新（`*_hash` 比較）。
- **サーバ**：Cloudflare Workers（Pages Functions）。**Clerk JWT を検証**（会員/プラン判定込み・D-SYNC-AUTH/PRICE）し、Work 単位で doc/media を出し入れ。

## 3. 同期プロトコル

1. **Push**：`updatedAt > lastSyncedAt` の Work を対象に、**doc/media のうち hash が変わった側だけ** gzip→暗号化して R2 へ、メタを D1 へ（D-SYNC-MEDIA）。**trashed の Work は内容 push はしないが、ゴミ箱状態は `PATCH` で伝播する**（共有ゴミ箱・D-SYNC-TOMBSTONE 改）。
2. **Pull**：サーバ側で `updated_at` がローカルより新しい Work をダウンロードし、`importWorks`（既存）で反映。**削除の伝播**＝D1 `deleted=1` の Work はローカルを snapshot へ退避してから除去（編集 vs 削除は LWW・編集勝ち＝復活）。purge 時に R2 doc/media を削除し、サーバ tombstone は ~30 日保持して物理削除（D-SYNC-TOMBSTONE）。
3. **競合（残余ケースのみ）**：単一セッション（§1）により同時編集は通常起きない。例外はオフライン編集中に別端末ログインされた取り残し（§3 末尾）。その場合は `updatedAt` の新しい方を採用し、**負けた方の Work をローカル snapshot（`snap:<workId>`・既存機構）へ退避**してから上書き＝丸ごと消失を防ぐ安全網。
4. 完了後に `lastSyncedAt` を更新。

### トリガ（D-SYNC-TRIGGER）
同期点は**2つだけ**。ユーザーは同期を意識しない:
- **ログイン時＝全体の双方向同期**：全 Work を突き合わせ、サーバが新しいものを pull、ローカルに未送信（`updatedAt > lastSyncedAt`）があれば push。
- **自動保存時＝編集中 Work の push**：既存の自動保存（`editorStore.save()`）にフックし、その作品の**変わった側（doc/media）だけ**をアップロード。連打を避けるため同一 Work は**最小 ~30 秒に coalesce**し、閉じる/画面遷移時に flush（D-SYNC-CAPACITY）。**pull はしない**（編集中に他端末の変更を引っ張らない）。
- **オフライン**：push 失敗は無視してよい。未送信分は次のログイン/自動保存時に `updatedAt > lastSyncedAt` で自然に拾われる（専用の再送キューは持たない）。
- **手動**：「今すぐ同期」ボタンは保険として任意。
- ログアウト中は一切同期しない（optin 維持）。

> 単一アクティブセッション（§1）により、両端末が同時に編集状態になることはない。唯一の穴は**オフライン編集中に別端末でログイン**されたケース：オフライン端末は自動ログアウトを受け取れず、復帰時に push が弾かれ、再ログインの pull で未送信編集が上書きされうる。これを完全マージで防ぐのは過剰なので、§3-3 の snapshot 退避で軽減する、が本書の立場。

## 4. core 資産の再利用

既存の純ロジックがほぼそのまま土台になる（サーバ側の新規実装を最小化）:
- `exportBundle` / `importBundle`（Work 配列の直列化・検証）
- `importWorks`（id 単位の upsert＝非破壊マージ）
- snapshot 機構（負け版の退避先）

サーバ側に必要なのは「認証 ＋ Work 単位の blob 出し入れ ＋ `updated_at` 比較」に集約される。

## 5. 決定事項（確定済み）

| ID | 決定 |
|---|---|
| **D-SYNC-OPTIN** | 既定ローカル・optin。同期 OFF でも全機能がオフラインで動く。 |
| **D-SYNC-DIRECTION** | 双方向同期。ただし同時編集は非対応。 |
| **D-SYNC-SESSION** | 単一アクティブセッション（重複ログイン禁止・後勝ち）＋ログイン状態の永続化。新ログインで旧端末を自動ログアウト＝同時編集を構造的に排除。ログアウトは①明示的②別端末ログインの押し出しのみ。認証基盤にサーバ側セッション無効化を要求。**押し出された旧端末は強制サインアウト（→ゲスト化）し、その瞬間トースト1回で理由を通知（常駐バナーは出さない）。検知一式（D1 `sessions`・トークン照合・`checkSession` ポーリング・push 409）は維持し、反応だけ `signOut()` に集約（Slice A）。** |
| **D-SYNC-CONFLICT** | 同時編集はセッションで排除済み。残余（オフライン編集の取り残し）のみ Work 単位 LWW（`updatedAt`）＋負け版を local snapshot へ退避。マージ/CRDT は持たない。 |
| **D-SYNC-CRYPTO** | サーバ側 at-rest 暗号化・鍵サーバ管理（復旧可）。E2E は将来。 |
| **D-SYNC-UNIT** | 同期単位は Work。バンドル全体送信はしない。 |
| **D-SYNC-STACK** | Cloudflare Workers ＋ D1（メタ）＋ R2（本体）。 |
| **D-SYNC-TRIGGER** | 同期点は2つ＝①ログイン時に全 Work 双方向同期 ②自動保存時に編集中 Work を push（pull しない）。未送信分は次回 `updatedAt > lastSyncedAt` で回収＝再送キュー不要。手動は任意の保険。 |
| **D-PLAN-TIERS** | 2段＝ゲスト（未登録・無料・ローカル無制限・同期なし）／会員（登録・有料・＋自動同期・複数端末・自動バックアップ）。会員登録＝有料。ソフトゲート（作品数ゲート）は置かない。 |
| **D-PLAN-LOCALDATA** | ローカルデータ主権。未ログインでも既存ローカル作品は全件閲覧/編集/書き出し可。プラン境界は「同期」にのみ適用。新規作成・編集・書き出し・ローカル保存は誰でも無制限・無料（隠さない・消さない）。**サブスク失効でアカウントを削除するときも削除対象はクラウド（R2 blob＋D1 メタ＋Clerk ユーザー）のみで、端末内 IndexedDB の原稿は不可触＝保持する。** |
| **D-PLAN-BUNDLE** | 有料は単一プランで「クラウド束」を提供（段を増やさない）。束＝同期（アンカー）／複数端末／自動バックアップ／AI・MCP アクセス／（将来）容量・クラウド版履歴。原則「サーバが要るもの＝有料、純ローカル＝無料」。書き出しは無料に残す。詳細は §1.2。 |
| **D-PLAN-AI** | AI・MCP アクセスは有料クラウド束の一機能。形＝**read-only リモート MCP**（Streamable HTTP・同期インフラ上の認証付きエンドポイント・`list_works`/`get_work`/`get_glossary`）。**推論はユーザーの AI が行い我々は保存テキストを返すだけ**（自前 AI なし）。設定コピーで各自の AI に接続。常駐不要ゆえ Tauri を待たず同期と同時期に出せる（ローカル stdio MCP は Tauri 後段）。本文流出は opt-in＋明示表示。 |
| **D-SYNC-AUTH** | マネージド認証＝**Clerk**。単一アクティブセッション強制は Clerk セッションに加え**自前 D1 のセッショントークン（新ログインで回転）**を併用し、Worker は **Clerk JWT を検証**。会員/プラン判定も同 JWT クレームで行う（D-SYNC-PRICE と一本化）。「サーバ最小」に対し、認証・課金の整合を自前で抱えない利得を優先。 |
| **D-SYNC-TOMBSTONE**（改訂・共有ゴミ箱） | 削除はソフト削除＋**ゴミ箱30日**。状態＝active／trashed／purged の3つ。**trashed も同期する（共有ゴミ箱）**：D1 `works.trashed_at`（>0=trashed・blob 保持）で表し、削除・復元・完全削除をすべて端末間へ伝播する。これで「別端末で削除→pull で復活」「各端末でゴミ箱が増殖」を解消する（旧設計＝trashed をローカルのみで持ち非同期にしていたのが原因）。**伝播**＝ゴミ箱移動/復元は `PATCH /api/sync/work`（blob 保持で `trashed_at` を更新）で即時＋ログイン同期でも回収（engine が `listLocalTrashed`→`toPushTrash`/`toRestoreLocal`）。**purge**＝`DELETE`（D1 `deleted=1`＋R2 doc/media 削除）。**LWW**＝`updated_at` を時計に、trashed の時計は `trashed_at`。編集 vs 削除は新しい方が勝つ（編集が新しければ復活）。30日 TTL は `trashed_at` 基準で自動 purge。サーバ tombstone は purge 後 ~30 日保持して物理削除。migration `0003_trash_sync` で `trashed_at` 追加。 |
| **D-SYNC-CAPACITY** | 1 GB/user・25 MB/work（blob）。クライアント push は同一 Work 最小 ~30 秒に coalesce（＋閉じる/画面遷移時に flush）。サーバ側レート上限 60 req/min/user。超過は**同期だけ停止**＝ローカルは無制限のまま（D-PLAN-LOCALDATA）。 |
| **D-SYNC-MEDIA** | 同期表現を作品あたり **R2 2オブジェクトに分割**＝「本文オブジェクト（テキスト/構造）」＋「画像オブジェクト（data URL 群）」。**変わった側だけ**アップロード（hash 比較で未変更はスキップ）。暗号化**前に gzip**。画像単位の content-addressing/dedup は将来最適化。ローカルは方式A（Work JSON 相乗り・P1.1 画像）を維持。 |
| **D-SYNC-PRICE** | 課金基盤＝**Clerk Billing（裏 Stripe）**。価格＝**月額 ¥500／年額 ¥4,800**（年は実質2ヶ月分お得）、トライアル無し。会員判定は Worker が検証する Clerk JWT クレームで行い、**Stripe ↔ 自前 D1 のサブスク状態同期は持たない**（D-SYNC-AUTH と同一線）。**解約＝期末まで継続予約（`cancel_at_period_end`。グレース期間中は member 継続・同期継続・再契約取消も可）。失効（期末到来）＝Clerk 失効 webhook をトリガにクラウドのアカウント＋データを削除し全端末を強制ログアウト（ローカル保持＝D-PLAN-LOCALDATA）。webhook は一度きりのアカウント終了フックでありサブスク状態ミラーではないため本決定の趣旨を壊さない。** |
| **D-SYNC-TELEMETRY** | 当面 **Cloudflare Web Analytics のみ**（エッジ計測・Cookie レス・**原稿/PII は構造上非送信**）で利用者数の概数を取る。継続率/ファネルが要れば **PostHog を匿名・自ドメイン中継・無料枠**で後付け。不可侵＝原稿/タイトル/本文/辞書/PII は送らない。 |
| **D-SYNC2-CAS**（2026-08） | push は **CAS（比較交換）**。クライアントは最後に同期した時点の docHash を `x-base-hash` で申告し、サーバ現況と一致するときだけ受理・不一致は 409 `{error:'conflict', meta}` を返して**黙った上書きをサーバ側で構造的に排除**する（旧・無条件 LWW push の置き換え。廃止理由だった「黙った上書き」への直接の対策）。新規は `''`、トゥームストーンへの push は `x-updated-at > row.updated_at`（編集勝ち＝復活）のみ受理。 |
| **D-SYNC2-3WAY**（2026-08） | 端末ごとに base（`syncbase:<workId>`＝最後に push/pull した平文 canonical JSON の hash＋その時点の remoteUpdatedAt）を記録し、**ローカル/リモート/base の三方向差分**で reconcile する（`planReconcile`・純関数マトリクス）。**pull でローカルを自動上書きするのは clean（base から未編集）のときだけ**。両側変更（真の競合）は LWW で勝敗を決めるが、**敗者は必ず snapshot（`snap:<id>`）へ退避しトーストで通知**する（旧・黙った pull 上書きへの対策）。復元（replaceAll）後は base を全消去＝端末を「新品」として再同期し、誤 purgeRemote を防ぐ。 |
| **D-SYNC2-SCOPE**（2026-08） | 自動同期のスコープは **Work（＋共有ゴミ箱状態）のみ**。structures / ideas / profile / activity は自動バックアップ（全体スナップショット）が運ぶ。周辺状態の個別同期は将来（同期対象を最小に保ち、競合面を Work に限定するため）。**→ 同月内に D-SYNC2-ITEMS / D-SYNC2-ACTIVITY-DB で拡張**：structures / ideas / activity は個別同期へ移行し、自動バックアップ経由で残るのは profile のみ。 |
| **D-SYNC2-AUTOBACKUP**（2026-08） | **自動クラウドバックアップ（Phase A）**＝編集静止 5 分で発火・前回クラウドバックアップから 60 分未満なら見送り（次の編集静止で再判定）・保持世代 20（既存 `/api/backup` 基盤に相乗り・2026-07「自動バックアップは将来」の実装）。hidden / pagehide / アンマウント時は dirty かつ間隔条件を満たせば fire-and-forget で送る。失敗（オフライン等）は黙って無視し次の機会に再試行（dirty は成功時のみ下ろす）。 |
| **D-SYNC2-NOSESSION**（2026-08） | **単一アクティブセッション（別端末押し出し）は復活させない**。複数端末の常時ログイン可（2026-07 改訂）を維持し、同時編集の衝突はセッションで排除するのではなく D-SYNC2-CAS / D-SYNC2-3WAY が検出して安全に解決する（押し出し UX の複雑さと「オフライン端末が押し出しを受け取れない」穴を再導入しないため）。 |
| **D-SYNC2-ITEMS**（2026-08） | **構造レイヤー（アウトライン/相関図/マインドマップ）とネタ帳も Work と同じ CAS＋三方向差分で同期する**（D-SYNC2-SCOPE の拡張）。D1 `works` テーブル・既存 `/api/sync/*` API をそのまま流用し、行キーに種別プレフィックス付き id（`structure:<id>` / `idea:<id>`）を使う＝**新規 migration・サーバ改修なし**。ゴミ箱概念がないため trash 系の状態遷移は使わず、削除は**トゥームストーン直行**。競合の敗者は snapshot 機構が無い代わりに **`synclost:<syncId>`（1 世代）へ退避しトーストで通知**する（「黙って消えない」原則の維持）。執筆画面で開いている作品に紐づく構造の pull/purge は見送り（Work 本体と同じ扱い）。 |
| **D-SYNC2-ACTIVITY-DB**（2026-08） | **執筆の記録（activity）は性質が異なるため別方式で同期する**。日別カウンタ（date/added/removed/saves）は原稿・PII を一切含まないため、R2 暗号化ブロブではなく **D1 `activity` テーブルに平文の行で保持**（migration `0006_activity_sync`）。同期は `POST /api/sync/activity`＝クライアントが全日分を送り、サーバが**日付ごと・フィールドごと max マージ**（UPSERT）して全量を返す。加算的データなので衝突が原理的に起きない＝LWW/CAS/base/409 不要。net は保存せず added−removed から導出。制約＝同一日に複数端末で書いた場合は合算ではなく大きい方が残る（過少方向・草/ストリーク用途で実害なし）。退会時の reaper は activity 行も削除する。**プライバシー**＝サーバに平文で置くのは日付と文字数カウンタのみで、原稿・タイトル・図鑑・PII は含まれない。 |
