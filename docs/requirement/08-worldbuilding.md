# 08 — 世界観設定（作者専用の設定置き場）と「用語集」への改名

> 2026-08 決定。[04-glossary.md](./04-glossary.md) の器を「読者に見せるもの」に絞り、作者だけの器を新設する。

## 0. なぜ要るのか（観測された壊れ方）

用語集（`Work.glossary`）は **公開サイトへ送られる**。先方（grove）は「その用語が出てくる話まで読んだ読者に項目を開く」段階公開を行う ＝ **もともと読者に見せる前提の器**。

ところが実運用（MCP 経由の執筆）で、この器に次のものが溜まった。

- `【作者用】開示設計` … 何をいつまで伏せるかの方針
- `【作者用】名づけのズレ` `【作者用】向こうにないもの` … 語彙と世界のルール
- `【作者用】年表` `【作者用】種族と分類` … 結末に触れる設定
- `【作者用】連載設計` `【作者用】キャラ設計` … 執筆の決め事

実データでは全 50 項目のうち **17 項目**がこの形だった。項目名に `【作者用】` と自分で書いていたことが、器が足りていない何よりの証拠になっている。

問題は 2 つ。

1. **用途が違う。**「読者が引く事典」と「作者が守る決め事」は読み手も寿命も違う。混ざると用語集が引けなくなる。
2. **公開経路に乗っている。** 段階公開の対象になるので、伏せているはずの設計が読者に届きうる。

## 1. 決めたこと

| ID | 決定 |
|---|---|
| **D-WORLD-SPLIT** | 器を**読み手で割る**。読者にも見せる事典＝**用語集**（`Work.glossary`）、作者だけの決め事＝**世界観設定**（`Plot.world`）。 |
| **D-WORLD-HOME** | 世界観設定は **`Plot` に持たせる**。公開バンドルが運ぶのは `Work` だけなので、**構造的に公開経路へ乗らない**（フラグの立て忘れで漏れる余地を作らない）。UI もプロットのタブに入る。 |
| **D-WORLD-FORM** | 自由記述 1 枚ではなく、**案内文つきの決まった枠**（`WORLD_SLOTS` 11 枠＋自由枠。枠の一覧は §2）。「何を書けばいいか分からないまま止まる」「際限なく伸びる」の両方を防ぐ。 |
| **D-WORLD-EMPTY** | 本文が空になった枠は**保存しない**（`setWorldNote` が削除する）。一覧に出るのは常に「書いたものだけ」。枠の定義（案内文）は空でも画面には並ぶ。 |
| **D-GLOS-RENAME** | 「図鑑」→ **「用語集」**。本文・プロットから `@` で呼び出し、リンクから引く器であることを名前で伝える。内部識別子（`glossary` / `GlossaryEntry` / `NavKey='glossary'`）は据え置き＝データ移行なし。 |
| **D-GLOS-AUTHORNOTE** | 用語集の項目に **`authorNote`（作者メモ）** を追加。項目に紐づくが読者に見せない情報の置き場で、**`toBundleWork` が送信時に落とす**。作品全体の決め事は世界観設定、項目 1 つに閉じた内緒は作者メモ、という住み分け。 |
| **D-GLOS-BODY** | すでにスキーマにあった `body`（詳細）を **UI に出す**。MCP からは書けるのに画面から見えず、`summary` に長文を押し込む運用を招いていた。 |
| **D-GLOS-CATEGORY** | 固定カテゴリから **「世界観」を外し**、`組織` / `生物` を足す（`人物 / 場所 / 組織 / 用語 / アイテム / 生物`）。「世界観」がタブ名と重なると、どちらへ書くのか毎回迷う。既存の自由入力値は従来どおり編集時に保全する。 |

## 2. 枠（`WORLD_SLOTS`）

**ジャンルを選ばない語で書く。** 最初の実装は「力の体系」「種族と集団」のような枠を置いていたが、これは異世界ファンタジーを前提にした語で、現代物・ミステリ・恋愛・私小説の作者には空欄の押しつけになる。どの作品にもある問い（いつどこの話か／人は何に縛られているか／何を破らないか）に言い換え、現実に無い仕組みを持つ作品だけが使う枠は `special` 1 つへ畳んで `optional` にした。`placeholder` も現代物と架空世界の例を並べ、「自分の作品には関係ない」と思わせない。

`key` は保存済みデータの結合キーなので**変えない**。増やすときは末尾へ足す。

| group（＝アコーディオンの 1 節） | key | ラベル |
|---|---|---|
| 世界と舞台 | `stage` | 時代と場所 |
| 世界と舞台 | `society` | 人を縛るもの |
| 世界と舞台 | `rules` | この作品の約束事 |
| 世界と舞台 | `history` | ここまでの経緯 |
| 世界と舞台 | `special` | 固有の仕組み（**任意**） |
| 書き方の決め事 | `style` | 語り手と文体 |
| 書き方の決め事 | `words` | 言葉づかい |
| 書き方の決め事 | `characters` | 人物の描き方 |
| 書き方の決め事 | `structure` | 話の組み立て |
| 読者への見せ方 | `reveal` | 何を、いつ明かすか |
| 読者への見せ方 | `forbidden` | やらないこと |
| （そのほか） | `custom` | 自由枠（`title` 必須・複数可） |

`reveal`（開示方針）は**方針だけ**を置く。個々の秘密がいつ明かされるかは既存の「秘密」（`Plot.secrets`）が持つ ＝ 点検可能なデータは点検できる器に残す。

## 2.1 フォームの作り（UX 決定）

枠が 11 ある器なので、素朴に縦へ並べると初見で心が折れる。長文の設定を書ける器でもあるので、入力欄の伸び方も決めておく必要がある。

| ID | 決定 |
|---|---|
| **D-WORLD-ACCORDION** | まとまり単位でアコーディオンに畳む（progressive disclosure）。既定は**最初の 1 節だけ開く**。「すべて開く／閉じる」も置く。 |
| **D-WORLD-SECTION-BADGE** | 畳んだ節は忘れられる、というのがこのパターンの定石の弱点。見出しに**説明文と「N / M 記入済み」**を必ず出し、開かなくても「どこに何があるか」が読めるようにする。 |
| **D-WORLD-FIELD-SIZE** | 入力欄は共有 `Textarea`（`field-sizing: content`）。中身に合わせて伸び、`max-h-[32vh]` で頭打ちになり、以降は**欄の中でスクロール**する。`rows` を JS で計算する自前実装はしない（無限に伸びるか、逆に見切れるかのどちらかになる）。`scrollbar-gutter: stable` でスクロールバー出現時の横ずれを止める。 |
| **D-WORLD-ALWAYS-EDITABLE** | 「読む状態／書く状態」を分けず、常に入力欄を出す。モード切替を無くしたほうが迷いが少なく、伸び方の規則も 1 つで済む。 |
| **D-WORLD-COMMIT** | 確定は blur。加えて**アンマウント時にも未確定分を送る**（節を畳んだ・タブを離れた瞬間に書きかけが消えない）。保存は非同期なので、最後に送った内容を控えて二重送信しない。Esc は書きかけを捨てる。 |

> `field-sizing: content` は 2026-06 に Baseline（Chrome 123 / Edge 123 / Firefox 152 / Safari 26.2）。この器のためだけに JS フォールバックは持たない。

## 3. スキーマ

```ts
// core/plot
type WorldNote = {
  id: string
  slot: string        // WORLD_SLOTS の key、または 'custom'
  title?: string      // 自由枠の見出し（定型枠はラベルを使うので持たない）
  body: string
  updatedAt: number
}
type Plot = { /* 既存 */ world: WorldNote[] }   // 旧データ互換のため optional + default []

// core/schema
type GlossaryEntry = { /* 既存 */ authorNote?: string }  // 公開時に落とす
```

永続化・同期・バックアップは既存の器に相乗りする（`world` は `Plot` の一部、`authorNote` は `Work` の一部）。**追加のマイグレーションは無い**。

## 4. MCP（AI に器の住み分けを守らせる）

「用語集へ設定を書いてしまう」は AI 側が器の意味を知らないことで起きた。**3 段構えで伝える**（クライアントによって効く層が違うため、1 か所に賭けない）。

| 層 | 何を渡すか |
|---|---|
| `initialize` の `instructions` | 4 つの器の説明と、「書き換える前に `get_world` を読む」「設定・決め事は用語集ではなく `set_world_note` へ」の手順 |
| ツール説明 | `upsert_glossary_entry` に「name/summary/body は読者にも見える。設定ルールは `set_world_note` へ」を明記 |
| ツールの戻り値 | `get_plot` は**世界観設定を本文ごと先頭に載せる**。`get_glossary` は件数と `get_world` への導線を 1 行で先頭に置く（用語集は元から巨大なので本体は載せない） |

追加ツール：

| ツール | 役割 |
|---|---|
| `get_world` | 世界観設定を `[slot: …, note_id: …]` 付きで返す |
| `set_world_note` | 枠を書き込む。定型枠は `slot` 一致で上書き、`custom` は `title` 必須。`body` 空文字で枠を削除。**プロットが無い作品でも書ける**（決め事はプロットより先に決まるため） |
| `delete_world_note` | `note_id` 指定で枠を削除 |

`upsert_glossary_entry` には `author_note` 引数を追加した。

## 5. 不変条件（テストで担保）

- 定型枠は `slot` 一致で 1 枠に収束し、既存ノートの `id` を保つ（毎回作り直さない）。
- `body` を空にすると枠ごと消え、もともと無い枠を空で保存しても no-op（同一参照を返す）。
- 自由枠は `title` 必須。未知の `slot` は MCP が弾く。
- 旧データ（`world` 欠落）を読み込むと `[]` で埋まる。
- 世界観設定だけ書いたプロットは `isTrivialPlot` で「中身なし」にならない（同期レースで消えない）。
- `toBundleWork` は用語集を送るが `authorNote` だけ落とす。用語集を持たない作品に `glossary` キーは生えない。
- `get_plot` は世界観設定を `【プロット】` 見出しより前に出す。`get_glossary` は本体を載せず `get_world` へ誘導する。
- 世界観設定が空の作品では、`get_plot` / `get_glossary` の両方が `set_world_note` を案内する。
- 定義から外れた `slot`（過去の枠など）を持つノートは「無題」にならず、`slot` 名を見出しにして「そのほか」へ並ぶ＝中身を見失わない。
- 枠のラベルと案内文に特定ジャンルの語（魔法・種族・王国 等）を持ち込まない。現実に無い仕組みの枠は 1 つだけ・任意。
- 既定では最初の節だけ開き、畳んだ節の入力欄は DOM に出ない。畳んだ節も見出しに記入数を出す。
- 節を畳んでも、blur を経ていない書きかけが保存される。

## 6. 積み残し

- **既存 `【作者用】` 項目の引っ越し。** 移送は MCP（`get_glossary` → `set_world_note` → `delete_glossary_entry`）で行える。UI の一括移送ボタンは今回入れていない。
- **読者向け用語集の項目単位の公開可否。** いまは「送る／送らない」が器の単位。項目ごとに読者へ出す・出さないを選ぶなら `GlossaryEntry` に後方互換でフラグを足す（`authorNote` が既にあるので、当面はそちらで足りる想定）。
