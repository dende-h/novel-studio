# 08 — 世界観設定（作者専用の設定置き場）と「用語集」への改名

> 2026-08 決定。[04-glossary.md](./04-glossary.md) の器を「読者に見せるもの」に絞り、作者だけの器を新設する。

## 0. なぜ要るのか（観測された壊れ方）

用語集（`Work.glossary`）は **公開サイトへ送られる**。先方（grove）は「その用語が出てくる話まで読んだ読者に項目を開く」段階公開を行う ＝ **もともと読者に見せる前提の器**。

ところが実運用（MCP 経由の執筆）で、この器に次のものが溜まった。

- `【作者用】開示設計` … 何をいつまで伏せるかの方針
- `【作者用】名づけのズレ` `【作者用】向こうにないもの` … 語彙と世界のルール
- `【作者用】年表` `【作者用】種族と分類` … 結末に触れる設定
- `【作者用】連載設計` `【作者用】キャラ設計` … 執筆の決め事

実データでは全 50 項目のうち **17 項目**がこの形だった。項目名に `【作者用】` と自分で書いていたことが、器が足りていない何よりの証拠になっている。

問題は 2 つ。

1. **用途が違う。**「読者が引く事典」と「作者が守る決め事」は読み手も寿命も違う。混ざると用語集が引けなくなる。
2. **公開経路に乗っている。** 段階公開の対象になるので、伏せているはずの設計が読者に届きうる。

## 1. 決めたこと

| ID | 決定 |
|---|---|
| **D-WORLD-SPLIT** | 器を**読み手で割る**。読者にも見せる事典＝**用語集**（`Work.glossary`）、作者だけの決め事＝**世界観設定**（`Plot.world`）。 |
| **D-WORLD-HOME** | 世界観設定は **`Plot` に持たせる**。公開バンドルが運ぶのは `Work` だけなので、**構造的に公開経路へ乗らない**（フラグの立て忘れで漏れる余地を作らない）。UI もプロットのタブに入る。 |
| **D-WORLD-FORM** | 自由記述 1 枚ではなく、**案内文つきの決まった枠**（`WORLD_SLOTS` 11 枠＋自由枠。枠の一覧は §2）。「何を書けばいいか分からないまま止まる」「際限なく伸びる」の両方を防ぐ。 |
| **D-WORLD-EMPTY** | **定型枠**は本文が空になったら保存しない（`setWorldNote` が削除する）。枠そのものは画面に常にあるので、空のレコードを持つ意味がない。**自由枠**は見出しがあれば空でも残す＝作者が作った器が、書く前に離れただけで消えることはない。 |
| **D-GLOS-RENAME** | 「図鑑」→ **「用語集」**。本文・プロットから `@` で呼び出し、リンクから引く器であることを名前で伝える。内部識別子（`glossary` / `GlossaryEntry` / `NavKey='glossary'`）は据え置き＝データ移行なし。 |
| **D-GLOS-AUTHORNOTE** | 用語集の項目に **`authorNote`（作者メモ）** を追加。項目に紐づくが読者に見せない情報の置き場で、**`toBundleWork` が送信時に落とす**。作品全体の決め事は世界観設定、項目 1 つに閉じた内緒は作者メモ、という住み分け。 |
| **D-GLOS-BODY** | すでにスキーマにあった `body`（詳細）を **UI に出す**。MCP からは書けるのに画面から見えず、`summary` に長文を押し込む運用を招いていた。 |
| **D-GLOS-CATEGORY** | 固定カテゴリから **「世界観」を外し**、`組織` / `生物` を足す（`人物 / 場所 / 組織 / 用語 / アイテム / 生物`）。「世界観」がタブ名と重なると、どちらへ書くのか毎回迷う。既存の自由入力値は従来どおり編集時に保全する。 |

## 2. 枠（`WORLD_SLOTS`）

**ジャンルを選ばない語で書く。** 最初の実装は「力の体系」「種族と集団」のような枠を置いていたが、これは異世界ファンタジーを前提にした語で、現代物・ミステリ・恋愛・私小説の作者には空欄の押しつけになる。どの作品にもある問い（いつどこの話か／人は何に縛られているか／何を破らないか）に言い換え、現実に無い仕組みを持つ作品だけが使う枠は `special` 1 つへ畳んで `optional` にした。`placeholder` も現代物と架空世界の例を並べ、「自分の作品には関係ない」と思わせない。

`key` は保存済みデータの結合キーなので**変えない**。増やすときは末尾へ足す。

| group（＝アコーディオンの 1 節） | key | ラベル |
|---|---|---|
| 世界と舞台 | `stage` | 時代と場所 |
| 世界と舞台 | `society` | 人を縛るもの |
| 世界と舞台 | `rules` | この作品の約束事 |
| 世界と舞台 | `history` | ここまでの経緯 |
| 世界と舞台 | `special` | 固有の仕組み（**任意**） |
| 書き方の決め事 | `style` | 語り手と文体 |
| 書き方の決め事 | `words` | 言葉づかい |
| 書き方の決め事 | `characters` | 人物の描き方 |
| 書き方の決め事 | `structure` | 話の組み立て |
| 読者への見せ方 | `reveal` | 何を、いつ明かすか |
| 読者への見せ方 | `forbidden` | やらないこと |
| （そのほか） | `custom` | 自由枠（`title` 必須・複数可） |

`reveal`（開示方針）は**方針だけ**を置く。個々の秘密がいつ明かされるかは既存の「秘密」（`Plot.secrets`）が持つ ＝ 点検可能なデータは点検できる器に残す。

## 2.1 フォームの作り（UX 決定）

枠が 11 ある器で、しかも 1 枠あたり長文を書く。**縦に積むと必ず破綻する**。

最初は枠を縦に並べ、次にまとまり単位のアコーディオンで畳んだが、実利用で「やはり縦スクロールが多い」と分かった。畳んでも**開いた節の中はやはり縦に長い**ので、スクロールの総量は減っても「書きながら迷子になる」は消えない。畳む・開くという操作が 1 段増えたぶん、かえって遠くなっていた。

そこで**ビートシートと同じ左右 2 枚看板**へ作り替えた。左は項目名と記入済みの印だけなので細くてよく、そのぶん右の入力欄に幅と**画面いっぱいの高さ**を渡せる。項目の切り替えはクリック 1 回で、ページ自体は縦に動かない。

| ID | 決定 |
|---|---|
| **D-WORLD-MASTER-DETAIL** | 左＝項目の一覧（3 つのまとまりで見出し分け・記入済みの印つき）、右＝選択中の 1 項目だけを編集。畳む操作は置かない（1 項目 1 行なので 11 枠でも全部見える）。 |
| **D-WORLD-NO-PAGE-SCROLL** | ページ自体はスクロールさせない。左右がそれぞれ高さを持ち、溢れたぶんはその中で動く（ビートシートと同じ構造）。 |
| **D-WORLD-FIELD-SIZE** | 入力欄は共有 `Textarea` を `flex-1` ＋ `max-h-none` ＋ `[field-sizing:fixed]` で使い、右カラムの残り高さを全部取る。既定の `field-sizing: content` のままだと flex の伸長と競合して高さが安定しない。溢れたぶんは欄の中でスクロールし、`scrollbar-gutter: stable` で横ずれを止める。 |
| **D-WORLD-ALWAYS-EDITABLE** | 「読む状態／書く状態」を分けず、選んだ項目は常に入力欄。モード切替を無くしたほうが迷いが少ない。 |
| **D-WORLD-COMMIT** | 確定は blur。加えて**欄が外れるときにも未確定分を送る**。左の一覧をクリックすると blur より先に切り替わる経路があるため、こちらが本命の確定処理になる。保存は非同期なので、最後に送った内容を控えて二重送信しない。Esc は書きかけを捨てる。 |
| **D-WORLD-NOTATION** | 入力欄は本文・プロットと同じ `CommitTextarea`。`@`／`＠`／`[[` で用語集のサジェストが出て、無い語はその場で登録して `[[名前]]` を挿入できる。**器が違っても書き方は 1 つ**にするため、サジェストの実装は画面ごとに書き写さず共有部品へ切り出した（`src/ui/components/PlotView/commit-textarea.tsx`）。 |
| **D-WORLD-CUSTOM-EDIT** | 自由枠は**見出しの変更と削除ができる**（定型枠は固定）。見出しの入力は `field-sizing: content` で中身ぶんの幅にし、すぐ隣に**押せる鉛筆ボタン**（押すと入力へ入り、既存の見出しを丸ごと選択）を置く。飾りの印だと「押しても何も起きない」ので操作を必ず持たせる。削除はアイコンだけでは気づかれないので「削除」の文字を添える。 |
| **D-WORLD-NO-TAB-BADGE** | タブに記入数のバッジは置かない。「伏線・秘密」の数字は**片付けるべき件数**だが、世界観設定の記入数は対処が要るものではなく、タブを開けば「N / 11 の枠に記入済み」が出て二重になる。 |

> 実測（1440×900）：入力欄 788×568px、長文 60 行でも `scrollHeight 1381` が欄の中でスクロールし、**ページの縦スクロールは発生しない**（`document.scrollHeight === clientHeight`）。

## 2.2 保存済みレコードとの互換（STG で踏んだ事故）

`Plot` に `world` を足した直後、**既存のプロットを開いて世界観設定タブを押すとアプリが落ちた**。
`plot.world.filter` が `TypeError` になり、React がツリーごと破棄するため、利用者からは
「本文編集画面へ飛ばされ、サイドバーからプロット・アウトライン・相関図・マインドマップが消え、
ヘッダーも空になる（リロードで戻る）」という別の症状に見えていた。

原因は **`PlotRepository` が `store.get<Plot>()` のキャストで読み出しており zod を通さない**こと。
型は `world: WorldNote[]` でも、それより前に保存されたレコードには実体が無い。同じ穴は
`secrets`（数日前に追加）にも空いていた。

| ID | 決定 |
|---|---|
| **D-PLOT-NORMALIZE** | 読み出しの入り口（`PlotRepository.get` / `list`）で `normalizePlot` を通し、後から足した配列を埋める。読み手ごとに `?? []` を書くのは書き漏らした一箇所で落ちるのでやらない。検証（parse）ではなく穴埋めにするのは、少し形の崩れたレコードを弾いてプロットごと読めなくするより被害が小さいため。 |
| **D-SCREEN-BOUNDARY** | 画面の描画エラーを `App` の画面領域で受け止める（`ErrorBoundary key={activeScreen}`）。境界がアプリの根元にしか無いと、1 画面の例外でシェルごと消えて原因が分からない画面になる。別の画面へ移れば境界は張り直される。 |

> 後から `Plot` / `Structure` などへ項目を足すときは、**スキーマの `.default()` だけでは保存済みデータに効かない**ことに注意する（効くのは zod を通す経路＝バックアップ・同期のみ）。`normalizePlot` に 1 行足すこと。

## 2.3 保全（バックアップ・同期・ライブスナップショット）

`world` は `Plot` の一部なので、**既存の器へ自動的に相乗りする**。新しい経路は要らない。

| 経路 | 乗る理由 |
|---|---|
| 手動・自動バックアップ | `createLocalBackupIO` の `gather` が `plotRepo.list()` を集め、`CloudBackupSchema.plots` が `PlotSchema` で検証する |
| クラウド自動同期 | `sync-service` が `plot:<id>` を `canonicalJson(PlotSchema, p)` で送る。`world` を書き換えるとハッシュが変わり差分として拾われる |
| ライブスナップショット（MCP が読む） | `pushLive` が同じ `gather` を使う |
| 公開バンドル | **乗らない**（`toBundleWork` が運ぶのは `Work` だけ）＝作者専用が保たれる |

> 「相乗りしているつもり」で落ちるのが一番怖いので、往復と canonical JSON の両方をテストで固定してある（§5）。

## 3. スキーマ

```ts
// core/plot
type WorldNote = {
  id: string
  slot: string        // WORLD_SLOTS の key、または 'custom'
  title?: string      // 自由枠の見出し（定型枠はラベルを使うので持たない）
  body: string
  updatedAt: number
}
type Plot = { /* 既存 */ world: WorldNote[] }   // 旧データ互換のため optional + default []

// core/schema
type GlossaryEntry = { /* 既存 */ authorNote?: string }  // 公開時に落とす
```

永続化・同期・バックアップは既存の器に相乗りする（`world` は `Plot` の一部、`authorNote` は `Work` の一部）。**追加のマイグレーションは無い**。

## 4. MCP（AI に器の住み分けを守らせる）

「用語集へ設定を書いてしまう」は AI 側が器の意味を知らないことで起きた。**3 段構えで伝える**（クライアントによって効く層が違うため、1 か所に賭けない）。

| 層 | 何を渡すか |
|---|---|
| `initialize` の `instructions` | 4 つの器の説明と、「書き換える前に `get_world` を読む」「設定・決め事は用語集ではなく `set_world_note` へ」の手順 |
| ツール説明 | `upsert_glossary_entry` に「name/summary/body は読者にも見える。設定ルールは `set_world_note` へ」を明記。本文を書く `set_episode` / `add_episode` にも「書く前に `get_world` を読み、それに従うこと」を明記 |
| ツールの戻り値 | `get_plot` は**世界観設定を本文ごと先頭に載せる**。`get_glossary` / `get_work` / `get_structures` は件数と `get_world` への導線を 1 行で先頭に置く（用語集も本文も元から巨大なので本体は載せない）＝**どの器を読みに来ても決め事の存在が目に入る** |

追加ツール：

| ツール | 役割 |
|---|---|
| `get_world` | 世界観設定を `[slot: …, note_id: …]` 付きで返す |
| `set_world_note` | 枠を書き込む。定型枠は `slot` 一致で上書き、`custom` は `title` 必須。`body` 空文字で枠を削除。**プロットが無い作品でも書ける**（決め事はプロットより先に決まるため） |
| `delete_world_note` | `note_id` 指定で枠を削除 |

`upsert_glossary_entry` には `author_note` 引数を追加した。

## 5. 不変条件（テストで担保）

- 定型枠は `slot` 一致で 1 枠に収束し、既存ノートの `id` を保つ（毎回作り直さない）。
- `body` を空にすると枠ごと消え、もともと無い枠を空で保存しても no-op（同一参照を返す）。
- 自由枠は `title` 必須。未知の `slot` は MCP が弾く。
- 旧データ（`world` 欠落）を読み込むと `[]` で埋まる。
- 世界観設定だけ書いたプロットは `isTrivialPlot` で「中身なし」にならない（同期レースで消えない）。
- `toBundleWork` は用語集を送るが `authorNote` だけ落とす。用語集を持たない作品に `glossary` キーは生えない。
- `get_plot` は世界観設定を `【プロット】` 見出しより前に出す。`get_glossary` は本体を載せず `get_world` へ誘導する。
- 世界観設定が空の作品では、`get_plot` / `get_glossary` の両方が `set_world_note` を案内する。
- 定義から外れた `slot`（過去の枠など）を持つノートは「無題」にならず、`slot` 名を見出しにして「そのほか」へ並ぶ＝中身を見失わない。
- 枠のラベルと案内文に特定ジャンルの語（魔法・種族・王国 等）を持ち込まない。現実に無い仕組みの枠は 1 つだけ・任意。
- 入力欄は画面に 1 つだけ（項目ぶん縦に積まない）。項目を選ぶと右がその項目だけに入れ替わる。
- 書きかけのまま別の項目へ移っても、blur を経ずに保存される。
- 自由枠は見出しがあれば本文が空でも残り、定型枠は空なら消える。
- `@` で用語集のサジェストが出て、選ぶと `[[名前]]` が入る。`[[` でも出る。用語集に無い語は登録してから挿入される。
- 自由枠だけ見出しを変えられ、削除できる（定型枠には削除ボタンも見出しの編集ボタンも出さない）。
- 鉛筆を押すと見出しの入力に入り、既存の見出しが丸ごと選択される（打ち直しが 1 手）。
- 「メモを足す」と足したメモが右に開く。保存は非同期なので、`plot` に現れるまでの一瞬で先頭の枠へ戻さない。
- バックアップの書き出し → 読み込みの往復で世界観設定が残る。
- プロットの canonical JSON（同期に載る内容）に世界観設定が含まれ、書き換えるとハッシュが変わる。
- `get_work` / `get_structures` の読み取りにも `get_world` への導線が出る。`set_episode` / `add_episode` の説明が `get_world` を指す。
- `world` / `secrets` を持たない保存済みレコードを `PlotRepository` 経由で読むと空配列で埋まる（埋めるだけで他の項目は書き換えない）。欠落したままでも `isTrivialPlot` / `worldNotesInOrder` / `pickPrimaryPlot` は落ちない。

## 6. 積み残し

- **既存 `【作者用】` 項目の引っ越し。** 移送は MCP（`get_glossary` → `set_world_note` → `delete_glossary_entry`）で行える。UI の一括移送ボタンは今回入れていない。
- **読者向け用語集の項目単位の公開可否。** いまは「送る／送らない」が器の単位。項目ごとに読者へ出す・出さないを選ぶなら `GlossaryEntry` に後方互換でフラグを足す（`authorNote` が既にあるので、当面はそちらで足りる想定）。
