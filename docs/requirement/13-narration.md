# コトノハ-leaf- 朗読音声書き出し機能設計

作成日: 2026-10-31

2026-11-07の追加合意は [操作仕様](../specs/narration-workflow/decisions.md) を優先する。
状態: 再実装の基準。PR #55の試作はPR #56で取り下げた。

## 1. 方針と範囲

作者が執筆済みの小説を朗読音声にし、試聴・調整したうえでファイルとして端末へ保存する機能を追加する。

- 基本用途は「制作して書き出す」。生成後の試聴は制作確認用とする。
- 開発は固定のテスト音源と、利用可能な期間の `s2.1-pro-free` を使う。提供時のモデルと文字枠は §8 に従う。
- 本文・ルビの原稿は変更せず、朗読設定を別データで持つ。
- 作品の読み方辞書、配役、行ごとの演出と音声を再利用できるようにする。
- 音声投稿、投稿サイトでの再生、公開音声の保存・配信、公開音声アップロードは今回実装しない。
- 将来の音声投稿は、書き出したファイルを作者がアップロードする方式を別途検討する。
- 初版は MP3 書き出し。BGM・効果音のミックス、動画出力、声のクローン作成、音声の部分インペイントは含めない。

接続ツールの仕様上、コトノハには本文から独立した演出譜、話者、場面区切り、`block_id` が存在する。これは確認済み。ただし leaf の実装ソース・DB・既存書き出し形式は未確認なので、以下の名称は論理モデルであり既存API名ではない。

## 2. 作者の操作

### 最初の試聴から書き出しまで

既定の操作は「声と朗読スタイルを選ぶ → 一話を生成する → 通しで聴く → 書き出す」。段落や台詞ごとの調整は、気になった箇所を再生画面から開けるようにする。生成前に全区間の確認を求めず、通し試聴も書き出しの必須条件にしない。

| 調整範囲 | 操作 |
|---|---|
| 作品・話 | leafが用意した朗読スタイルを選ぶ。「自然な一人語り」「明るく軽快」「静かに余韻を残す」などを候補とし、語りの基調・テンポ・場面の間に反映する。配役は独立して選べる。 |
| 場面 | 必要な場面だけ「緊張感を出す」「穏やかに」などで上書きする。既存の演出譜の場面区切りを使う。 |
| 台詞・段落 | 詳細設定で声、読み、演技、間を調整する。個別指定は場面・作品の設定より優先し、解除すれば上位の設定を引き継ぐ。 |

通し試聴中に「ここを直す」で現在の区間を開き、修正後は少し手前から再生できるようにする。前後のつながりを聴いて採用する。プリセットの変更で再生成が必要な場合は、影響する範囲と消費文字数を確定前に示す。品質検証では、個別調整なしで書き出せた割合と、最初の書き出しまでにかかった時間を測る。

体験の中心は、作者が自分の原稿で声を選び、台詞の読み方を変え、その違いを耳で確かめられること。Drama 3では指示なしの読みも選べるようにし、演技は効かせたい箇所から足せるようにする。指示なしでも良好という作者の試聴所感を出発点に、同じ原稿と声で指示あり・なしを比較する。

- **声を選ぶ。** 日本語の短い既成サンプルで声を比較する。落ち着き、明るさ、年代感などの手がかりを添え、語り手向けと台詞向けの候補を出す。モデルと利用条件を確認した声から揃え、声の数は試聴結果に基づいて増やす。
- **声を出し分ける。** 「ひとり朗読」と「配役朗読」を同じ画面から選ぶ。配役朗読では既存の演出譜の話者を使い、作品の配役を次の話にも引き継ぐ。作者が台詞を選べばその箇所の声を上書きできる。
- **台詞に演技を付ける。** 台詞を選び「軽く冗談めかす」「息をひそめる」「温かく語る」などから選択する。詳細で短い自由記述を使えるようにする。既存の音声と変更後の音声を同じ箇所で聴き比べ、採用する音声を選べるようにする。
- **試聴の費用を見せる。** 既成サンプルと生成済み音声の再生は生成枠を使わない。自分の原稿で声や演技を変えて生成する場合は対象文字数を事前に表示する。

初回体験では、短い地の文と台詞を含む範囲を選べるようにする。品質検証では、書き出しまでの時間、同じ区間の再生成回数、読み間違いの修正箇所、声と演技の比較後に採用できた割合を確認する。

作品から独立したページ「朗読制作」を開く。既存の「書き出し」は完成音声の取得への導線として使える。制作画面は作品・話を切り替えても設定とジョブを復元できる専用ルートを持つ。

デスクトップでは中央に幅を確保した原稿と、右に選択中の範囲の編集欄を置く。狭い画面では原稿・編集欄を縦に並べ、操作中の範囲へ戻れるようにする。長いタイトル、原稿、演技指示は折り返し、画面全体の横スクロールを防ぐ。上部に使用モデル、月間または体験の上限、残り文字数を表示し、生成操作のそばに今回消費する文字数を出す。

原稿上で話全体、場面、台詞・段落、連続する複数の段落を指定できる。指定を保存した場所は本文上に印を表示し、複数の離れた箇所にも別々の演技を保存できる。スタイル名には読みの速さ・明るさ・場面間の間がどう変わるかを短く添える。試聴の再生位置と原稿を対応付け、修正・試聴・採用の操作を原稿と行き来せず続けられるようにする。

生成処理と採用音声は画面コンポーネントの寿命から切り離す。別画面への移動や再読み込みをしても、処理中のジョブIDから進捗を復元し、取得済み音声を再利用する。画面を閉じる操作はキャンセルと区別する。

1. 現在の話、または選択した複数話を選ぶ。初期選択は現在の話。
2. 「ひとり朗読」または「配役朗読」を選ぶ。初期値はひとり朗読。
3. 語り手の声を選ぶ。配役朗読では登場人物ごとに声を割り当てる。
4. 朗読スタイルを選ぶ。読み方・話者の確認欄で、必要に応じて未設定箇所や辞書候補を確認する。
5. 必要に応じて、選択した短い区間を試聴する。新規生成を伴う試聴には消費文字数を表示する。
6. 未生成・変更ありの区間、消費枠、推定時間を確認して生成する。
7. 一話を通して試聴できる。気になる区間があれば再生位置から開き、読み・話者・演技を調整して再生成する。
8. 採用した音声を結合し、MP3をダウンロードする。

複数話は話ごとのMP3をZIPで書き出す。初版では全話を一本にする機能は必須としない。

制作画面には、本文、話者、読み補正・演技の有無、音声状態、再生・再生成を並べる。詳細設定は必要な区間を選んだときに開く。

## 3. 語り手と配役

### ひとり朗読

地の文と台詞を同じ声で読む。台詞ごとの演技指定はできる。一人称の作品では、主人公を語り手に設定できる。

### 配役朗読

地の文・心の声の既定声と、人物ごとの台詞の声を分ける。配役は作品単位で保存する。

- 既存演出譜に話者がある場合、それを初期値として利用する。
- 用語集の人物は配役候補に利用する。新規の音声用情報は作者用の別データとして保存する。
- 話者未設定の台詞は作者に選択してもらう。未設定を含む生成では語り手で読む旨を表示する。
- 自動話者推定は後続改善とし、初版の動作に必須としない。推定する場合も確定値と区別する。
- 表示名「？？？」と実際の人物IDは分ける。名前を伏せても内部では声を指定できるようにする。
- 声を変えるときに既存演出譜の表示用話者や本文を暗黙に変更しない。

## 4. 読み方とルビ

発音の決定順は次のとおり。

1. その出現箇所に設定した明示的な読み・アクセント補正。
2. 原稿のルビ。
3. 作品の読み方辞書。
4. モデルの自動読み。

- ルビはアプリの既存パーサーから抽出する。文字列全体への単純な正規表現置換にはしない。
- `｜漢字《かんじ》` 等の対応範囲は既存エディター仕様に合わせる。
- 音声用テキストに変換してから送信し、本文・原稿ルビを変更しない。
- 特殊ルビは原稿ルビを優先し、ルビ内の文字列に辞書を再適用しない。
- 辞書の一致は長い語を優先し、再帰置換しない。一般語の部分一致による誤読を防ぐため、対象語・文脈を試聴できるようにする。
- 人物名・地名の既存の読みが利用可能なら辞書候補に取り込む。公開用の用語集を音声調整のために書き換えない。
- 音声化しないルビ、字義と読みの両方を読む処理などの特殊動作は初版で自動化しない。

辞書の画面入力は「表記」「読み仮名」を基本とする。詳細では短い語句の高低アクセントを試聴して調整できる設計にする。Fish固有の音素列は内部で生成・保存し、作者に直接入力を要求しない。かな変換で直る読みと音素指定が必要な読みを使い分ける。

## 5. 演技と音声調整

### 演技を指定する画面の仕様

「どんなふうに読んでほしいですか？」という一つの入力欄を、話・場面・台詞のどの範囲でも使う。自然文の直接入力を標準にする。候補チップは「そっとささやくように」などの編集できる文を入力欄に入れる。すでに文章があれば、作者の入力を保ったまま追記する。原稿と演技メモは別々に保存し、Drama 3への送信時に適用範囲の先頭へ指示を付ける。

1. **範囲を選ぶ。** 初期表示は「この話」。原稿から場面・台詞・連続した文を選ぶか、通し試聴中に「ここを直す」を押す。入力欄のすぐ上に対象名と原文の抜粋を出し、どこに効くか確認できるようにする。
2. **普段の言葉で書く。** 例は「少し寂しそうに。最後の『ありがと』だけ温かく」。話・場面・台詞の指示のうち適用されるものを表示し、個別指定を外すと上位の指示に戻る。範囲を選び直しても未保存の文を失わないようにする。
3. **保存または試す。** 「指示を保存」で次回の生成に反映できる。「この範囲を試す」では生成前に消費文字数を示す。複数箇所を先に指定し、まとめて一話を生成する操作も用意する。
4. **流れの中で聴き比べる。** 元の音声と新しい音声を同じ再生位置から切り替え、少し手前から前後のつながりを確認する。「この読みを採用」して初めて書き出し対象を更新する。結果が合わなければ元の音声に戻るか、指示を修正してもう一度試せる。

標準画面は「朗読スタイル」「声」「演技指示」「生成・再生」に絞る。読み・アクセント・細かな間の調整は、該当箇所の詳細から開く。狙った表現にならない場合は、範囲を短くして語句を選び直すか、指示を書き換えて確認できる。原稿編集で指定箇所の対応が曖昧になった場合は、確認待ちとして扱う。

公開前に作者が説明なしで、①スタイルだけで一話を書き出す、②通し試聴から台詞を選び自然文で演技を変更する、③前後を聴いて元に戻す、の三つを完了できるか確認する。日本語原稿で、適用範囲の取り違え、書き出しまでの時間、狙った演技を採用できるまでの再生成回数を観察する。操作の迷いが残る場合は画面を修正し、演技が安定しない場合は声・指示・分割を見直す。

- 演技指定は任意。指定なしでも生成できる。
- 初期候補は「おまかせ」「明るく」「穏やかに」「不安げに」「静かに感謝」「ささやく」程度に絞る。
- 基本の語り方を作品単位で保存し、場面・区間単位で上書きできる。
- 自由記述の短い演技メモを用意する。長さの上限を設定し、送信原価に含めて扱う。
- 自動で全台詞に演技タグを追加しない。推定演出やLLM解析の導入は別の改善項目とする。
- 速度は少数の選択肢を基本とし、音量は書き出し時に統一する。
- 無音の間隔は音声の外側でも調整し、間だけの変更でTTSを再実行しない。
- 詳細なアクセント編集は共通データモデルを先に持ち、初版UIは読み仮名補正を優先して段階的に追加する。

モデルに渡す演技は制御指示であり、結果の完全一致は保証しない。採用前の試聴を品質確認の中心にする。

## 6. 共通の音声データ

以下は新規に設ける論理データ。実装時に既存スキーマへ対応付ける。

| データ | 主な項目 | 役割 |
|---|---|---|
| VoiceProfile | id, provider, voiceId, version, label | 選択可能な声。利用条件を確認した声を提供する |
| VoiceCast | workId, characterId / narrator, voiceProfileId | 作品の配役 |
| PronunciationEntry | id, workId, surface, reading, accent, version | 作者用の読み方辞書 |
| VoiceCue | workId, episodeId, blockId, spanId, speakerId, readingOverrides, direction, speed, pauses, version | 行・台詞内の音声指定 |
| VoiceSegment | id, sourceRefs, textSnapshot, sourceRevision, contextSnapshot, settingsSnapshot, fingerprint, status | 生成する短いまとまり |
| VoiceTake | id, segmentId, model, voiceVersion, assetId, duration, generatedAt, actualInputBytes, status | 一回の生成結果。旧結果を上書きしない |
| VoiceSelection | segmentId, acceptedTakeId | 作者が採用した結果 |
| VoiceJob | id, userId, sourceSnapshotId, segmentIds, state, reservedQuota, cancelRequested | 非同期生成処理 |
| VoiceAsset | id, ownerId, storageKey, checksum, expiresAt, localStatus | 非公開の一時音声とローカル取得状態 |
| VoiceUsage | id, userId, jobId, segmentId, reservationId, billableCharacters, inputBytes, state | 枠の予約・消費・返却と原価の台帳 |

1行に複数話者がいる場合に備えて `spanId` を持つ。行番号だけで識別しない。本文編集で行が分割・結合された場合は、対応が確実な指定のみ移し、不明な指定は確認待ちにする。別の台詞へ黙って付け替えない。

既存演出譜との連携は `block_id` を基本キーにする。話者表示、立ち絵、BGMと音声の配役は関連するが、同一の設定とはしない。

## 7. 生成・キャッシュ・修正

処理の流れ:

`原稿の版を固定 → 読み・配役・演出を解決 → 区間分割 → 見積もり → 枠を予約 → キュー → TTS → 検証 → 試聴・採用 → 結合 → 書き出し`

- 分割は段落・台詞・場面の切れ目を基本とし、上限を超える場合は文単位で分割する。文字数の機械的切断で文を壊さない。
- 区間が短すぎる場合は自然さと再利用性を比較し、前後とまとめる。区間サイズは両モデルで実測して決める。
- 音素タグ・演技タグを途中で切らない。
- 生成時の原稿・辞書・声・演技設定を固定する。生成中に編集しても現在のジョブには混入させない。
- fingerprintには実際の送信テキスト、モデル、声と参照音声の版、辞書解決結果、演技、速度、音声形式、使った文脈、前処理の版を含める。
- 同じ設定で採用済み音声があれば再利用し、TTSを呼ばず利用枠も消費しない。キャッシュは利用者間で共有しない。
- 本文・辞書・配役を変更したときは、影響する区間だけを「変更あり」にする。文脈を使う場合は依存する区間も対象にする。
- 「別の読みを生成」は同じ設定でも明示的な新規生成となり、利用枠を消費する。
- 修正が失敗しても、以前に採用した音声は残す。旧原稿の音声を使う場合は古い版と分かる表示にする。
- 結合点の途切れ・声色の変化は品質評価に含める。必要なら前後を含めた短い区間で再生成する。

状態は `draft / queued / generating / ready / failed / canceled / stale / missing` を扱う。`stale` は原稿や設定の変更、`missing` はファイルの期限切れ・端末削除を表す。

## 8. 提供枠と原価管理

既存500円プランを維持する。以下は会話での提案値であり、料金公開・課金設定の変更は本設計では行わない。

| 月額総額・税込 | モデル | 朗読枠 |
|---|---|---|
| 無料 | Drama 3 | 初回のみ500文字 |
| 500円 | S2.1 Pro | 月5,000文字 |
| 980円 | Drama 3 | 月10,000文字 |
| 1,980円 | Drama 3 | 月30,000文字 |
| 4,980円 | Drama 3 | 月100,000文字 |

無料体験はアカウントにつき一度だけ付与する。検証環境の無料APIと公開用の体験枠は別設定とする。プランの権限はサーバーが確定し、画面の表示と予約処理は同じ定義を参照する。月次枠では期間末、体験枠では一回限りであることを表示する。

- 基本の消費単位は、今回新規生成する読み対象本文の文字数。ルビは親文字を数え、ルビ記法・作者用メモ・演技タグは利用者向け文字数から除く。
- 文字カウント仕様は共通ライブラリーに集約し、UTF-16コード単位をそのまま数えない。Unicodeコードポイントを基本とし、句読点を含め、音声化しない空白・改行を除く。
- 辞書・ルビ変換後の実送信バイト数も別に見積もり、過剰な読み展開や演技指示には長さ制限を設ける。原価は利用者向け文字数だけで推測しない。
- 新規生成の試聴、声の比較、作者都合の再生成も枠を消費する。保存済み音声の再生、再結合、再ダウンロードは消費しない。
- 月をまたぐジョブは予約時の期間に計上する。並列操作でも予約を原子的に扱い、上限超過を防ぐ。
- 生成の成功後に消費を確定する。失敗区間・未実行区間の予約は返却する。
- タイムアウト等の結果不明状態では無制限に再送しない。ジョブ・試行IDで重複を記録し、事業者側原価と利用者の消費を分ける。
- キャンセルは未着手の区間を停止し、実行済み・成功済みの扱いを実行前に示す。原価発生済みの区間を未生成扱いに戻して繰り返し利用できない設計にする。
- 運営障害・明確な音声不良の返却は上限付きの別台帳に記録する。モデル出力が好みに合わない場合は通常の再生成とする。
- 追加5,000文字・500円は案として保持する。初版に必須ではない。
- 無料API利用中から利用枠・原価相当額を記録し、本番切り替え前に採算を評価する。
- API費用、演技・発音指定による増分、サーバー一時保存、結合処理、ダウンロード、問い合わせ対応を別々に計測する。

暫定原価前提: Drama 3通常料金 $50 / 100万UTF-8バイト、日本語1文字あたり概算3バイト。1ドル160円なら1万文字約240円、30%の余裕込み約312円。現在の料金と為替は設定で更新し、原価予算超過時には新規ジョブを止める。30%は実測値ではなく、発音タグを多用した場合は不足する可能性がある。

## 9. API・保存の責務

- APIキーはサーバー側のシークレットとして管理し、ブラウザーへ渡さない。
- サーバーが認証、プラン判定、利用枠の予約、送信サイズ検証、モデル選択、ジョブ制御を担う。
- クライアントから任意のモデル名・原価・消費文字数を信用して受け付けない。
- 開発・本番を別設定にし、開発では `s2.1-pro-free` 以外を明示許可なしに使わない。有料への自動フォールバックはしない。
- モデル名の不正値で別モデルに落ちるAPI仕様を考慮し、送信前に許可リストで検証する。
- 生成開始には冪等キーを付け、二重クリック・通信再送でジョブと課金を重複させない。
- 同時生成数は全体キューで制限する。APIのレート制限時は回数上限付きで待機する。
- 原稿・声の参照データを外部送信することを、機能の初回利用時に分かるようにする。
- ログに本文全文やAPIキーを残さない。音声は作者本人だけが取得できる非公開領域と短命のダウンロードURLで扱う。

生成直後の一時音声は生成から7日保管する。2026-11-09の合意により、会員のバックアップ・別端末同期では音声を別の耐久保管へ保存する。全体ファイルバックアップは音声同梱ZIPとし、旧JSONも取り込める。保管上限・所有者分離・復元契約は [朗読のバックアップと端末間同期](../specs/narration-workflow/backup-sync.md) を参照。

期限切れ前にダウンロードを促し、同一音声の再取得と再生成を区別する。端末保存済みデータが確認できる場合は再利用できる設計にするが、初版でローカル永続保存を保証できない環境ではブラウザーキャッシュを保管の保証にしない。期限切れ後の再生成は通常の枠を消費する旨を明示する。

## 10. 書き出し

- 初版: 話単位のMP3、複数話はZIP。
- 書き出し前に全対象区間の採用音声・原稿版・欠落を検査する。
- 足りない区間を無音で埋めて完成扱いにしない。失敗時は完成した話だけを明示して書き出せる。
- 音量と出力形式をそろえ、区間の順番・場面間の間・再生時間を検証する。
- ファイル名には作品名・話番号・話タイトルを使い、OSで使えない文字を正規化する。
- 語り手や配役、辞書、演技は作者の設定として保持する。一般向けMP3に非公開の演技メモや秘密の人物情報を埋め込まない。

## 11. サウンドノベルへの拡張

今回から音声を「話全体のMP3」だけでなく、`block_id / spanId` とひも付いた短い採用テイクとして保持する。朗読MP3はそれらを結合した成果物とする。

後続機能では次を追加する。

1. 既存演出譜の台詞に採用テイクを関連付ける。
2. サウンドノベルの書き出し時に、採用した音声ファイルだけを同梱する。
3. パッケージ内の相対パスとブロックIDをマニフェストに保存する。外部の署名URLに依存させない。
4. 台詞表示と音声開始を連動させ、停止・スキップ・音量・自動送りを扱う。
5. BGMの音量抑制、音声終了待ち、音声なしの台詞へのフォールバックを追加する。

将来のマニフェスト例（新規設計案）:

```json
{
  "schemaVersion": 1,
  "voices": [
    {
      "episodeId": "episode-id",
      "blockId": "block-id",
      "spanId": "span-id",
      "asset": "audio/voice-segment-id.mp3",
      "durationMs": 4200
    }
  ]
}
```

配役の人物IDや作者用の演技指示を、必要なく書き出しパッケージに含めない。名前を伏せた登場人物の正体を漏らさない。

## 12. 実装順序と完了条件

### 将来のオーディオブック投稿

公開形式として、場面と台詞を操作しながら楽しむサウンドノベルと、話や章を続けて聴くオーディオブックを用意する構想。共通の配役・読み方・採用音声を制作側で使い、サウンドノベルには台詞の音声、オーディオブックには結合済みの章音声を渡す。

最初の提供範囲は端末へのMP3書き出し。将来の投稿は、作者が書き出した音声を明示的にアップロードし、作品の話や章に関連付ける。公開プレーヤー、章送り、音声の差し替え・削除、公開範囲、ファイル上限、保存・配信費は投稿機能の設計で決める。書き出し後の利用実績と作者の投稿意向を確認してから着手を判断する。

### A. 無料APIで機能を完成

読み変換、作品辞書、語り手と配役、区間管理、ジョブ、利用量台帳、試聴、部分再生成、MP3/ZIP書き出しを実装する。外部音声生成が不要な作業はローカルの固定音声でも検証できるようにする。

### B. Drama 3で品質と原価を検証

日常・恐怖・別れ、難読人名、同音異義語、特殊ルビ、複数話者を含む素材で比較する。短い台詞だけでなく一話分を通して評価する。声の利用条件とAPIを組み込む提供形態を確認する。

### C. 限定提供から正式公開

少人数で原価・修正率・失敗率・生成時間・問い合わせを計測する。プランの枠と保存期限を確定し、上限と支出停止を有効にして正式公開する。

最低限の受け入れ条件:

- 専用画面を長い日本語タイトル・長い指示を含む原稿で開き、対応する画面幅で横スクロールせずに操作できる。
- 一話のスタイルを選んで出力し、場面と複数の台詞へ別々の指示を保存できる。適用範囲と引き継ぐ設定が画面から分かる。
- 生成中に画面を移動・再読み込みしても同じジョブに戻り、生成後にも再生成せず再生・書き出しができる。
- 生成前にモデル・残り枠・今回の消費を確認でき、枠不足のリクエストは外部APIへ送られない。

- 原稿を変更せず、原稿ルビと辞書の優先順位どおりに音声用テキストを作れる。
- 声・辞書・演技の変更で必要な区間だけが変更扱いになる。
- 再生成失敗で採用済み音声が失われない。
- 二重送信・並列操作・月境界・キャンセル・結果不明で利用枠が不整合にならない。
- 開発環境から有料モデルへ意図せず送信されない。
- 生成音声に欠落がある場合、正常な完成品として書き出されない。
- 一話分のMP3と複数話ZIPを実際に再生し、順番・つながり・音量・読みを確認できる。
- 別の利用者の原稿・音声・ジョブへアクセスできない。
- 音声期限切れ・本文更新後も、状態と再生成時の消費が作者に分かる。
- 投稿先への音声アップロードや公開配信を、今回の機能が開始しない。

### 開発・リリース手順

最新の `origin/stg` から作業ブランチを切り、`stg` 向けPRでCIを確認する。`stg` へのマージで Cloudflare Pages のステージングに自動デプロイされる。ステージングで生成・試聴・書き出しを確認した後、`stg` から `main` へのリリースPRを進める。`main` へのマージで本番に自動デプロイされる。D1の変更がある場合は、既存ワークフローに従い各環境でデプロイ前にマイグレーションを適用する。
