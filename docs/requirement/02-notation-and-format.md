# 02 — 記法仕様 ＋ 正本 block スキーマ

## 1. 方針

- **正本記法 = サイト互換**（小説家になろう / カクヨム）。書き出しが恒等に近く、作家の学習がゼロ。
- 独自概念（@参照）だけは独自記法とし、外部書き出し時は degrade。
- **正本（block JSON）はエディタライブラリ非依存**。パーサ（記法→正本）と各エクスポータ（正本→ターゲット）は `src/core`（純TS・TDD）に置く。

## 2. 記法マッピング

| 要素 | 記法 | 互換 | 外部書き出し |
|---|---|---|---|
| ルビ | `｜親文字《よみ》`（半角 `|` 可、親文字が漢字のみなら `｜` 省略可） | なろう/カクヨム | ほぼ恒等 |
| 傍点 | `《《テキスト》》` | カクヨム | なろうは傍点記法が無い → ルビで `・` を振る等に **degrade** |
| シーン区切り | `＊` のみの行 | 独自 | 各ターゲットの区切り表現へ |
| 段落（block） | **改行＝1 block**、空行＝空 block（間として保持） | なろう流 | 行構造を完全保存（恒等） |
| @参照 | `[[名前]]` | 独自・**P1**（詳細 [04](./04-glossary.md)） | 外部（なろう/カクヨム/EPUB）はプレーンテキストに degrade／プレビューはグレーリンク。EPUB の用語集リンク化は P1+ |
| 強調・見出し | MVP では持たない（日本語小説で非慣用。話タイトルはメタ） | — | — |

## 3. 正本 block スキーマ（ドラフト）

> Zod でランタイムバリデーション。将来 `ref`（@参照）等を**後方互換で追加**できるよう設計する。

```ts
// src/core/schema (framework 非依存・純TS)
type Work = {
  id: string
  title: string
  // 表紙・帯・POP 等のメタは将来（公開ターゲット向け）
  episodes: Episode[]
}

type Episode = {
  id: string
  title: string
  blocks: Block[]
}

type Block =
  | { id: string; type: 'paragraph'; inlines: Inline[] }   // 空行は inlines: []
  | { id: string; type: 'sceneBreak' }
  // 将来: 'heading' | 'image'

type Inline =
  | { type: 'text'; text: string }
  | { type: 'ruby'; base: string; reading: string }
  | { type: 'emphasisDots'; text: string }      // 傍点
  // 将来: { type: 'ref'; name: string }         // @参照（P1）
```

## 4. パイプライン

```text
記法テキスト ──parse──▶ 正本 block 列(JSON) ──export──▶ EPUB / なろう / カクヨム
        ▲                      │
        └──── ライブプレビュー ◀┘ (正本 → HTML)
```

- **parse**: 行 split → 各行を inline 解析（ルビ/傍点を AST 化）。`＊` のみの行は `sceneBreak`。
- **export**: 正本を走査し各ターゲット記法/HTML/EPUB(XHTML+縦書きCSS) を生成。
- すべて純関数で **TDD 対象**（記法 → 正本 → 各ターゲットの往復テスト）。

## 5. 不変条件（テストで担保）

- なろう記法 → 正本 → なろう記法 が**恒等**（ルビ・行構造が保たれる）
- 空行・行数が往復で保存される
- 不正な記法（閉じ括弧欠落等）でパーサが壊れない（フォールバック挙動を定義）

## 6. 脚本形式（COT-6）

`Work.format?: 'novel' | 'script'` を作品単位で持つ。未設定は小説で、
小説に戻す操作ではキーを削除する。本文・Block の構造は変えず、描画・書き出し時に
`src/core/script/` が各行を次の順で判別する。

1. 空行・空白だけの行は空行。`***` だけの行（前後空白を除く）は場面転換。
2. 行頭空白を除いて `○`・`〇` で始まる行は柱。
3. 字下げした行はト書き（途中に鉤括弧があっても同じ）。
4. `「`・`『` で始まる行は話者なしのセリフ。
5. 名前（空白・括弧を除く1〜20文字）＋任意の `（補足）`（1〜10文字、1つまで）＋任意の空白＋`「`・`『` は話者つきセリフ。
6. それ以外はト書き。

プレビューは原稿用紙（`src/core/script/layout.ts`・縦書き 20字×20行、横書き 40字×40行）に組む。
柱は行頭で前に空行1つ（打ってあっても増やさない）、ト書きは3字下げ（折り返しも）、セリフは話者名から書き2行目以降は1字下げ。
`***` は `×　　×　　×` を中央に置く。半角は全角に揃え、！？の後ろは1マス空け、句読点はぶら下げ、閉じ括弧などは追い出す。ノンブルは本文の最初の頁を 1 とする。
書き出しは Word（`.docx`・横置き縦書き・20字×20行の行グリッド・A4 14pt／B5 12pt・柱書き／ト書き／セリフの段落スタイル・本文からのページ番号）か、体裁を整えたテキスト（`.txt`・折り返しなし）。
公募の規定は多様なので PDF のような固定レイアウトにせず、Word で手直しできる形にする。
表紙・登場人物表（用語集の人物）・梗概（`Work.synopsis`・結末まで・読者向けの `description` とは別）を前付けにできる。梗概は grove へ送らない。
書式チェックは上記に加え、セリフ末尾の句点・算用数字・カメラワークの指示・登場人物表に無い話者も候補にする。
EPUB・なろう・カクヨムは小説専用で、脚本の作品では書き出し先に出さない（exporter も形式で出力を変えない）。
AI向けテキストと MCP は形式の説明をメタ情報に加え、本文は従来どおり出力する。
フォルダ zip と同期には本文を変更する処理を追加しない。
小説の出力は従来どおり。`＊` 行は現在のパーサでは通常の段落である（上の初期ドラフトにある sceneBreak は廃止済み）。

grove 公開は脚本だけ `format: 'script'` を含む契約 v7 を使う。
公開先が v7 未対応なら形式を小説に戻す案内を表示する。
本番反映は grove の v7 リリース後とする。演出譜の話者判別は今回の対象外。

### 入力補助と書式チェック

セリフの挿入は小説でも利用できる。丸括弧・隅付き括弧のボタンは利用頻度が低いため置かない。PC ツールバーではボタンのラベルの下にキーを表示する（スマホの記法バーには表示しない）。
ルビ/傍点/用語引用は Ctrl/Cmd+I/B/K、セリフ/柱/場面転換/三点リーダー/ダッシュは
Ctrl+Alt+D/H/S/E/M（MacはCtrl+Option）。三点リーダー「……」とダッシュ「――」は2マス分をまとめて入れ、小説でも使える。柱・ト書き・場面転換は脚本だけで利用でき、IME変換中は記法挿入を行わない。
「場面転換」は現在行の前に独立した `***` 行を入れる。

ト書きは脚本の大半を占めるため、PC ではボタンやショートカットではなくキー操作で入れる。
Tab で現在行（選択中は各行）の行頭空白を全角3つに揃え、Shift+Tab で外す。
字下げした行で Enter を押すと次の行も同じ字下げで始まる（空白だけの行でも継続し、抜けるのは Shift+Tab）。
Esc の直後の Tab は標準のフォーカス移動に返す（キーボードだけでエディタから出る逃げ道）。
用語サジェストが開いている間は Tab / Enter を候補の確定に譲る。
スマホは Tab が無いので、記法バーに「ト書き」「ト書き解除」ボタンを置く。PC ツールバーには脚本の書き方を説明するⓘを置く。脚本の本文のプレイスホルダーで、柱・セリフ以外の行が自動で3字下がることを案内する。
脚本の `***` は原稿用紙で `×　　×　　×` として中央に配置し、AI 向けテキストでは打ったまま保持する。

脚本の「書式チェック」は確認候補を表示するだけで、本文を書き換えない。
柱の有無・空の柱・話者の有無と判別・行内の括弧の対応を確認し、候補から該当行を選択できる。
表記の意図や場面転換の必要性は判定しない。意図した書き方ならそのまま保存・書き出しできる。
