# 11 — 用語集の「対話」（一問一答で項目を育てる）

> 2026-09 決定。[04-glossary.md](./04-glossary.md) の出発点（本文に出る固有名詞を `@` で入れ、書きながら見て、あとで一括で直す）に立ち返り、
> 用語集の項目を**決まった質問に一問ずつ答えて**登録・深掘りできる入口を足す。
> 画面の試作は https://claude.ai/artifact/X8EuYyrHvgMs3sf7AdV8uK 、質問の正本は本書の付録 A（一覧ページ https://claude.ai/artifact/Qw5483HqrrdsCQrXW8A3Uv と同内容）。

## 0. 何を作るか

用語集の右ペインに「フォーム｜対話」のタブを足す。対話は **LLM を使わない台本つきのボット**で、
項目の名前を呼びかけながら決まった質問を順に出し、答えを一問ずつ保存する。
名前・読み・別名・公開情報の 4 問は既存の欄へそのまま入り、深掘りの答えは項目に紐づく新しい器（対話ノート）へ入る。
途中でやめても、一覧の「対話の途中」から再開できる。
MCP（外部の AI）からも同じ器を読み書きできる（§5）。

## 1. 決めたこと

| ID | 決定 |
|---|---|
| **D-DLG-ENTRY** | 入口は既存の「＋ 新しく登録」ひとつ。押すと右ペインが**対話タブ**で開き、最初に分類を聞く。既存の項目を開いたときは**フォーム**で開く（今の利用者の操作は変えない）。見出し横の「フォーム｜対話」でいつでも行き来できる。 |
| **D-DLG-BOT** | ボットは**決まった質問だけ**をする（自由入力を理解しない）。最初の一言でそう名乗る。選択肢はチップ、入力欄は答えを書くためだけに使う。 |
| **D-DLG-NAME** | ボットは項目の名前を呼びかけて聞く（「セトの特技や、得意なことはありますか」）。名前が未入力なら分類ごとの言い換え（その人物／その場所／その集まり／その物／その生き物／その言葉）。 |
| **D-DLG-SECTIONS** | 質問は「プロフィール」「見た目」「話し方」のような**まとまり**に分け、切り替わりでボットが「ここから話し方について 4 問です」と言う。 |
| **D-DLG-SKIP** | どの問いも「スキップ」と「あとで答える」ができる。あとでにした問いは一覧に「あとで n」と出て、次に開いたときに聞き直す。進み具合は**基本の問いだけ**で数える（任意は数に入れない）。 |
| **D-DLG-DIG** | 「もう少し深める」の追い質問は**人物の 6 問だけ**（特技・癖・譲れないもの・好きなこと・嫌いなこと・怖いもの）。向きは「どうしてそうなったのか」に限る。答えたあとにチップで聞き、押さなければ次へ進む。追い質問の答えは親と同じ公開の扱い。 |
| **D-DLG-KIND** | 場所・組織・アイテム・生物・用語は最初に「種類」を聞き、その答えでだけ出る枝の問いを持つ（宗教の教えと儀式、国の統治のしくみ、架空の生き物の弱点、言葉を話す種族の暮らし、出来事の経緯など）。分類は 6 つのまま増やさない。 |
| **D-DLG-VIS** | 公開の既定は 4 段階。共通 4 問＝読者に見える欄そのもの（固定）。**プロフィールのまとまり＝最初から「読者に見せる」で、作者だけに戻せる**。それ以外の深掘り＝「作者だけ」が既定で、読者に見せるへ切り替えられる。秘密＝作者だけ（固定）。切り替えは答えの吹き出しの印を押す。 |
| **D-DLG-STORE** | 答えは `GlossaryEntry.dialog`（optional の record。§2）に**質問の鍵ごと**に持つ。共通 4 問は既存の欄（`name` `reading` `aliases` `summary`）へ書き、`dialog` には持たない。種類は `dialog.kind` に持つ。 |
| **D-DLG-EXISTING** | 既存の項目は共通 4 問を聞かず、深掘りから始める（名前・読み・別名・公開情報はフォームの欄で直す。対話の冒頭に「フォームに入っている情報」のカードを出す）。分類が無い・質問セットの無い分類（旧データの自由入力）の項目は、まず分類から聞く。フォームで作った項目にも同じ対話ノートが付く。 |
| **D-DLG-PUBLISH** | 第 1 段では**公開バンドルの契約を変えない**。`dialog` は投稿時に落とす（`toBundleGlossary` が `authorNote` と同じく除く）。読者に見せる答えは、まとめカードの「公開の答えから公開情報の下書きを作る」で `summary` の下書きにし、作者が確認して入れる。構造のまま grove へ送るのは第 2 段（契約の版上げ・先方との合意が要る）。 |
| **D-DLG-LIST** | 一覧の各行に進み具合を出すのは**対話を始めた項目だけ**（途中＝細いバーと「対話 9/25」、完了＝「✓ 対話済み」）。手を付けていない項目は今の見た目のまま。分類チップの末尾に「対話の途中 n」を足す。 |
| **D-DLG-KEYS** | 入力欄は Enter で決定、Shift+Enter・Ctrl+Enter・Cmd+Enter で改行。IME 変換中の Enter は決定にしない。`@`／`[[` の候補が開いているあいだは Enter・Tab が候補の確定。タッチ端末では Enter＝改行、決定は「答える」ボタン。 |
| **D-DLG-REF** | 入力欄は既存の `CommitTextarea`（`@`／`[[` サジェストつき）を使う。答えの中の `[[名前]]` はそのまま保存し、表示ではリンクとして描く。 |
| **D-DLG-EDIT** | 答えの吹き出しの「直す」でその問いだけ聞き直す。途中で直したあとは本流（次の未回答）へ戻る。全問答え済みなら「どれを変えますか」の一覧を出し、選び直す。 |
| **D-DLG-MCP** | MCP で対話ノートを**読める・書ける・消せる**（§5）。`get_glossary` が答えを返し、`upsert_glossary_entry` の `dialog` で鍵ごとにパッチし（省略＝据え置き、空文字＝削除）、質問の鍵と選択肢は `get_glossary_questions` で引ける。 |
| **D-DLG-WORLD** | 国の税制・経済の仕組み・宗教の全体像のような**名前のない設定は聞かない**（世界観設定の器＝[08](./08-worldbuilding.md)）。対話で聞くのは、その名前の項目そのもののことだけ。ボットの案内と MCP のツール説明の両方で `set_world_note` へ誘導する。 |

## 2. データ（正本スキーマ・後方互換）

```ts
// src/core/schema/index.ts に追加（すべて optional。旧レコードはそのまま読める）
export const DialogAnswerSchema = z.object({
  /** 答え。空文字は「スキップ／あとで」の印としてだけ使い、公開・下書きには使わない */
  text: z.string(),
  /** 読者に見せるか。省略＝その問いの既定（D-DLG-VIS） */
  public: z.boolean().optional(),
  /** スキップした（聞き直さない） */
  skipped: z.boolean().optional(),
  /** あとで答える（次に開いたとき聞き直す） */
  later: z.boolean().optional(),
})
GlossaryEntrySchema = GlossaryEntrySchema.extend({
  /** 対話ノート。鍵は質問の key（追い質問は `親__子`）。無い＝対話を始めていない */
  dialog: z.record(z.string(), DialogAnswerSchema).optional(),
  /** 答えたときの質問セットの版。質問を足したり消したりしても旧データを壊さないための印 */
  dialogVersion: z.number().optional(),
})
```

- **消さない・必須化しない**（CLAUDE.md の互換規約）。`dialog` が無い項目は「未着手」として扱い、既定値を埋めない。
- **IndexedDB の直読み**は Zod を通らないので、`dialog` の有無だけで分岐し、`.default` に頼らない。
- **公開バンドルからは落とす**（第 1 段・D-DLG-PUBLISH）。同期・バックアップは `Work` ごと運ぶので追加実装なし。
- **質問を変えたとき**は、鍵を消さずに `deprecated` の印を質問側に付け、旧鍵の答えは対話ノートの表示に「（旧）」として残す。鍵の改名はしない（する場合は読み出し時に読み替える互換ヘルパを置く）。

## 3. 質問セットの置き場と純ロジック

- 質問セットは**純データ**として `src/core/glossary/dialog.ts` に置く（`BASE` `DEEP` `KINDS` `FALLBACK`。付録 A と同内容。React・UI を import しない）。
- 同ファイルに純関数を置き、テストを同階層に並べる。
  - `questionsFor(category, answers)` … 種類の枝と「伏せていること」の分岐を解いた、いま有効な問いの列
  - `nextQuestion(entry)` / `progress(entry)`（基本だけで数える）/ `isAnswered` / `laterCount`
  - `digQuestionsOf(question)` … `親__子` の鍵を持つ追い質問
  - `resolveName(entry)` … 名前か分類ごとの言い換え（D-DLG-NAME）
  - `defaultPublic(question)` … D-DLG-VIS の既定
  - `draftSummaryFromDialog(entry)` … 公開の答えから公開情報の下書き（D-DLG-PUBLISH）
  - `applyDialogPatch(entry, patch)` … MCP と UI が共用するパッチ規則（§5.2）
- 画面は `src/ui/components/GlossaryView/` に対話ペインを足す（既存の二枚看板を壊さない。入力欄は `CommitTextarea`）。

## 4. 画面の要点（試作で確認済み）

- 右ペインの見出し横に「フォーム｜対話 n/m」のセグメント。対話タブは会話ログ＋入力欄。
- フォーム側の作者メモの下に「対話ノート」の区画。未着手なら案内と「対話で深める」、途中なら答えの一覧と「対話をつづける」、済みなら「対話で直す」。ここは見るだけで、直すのは対話から。
- ひと通り答えると「まとめ」のカード（読者に見える答え／作者だけの答え）と、「公開の答えから公開情報の下書きを作る」。
- 新規は登録するまで保存しない（下書き）。フォーム側の「用語集に登録」も同じ結果になる。登録するとその項目のフォームで開く。書きかけの下書きを残したまま別の項目や「＋ 新しく登録」へ移るときは、捨てるかを確認する。
- 対話は一度開いたらタブを切り替えても隠すだけ（会話の途中を保つ）。項目を切り替えると会話は消え、次に開いたときは答え済みを並べ直して続きから聞く。
- 答えるたびに保存する（既存の項目）。保存に失敗したときは対話の中に一言出し、会話は止めない。

## 5. MCP（読む・書く・消す）

### 5.1 `get_glossary`（既存・出力を足す）

各項目の平文に「対話ノート」の節を足す。鍵・見出し・公開の扱い・答えを一行ずつ。

```
[entry_id: g_123] セト（人物）
  読み: せと / 別名: 案内人さん
  公開情報: 境の街の案内人。
  作者メモ: …
  対話ノート（非公開・v1）:
    kind: —（人物には無し）
    title 役職・肩書き [読者に見せる]: 境の街の案内人
    skill 特技 [読者に見せる]: 道を一度で覚える
    skill__why ↳どうして身についたか [読者に見せる]: 迷えば帰れない場所で育ったから
    value 譲れないもの [作者だけ]: 約束の値段は変えない
    secret 秘密 [作者だけ・固定]: 帳の向こうの記憶
    （スキップ: birthday, blood ／ あとで: rival）
```

### 5.2 `upsert_glossary_entry`（既存・引数を足す）

- 新しい引数 `dialog`（object）。鍵は質問の key（追い質問は `親__子`、種類は `kind`）。値は次のいずれか。
  - 文字列 … 答えを設定。`""`（空文字）は**その答えを削除**。
  - `{ "text": "...", "public": true|false }` … 答えと公開の扱いを同時に設定。
- **パッチ方式**（既存の規則と同じ）。渡した鍵だけ書き換え、渡さない鍵は据え置く。
- `public` を省略したとき、新規の答えは D-DLG-VIS の既定、既存の答えは据え置き。固定公開／固定非公開の鍵に `public` を渡しても無視して固定値にする（エラーにはしない）。
- **未知の鍵はエラー**にし、有効な鍵は `get_glossary_questions` で引くよう案内する（誤字で答えが迷子にならないため）。
- `kind` は分類ごとの選択肢のいずれか。それ以外はエラー（選択肢は `get_glossary_questions` に出る）。
- `dialogVersion` は書き込み時にサーバが現在の版で埋める。
- 共通 4 問（name／reading／aliases／summary）は従来どおりトップレベルの引数で渡す。`dialog` にこれらの鍵を入れたらエラー。
- ツール説明に、世界全体の決め事は `set_world_note` へ、を残す（D-DLG-WORLD）。

### 5.3 `delete_glossary_entry`（既存・変更なし）

項目ごと消える（対話ノートも一緒に消える）。答えを一つだけ消すのは 5.2 の空文字。

### 5.4 `get_glossary_questions`（新規）

引数：`category`（省略で全分類）。認証は他の読み口と同じ。
返すもの：分類ごとに、まとまり／鍵／見出し／ボットの言葉（名前は「（名前）」の印のまま）／公開の既定／基本・任意／形式（自由記述・選択肢とその値）／条件（種類が◯◯のとき、伏せていることが「ある」のとき）／追い質問の鍵。
LLM はこれを読んでから `upsert_glossary_entry` の `dialog` を組む。作品に依存しないので `work_id` は要らない。

### 5.5 純ロジックの共有

`applyDialogPatch`（§3）を MCP の `upsertGlossaryEntry`（`src/core/mcp-edit`）と UI の保存の両方が呼ぶ。鍵の検証・既定の公開・固定の扱いを一か所に置き、片方だけ緩まないようにする。

## 6. 後方互換の確認項目

- 旧レコード（`dialog` 無し）が一覧・フォーム・公開・同期・バックアップ・MCP の全経路で今までどおり読めること（回帰テスト：旧形式フィクスチャ）。
- `dialog` を持つ Work を**旧バージョンのクライアント**が読んでも壊れないこと（Zod は未知キーを落とすだけ。`WorkSchema.parse` を通る経路で `dialog` が消えないことを確認する＝スキーマに足し忘れると同期で消える）。
- 公開バンドルに `dialog` が載らないこと（第 1 段）。
- MCP の `upsert_glossary_entry` が `dialog` を省略したとき、既存の対話ノートを落とさないこと（パッチ規則）。

## 8. 未決（暫定スタンスつき）

- **種類に「その他」を足すか。** 足す方向。選ぶと枝は出ず、共通の問いだけになる。
- **誕生日の入力形式。** 自由記述のまま（架空の暦を使う作品で月日の形に収まらないため）。
- **任意の問いの入口。** 本流に混ぜて「（任意）」と添える。多いと感じたら「もっと深める」として別の入口に切り出す。
- **「深める」を続けて押したら以後は自動で追い質問に入る設定。** 第 1 段では持たない。

## 付録 A — 質問の正本（第 9 版）
