# 朗読制作の実装・検証メモ

設計の正本は [朗読書き出し機能設計](requirement/13-narration.md)。
開発開始点は origin/stg の cdda3ca。作業ブランチは feat/narration-studio。
本番リリースは stg での動作・演技品質確認後の別工程。

## 実装境界

- 執筆画面の「朗読制作」から専用ルートへ。遷移前に本文を保存する。
- 作品の声・スタイル・配役・辞書と、話／場面／連続段落の演技を本文とは別に保存。
- 個別の読み > 原稿ルビ > 長い辞書語 > モデルの読み。指示は範囲と原文を照合し、本文変更で対応が不確かなものは適用しない。
- 原稿を句読点で区切り、原文参照（blockId/spanId）を保つ。区切りのない800文字超は生成前に案内する。
- 同じ設定の採用音声・未採用候補を再利用する。意図した「この範囲を試す」は新しい生成になる。
- 画面から独立したストア、IndexedDBの採用テイク、D1ジョブ、Durable Object alarmで画面移動／再読込後も復元。
- 元／候補を前後の音声を含めて聴き、同一範囲なら再生位置を保って切り替える。採用は明示操作。
- MP3は44100HzのMPEG-1 Layer IIIフレームを検査し、ID3/Xingを取り除いて結合。間はreservoir無効の無音MP3を使い、TTSを呼ばず変更できる。入力音量はFishのnormalize_loudnessで揃える。
- MP3に辞書・人物ID・演技指示を埋め込まない。欠落／未採用／変更ありは書き出し前に停止する。
- 設定と音声は端末のIndexedDBに保存。**現時点では既存のクラウド同期・JSON全体バックアップには含まれない**。完成MP3の書き出しを案内する。
- 公開投稿・サウンドノベルへの音声同梱は今回の実装に含めない。

## サーバーと原価

`0011_narration.sql` を Pages より先に適用。
D1 batch内のトリガーで文字枠を予約し、成功だけ消費、失敗／未着手キャンセルは返却する。
予約時の期間を保持し、JSTの月境界や年額会員にも月次枠を適用する。
日次入力バイト上限は `NARRATION_DAILY_BYTE_LIMIT`（既定1,000,000）。失敗を含めた保守的な合計で停止する。
試行IDはtake ID。結果不明は自動再送せず予約を保留し、事業者側での成功／失敗を確認して運営が確定する。
D1ロックで環境全体1区間ずつ。プロバイダーの429は失敗として返却し、作者が時間をおいて再試行する。

原稿スナップショットは既存ENCRYPTION_KEYで暗号化したR2。
音声はprivate R2のユーザーprefix内に保存し、Clerk認証＋所有者照合のAPIだけで取得。
署名付きの公開URLは発行しない。
音声は生成から7日、原稿スナップショットは30日で時間単位のcronが削除する。
期限切れでも端末に取得済みならその音声を再利用する。
ジョブ・利用量台帳は無料体験の再付与防止と原価調査のため残す。

## 公開切り替え

現在はstaff限定、s2.1-pro-free固定。有料モデルへの自動フォールバックはない。
NARRATION_RELEASE=1 と NARRATION_PAID_ENABLED=1 の両方を明示設定しない限り有料モデルに送信しない。
料金公開・Stripe価格作成・本番のWorker作成はこの変更では行わない。
既存STRIPE_PRICE_MONTHLY/YEARLYはbasic、追加プランは
NARRATION_PRICE_STANDARD/PLUS/PREMIUMをサーバー側のprice IDに対応付ける。

声の初期目録はユーザー設定済みのFISH_NARRATION_VOICE_ID（Shiori）だけ。
追加する声は利用条件・日本語の試聴を確認したうえで、NARRATION_VOICESに
id/label/description/version/referenceId/sampleUrlの配列を設定する。
sampleUrlは自サイトの /narration-samples/ 以下のみ。声クローン作成や未確認の公開声を自動で提供しない。

## 作業画面の整理（2026-11-05）

## 合意した操作の実装（2026-11-07）

- 正本は docs/specs/narration-workflow/decisions.md。話別の声・スタイル、クリック／ドラッグ選択、右上／余白／Escの解除、読み方の箇所修正と共通化を追加。
- 指示と生成区間を分ける。文・台詞単位で生成し、語句の演技は対象語を引用した自然文の指示として渡す。演技強度・再現性はモデル依存で、実音声の品質評価を引き続き必要とする。
- 部分候補は保存し、元／新の選択に対して一つの採用ボタン。比較プレーヤーは同じ欄内。前後の音声を含む。生成時の文字枠消費は採用と独立。
- 一話生成／再生成は全区間が成功し端末への音声保存が終わってから一括採用。失敗時は旧音声を保持。再試行は成功済み区間を再利用。
- スタイル試聴は別の日次回数台帳で通常文字枠を消費しない。同条件の音声を再利用。NARRATION_PREVIEW_LIMIT（1日・アカウント単位、JST）で上限を設定。stgの仮既定値は5回、本番既定値は0回。公開回数決定後に設定する。プロバイダー入力の日次原価上限は試聴にも適用。
- 既存のD1予約・確定トリガーを別periodで利用し、DBマイグレーション不要。Worker変更なし。Pagesのみで反映。
- 旧設定・採用音声は残し、旧区間のスナップショットを保存して書き出しを維持。文単位への移行は明示的な一話再生成。本文変更後も保存済み音声を確認付きで書き出せる。
- 保存は引き続き端末・アカウントごと。端末間の同期は今回対象外。
- ブラウザ検証は固定MP3によるAPI代替。実Fish呼び出し・有料モデル解禁は行わない。追加の声と既成サンプル整備、実演技品質評価は公開前項目。


### 注釈対応：本文を選んで声を付けるUI
話別の明示モードは任意の episodes[episodeId].mode、範囲のスタイルは cues[].style に保存する。旧レコードは明示モードがない限り従来の声解決を維持し、初めてモードを選択した時点で既存の声を本文範囲の指定へ移す。新しい複数声モードでは用語集・演出譜の話者から声を推定しない。元の音声・旧設定は削除しない。

E2Eは固定音声と架空の2声を使い、長文・長いタイトル・速さと間の配置・声指定の保存・モード往復・比較採用・MP3保存・390〜1440pxの横はみ出しを確認する。実APIの生成品質・声の種類の評価とは区別する。声カタログ、サンプルURL、無料枠・公開フラグは今回変更しない。


### 既定の読点補正と選択操作
新規のVoiceSegmentは、方向指定が空で読点を含む場合だけ任意の commaPause: short を持つ。APIのZod検証で保持し、fingerprintにも含めるため、補正前のキャッシュを誤って新しい読みとして再利用しない。既存セグメント・採用音声は変更せず、旧リクエストは従来の入力で処理する。providerText はAPIのバイト予算計算と実送信の両方で使用する。利用者の文字数は原文から数える。

画面の選択にはネイティブbuttonを使わず、キーボード操作を持つ選択可能なspanを使う（buttonはブラウザの複数ブロック選択を妨げる）。E2Eで追加クリック・個別解除・前後方向の実ドラッグ・読み仮名の再表示・通し再生と比較の位置分離を確認する。音声品質は固定音声のE2Eでは判定できないため、実モデルの聴感確認とは区別する。


### 状態表示と連続選択（2026-11-08）
本文のdata-narration-stateと文字ラベルで未生成・生成済み・比較待ち・変更・生成中・問題を表し、選択は独立した青で示す。凡例は原稿上部に固定。通常の保存指示は本文横のリンクで再編集し、本文に対応しない指示や旧設定だけを別一覧へ残す。サウンドノベルのsceneBreakは新しい朗読に適用せず、legacy解決だけ従来値を保持する。

E2Eは場面区切り付きの長文、連続クリック・ドラッグ、語句指定のリンクからの再編集、複数声モードの範囲カード、狭いselect内の最長ラベルの幅、生成済み／比較待ち／選択の色の区別を確認する。実カタログがShioriのみの場合、別の声での出し分けにはカタログ追加が必要。


## 2026-11-08 初回の部分生成と段落での操作

- 元の採用音声がない部分は、生成・音声保存の成功時に自動反映する。比較と「こちらを採用」は既存音声の再生成だけに表示する。初回と再生成が混在する選択でも、初回部分は自動反映、既存部分だけを候補として残す。
- 初回は「選択部分を生成」。反映後は「選択部分を聴く」で確認できる。再生成には文字数を消費し、採用・試聴には追加の生成を伴わない。
- 旧UIで残った初回の比較候補も、明示的な部分生成スナップショットがあり、採用音声がない場合は保存確認後に反映する。冒頭試聴や単なるキャッシュ音声は対象外。
- 画面のクリック選択は段落単位。離れた段落をクリックすると途中も含めた連続範囲になる。同じ段落を再クリックすると解除。文字ドラッグによる語句・段落をまたいだ選択は維持する。
- 状態タグは段落ごと・同じ状態ごとに1つにまとめる。部分ごとの色は維持し、段落内に生成済みと未生成が混在しても判別できる。自由記述の指示は選択範囲に保存する。
- 内部の生成単位（主に句点・閉じかっこ）は変えない。既存音声・指示・生成費用の単位を保つ。段落表示への変更は演技指示への音声モデルの追従精度や読点の間を保証するものではない。分割レベル切り替えは追加しない。
