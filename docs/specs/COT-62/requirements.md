# 要件定義 — COT-62 推敲画面に作品ごとの「例外」と「表記の好み」を足し、選んだ結果から決まりを提案する

## 背景と目的

推敲画面（COT-40）では、「このまま」は指摘ごと・話ごとにしか効かない。そのため、作者がわざと使っている言葉が、話をまたぐたびに指摘に出続ける。表記ゆれも、両方の書き方が指摘に出るだけで、作品としての書き方を決めておけない。作品ごとの決まり（例外と表記の好み）を持てるようにし、作者が選んだ結果から決まりを提案して、推敲の繰り返しを減らす。辞書という概念は利用者に見せない（2026-10-20 ユーザー決定）。

## 機能要件

### FR-1 例外（この作品ではこの言葉を指摘しない）

- 例外を作れる項目と、例外の単位：
  - ら抜き言葉：指摘された言葉（「見れる」）
  - 同じ語の連続：指摘された文字列（「言った言った」）
  - 表記ゆれ：書き方の組（子供／子ども）。「書き分けを許す」と呼ぶ。組のどの書き方も指摘しない
- 例外を作れない項目：
  - 字下げ・閉じ括弧の前の句読点・！？の後の空白・三点リーダー・ダッシュ・半角の約物。「確認する項目」で項目ごと止められる
  - 一文の中の同じ助詞。指摘が文に結び付き、言葉に結び付かない
- 入口：未判断の指摘のカードに置く
  - ら抜き言葉・同じ語の連続：「この作品では指摘しない」
  - 表記ゆれ：「この作品の決まりにする」のメニューの中の「書き分けを許す」
- 受け入れ条件
  - Given 第1話と第2話に「見れる」がある / When 第1話の「見れる」のカードで「この作品では指摘しない」 / Then 第1話・第2話とも、「見れる」のら抜き言葉の指摘が一覧にも本文の印にも出ない。「見られる」など別の言葉の指摘は出る
  - Given 「子供」と「子ども」が混ざった作品 / When 表記ゆれのカードで「書き分けを許す」 / Then 子供・子どもの表記ゆれの指摘が全話で出ない。ほかの組（出来る／できる）は出る
  - Given ら抜き言葉の「見れる」を例外にした / When 同じ話に新しく「見れる」を書く / Then 指摘は出ない
  - Given 例外にした言葉に、前から「このまま」や「直す」の判断がある / When 例外を作る / Then 判断の記録は消さない。「直す」と決めた箇所は、本文の画面の「直す箇所」に残る（直すか「外す」まで）
  - Given 一文の中の同じ助詞・字下げなどのカード / When カードを見る / Then 「この作品では指摘しない」は出ない

### FR-2 表記の好み（この作品の表記）

- 表記ゆれのカードの「この作品の決まりにする」のメニューに、組の書き方を1つずつ「◯◯にそろえる」として並べる
  - 辞書の組：出来る／できる、事／こと など
  - 数の書き方：「3人／三人」は「算用数字にそろえる」「漢数字にそろえる」。助数詞ごとに決まる
  - 自動で見つけた組
- 好みを決めた組では、好みの書き方は指摘しない。ほかの書き方は、作品に好みの書き方が1つも無くても指摘する
  - 説明：「「子供」は、この作品の表記「子ども」と違います。」
  - 数：「「3人」は、この作品の数の書き方（漢数字）と違います。」
- 同じ組に例外（書き分けを許す）と表記の好みは同時に持たない。後から決めたほうに置き換える
- 受け入れ条件
  - Given 子供 3件・子ども 2件の作品 / When 「子どもにそろえる」 / Then 子どもの指摘が消え、子供の3件だけが新しい説明で残る
  - Given 「子どもにそろえる」と決めた作品で、子どもが本文から無くなった / When 推敲画面を開く / Then 残った子供は引き続き指摘される
  - Given 「3人」と「三人」が混ざっている / When 「漢数字にそろえる」 / Then 「人」の算用数字だけが指摘され、「3日」など別の助数詞は今までどおり
  - Given 自動の表記ゆれ（例：行う／行なう） / When 「行うにそろえる」 / Then 行なうだけが指摘される
  - Given 「子どもにそろえる」にした組（好みに合わない「子供」のカードがある） / When そのカードのメニューで「書き分けを許す」 / Then 好みが消え、例外に置き換わる（一覧も1件のまま）
  - Given 「書き分けを許す」にした組（その組のカードは出ない） / When 一覧で「戻す」→ 出てきたカードのメニューで「子どもにそろえる」 / Then 表記の好みになる（例外から好みへの切り替えは、この2手で行う。置き換えの規則そのものは core のテストで固定する）
- くわしい確認の準備ができていても、好みで隠した書き方が自動の表記ゆれとして出直さない（辞書の組と自動の組が同じ語を見ている場合。例：子供／子ども）

### FR-3 決まりの一覧と取り消し

- 推敲画面の見出しの「確認する項目」の隣に「この作品の決まり（N）」を置く。押すと、見出しの下に一覧の欄が開く（「確認する項目」と同じ開閉。両方を同時に開いてよい）
- 一覧の欄は高さに上限を持ち、行が多いときは欄の中でスクロールする（本文と右の欄を押しつぶさない）
- 一覧の1行：決まりの中身と「戻す」
  - 例外：「見れる」— ら抜き言葉は指摘しない
  - 書き分けを許す：「子供・子ども」— 書き分けを許す
  - 表記の好み：「子ども」にそろえる（子供・子ども）
- 0件のとき：ボタンは「この作品の決まり」（数を付けない）。欄には「決まりはまだありません。指摘のカードから作れます。」
- 受け入れ条件
  - Given 例外1件・表記の好み1件 / When 「この作品の決まり（2）」を押す / Then 2行が出る
  - Given 一覧が出ている / When 「見れる」の「戻す」 / Then その行が消え、「見れる」の指摘が全話で出るようになる
  - Given 決まりが1件だけ / When 「戻す」 / Then 欄は開いたまま、0件の案内に替わり、ボタンの数が消える
  - Given キーボードで操作している / When 「戻す」で行が消える / Then フォーカスは次の行の「戻す」へ移る（無ければ前の行、どちらも無ければ欄の見出し）
  - Given 決まりが30件・「提案しない言葉」も20件・「確認する項目」も開いている / When 「この作品の決まり」を開く / Then 欄の中身（決まりの一覧と提案しない言葉）は上限の高さで止まり、中でスクロールできる。本文と右の欄は見えたまま

### FR-4 選んだ結果から決まりを提案する

- 例外の提案：
  - 対象は、ら抜き言葉と同じ語の連続の同じ言葉
  - 作品の全話で「このまま」にした回数が3回以上になったら提案する
  - 文言：「「見れる」を3回このままにしました。この作品では指摘しないようにしますか？」
  - ボタン：「指摘しない」「提案しない」
- 表記の好みの提案：
  - 表記ゆれの同じ組の同じ書き方を、作品の全話で「直す」にした回数が2回以上になったら提案する
  - 「同じ書き方」は、判断に残った文字列を組の書き方に当て直して数える。辞書の組の文字列には前後の文字が入る（「た事が」「る事に」はどちらも「事」）。数は「3人」「5人」をどちらも「人」の算用数字として数える
  - 組の書き方が2つなら、そろえる先はもう一方
  - 文言（語）：「「子供」を2回直すと決めました。この作品は「子ども」にそろえますか？」
  - 文言（数）：「算用数字の「人」を2回直すと決めました。この作品の「人」は漢数字にそろえますか？」
  - ボタン：「子どもにそろえる」（数は「漢数字にそろえる」）「提案しない」
  - 組の書き方が3つ以上なら、そろえる先を選べるメニューを出す
- 出し方：
  - 推敲画面の「指摘」タブで「未判断」を選んでいるとき、絞り込みのチップと一覧の間（一覧のスクロールの外）に1件だけ出す
  - 直前に判断した指摘が線を超えたときだけ出す（直前の判断が対象外なら出さない）
  - すでに決まりがある言葉・組や、「提案しない」にした提案は出さない
- 「提案しない」は作品ごとに覚え、同期する。戻すまで同じ提案は出ない。戻すときは「この作品の決まり」の欄の下の「提案しない言葉（N）」から1件ずつ戻す
- 受け入れ条件
  - Given 第1話で「見れる」を2回、第2話で1回「このまま」にした / When 3回目を選んだ直後 / Then 未判断の一覧の上に、例外の提案が出る
  - Given 提案が出ている / When 「指摘しない」 / Then 例外ができ、提案が消え、「見れる」の指摘が全話で消える
  - Given 提案が出ている / When 「提案しない」 / Then 提案が消え、その後「見れる」をこのままにしても同じ提案は出ない。「提案しない言葉（1）」に入り、戻すと再び提案されうる
  - Given 未判断が1件だけ残っていて、それを「このまま」にすると3回目になる / When 「このまま」 / Then 一覧は「未判断の指摘はありません」になり、その上に提案が出る
  - Given 一覧の下のほうのカードで3回目の「このまま」を選んだ / When 選んだ直後 / Then 提案は一覧のスクロールの外（チップの下）に出て、スクロールしなくても見える
  - Given 「事」の書き方を、文字列「た事が」と「る事に」で1回ずつ直すと決めた / When 2回目を選んだ直後 / Then 「こと」にそろえる提案が出る
  - Given 「3人」と「5人」を1回ずつ直すと決めた / When 2回目を選んだ直後 / Then 「人」の漢数字にそろえる提案が出る
  - Given 「子供」を2回「直す」にした（組は子供／子ども） / When 2回目を選んだ直後 / Then 「子どもにそろえる」の提案が出る
  - Given 「このまま」にした回数が2回 / When 一覧を見る / Then 提案は出ない
  - Given 「未判断」以外の絞り込み（直す・このまま）を見ている / When 一覧を見る / Then 提案は出ない

### FR-5 保存・同期・バックアップ

- 決まり（例外・表記の好み・提案しない言葉）を作品ごとに1件の記録として保存する
- 作品と一緒に同期・バックアップする（推敲の判断・外した語と同じ扱い）
- 取り込みの件数に「推敲の決まり：N作品」を足す
- 作品の完全削除（ゴミ箱の purge・30日の期限切れ・ゴミ箱を空にする）で一緒に消す。ゴミ箱へ移すだけでは消さない
- 受け入れ条件
  - Given 決まりを作った / When 再読み込み / Then 決まりが残っている
  - Given 有料の同期が動いている / When 別の端末で同期 / Then 決まりが同じになる
  - Given 決まりの記録が壊れていて読めない / When 推敲画面を開く / Then 決まりなしとして指摘を出し、壊れた記録で他の端末の記録を上書きしない
  - Given 旧バックアップ（決まりの欄が無い） / When 取り込む / Then 決まりなしとして読める

### FR-6 ヘルプ

- 「推敲する」の説明に次を足す
  - 「用語集に登録した名前は、推敲でもひとつの言葉として扱います。」
  - 決まりの説明：「わざと使っている言葉は「この作品では指摘しない」、表記ゆれは「◯◯にそろえる」で、作品の決まりにできます。決まりは「この作品の決まり」から戻せます。」

### FR-7 推敲画面の「辞書」の文言を言い換える

- くわしい確認の準備中の表示（`proofread-view.tsx:481`）「（辞書の読み込みは初回のみ）」→「（初回だけ時間がかかります）」
- 進み具合の読み上げ名（`:487`）「辞書の読み込み」→「くわしい確認の準備」
- 受け入れ条件
  - Given くわしい確認の準備中（初回） / When 推敲画面を開く / Then 推敲画面の文字と読み上げ名に「辞書」が無い（ヘルプのライセンス表記は推敲画面の外なので対象外）

## 非機能要件

- **NFR-1 性能**：決まりを当てる処理は、指摘を作る処理に 10ms 以上足さない（1話1万字・決まり100件・Node）
- **NFR-2 プライバシー**：決まりは端末に置き、有料の同期とクラウドバックアップに乗る。AI 連携用のライブスナップショット（バックアップと同じ直列化・暗号化）にも載るが、MCP のツールは決まりを読み書きしない（AI の変更を取り込んだ後も残る）。publish バンドル・grove には出さない
- **NFR-3 文言**：新しい文言に「辞書」を使わない（推敲画面に今ある2か所は FR-7 で言い換える）
- **NFR-4 アクセシビリティ**：
  - カードのボタンと一覧の「戻す」は、言葉を含めて読み上げる（「見れるをこの作品では指摘しない」「見れるの決まりを戻す」）
  - 提案はスクリーンリーダーに知らせる。`role="status"` の入れ物を常に置き、中身だけを入れ替える（後から要素ごと差し込むと読み上げられないことがあるため）

## 後方互換性チェック（CLAUDE.md の各項目）

- **スキーマ**：
  - 作品・話・用語集・推敲の判断・外した語のスキーマは変えない
  - 決まりは新しい kv レコード（作品ごとに1件）に置く
  - 新設なので、核の欄（`workId`・`updatedAt`）は必須にする。中の配列は `.optional().default([])` にする
  - バックアップの欄は `.optional().default([])` にし、壊れた要素だけを捨てる（COT-59 と同じ）
- **旧形式の読み出し**：新しいレコードは今回から。無ければ決まりなし
- **表示先の維持**：
  - 既存の指摘カード・「同じ指摘をすべてこのまま」・「確認する項目」は残す
  - 例外で消えるのは、作者が決めた指摘だけ
- **部分更新で他の欄を落とさない**：決まりの更新は、その記録の中の1件だけを足す・消す
- **削除は明示操作だけ**：
  - 決まりを消すのは「戻す」と作品の完全削除だけ
  - 例外を作っても、推敲の判断の記録は消さない
- **同期と復元で決まりが失われる場合**（受け入れる。COT-59 の外した語と同じ）：
  - 2台で同時に別々の決まりを作ると、LWW で負けた側の決まりは消える。推敲の種類は synclost に退避しない（`src/ui/sync/sync-service.ts:449-450`）
  - 決まりの欄を持たない旧版のバックアップやライブを復元・取り込みすると、決まりは空に置き換わる（`replaceAll`）
  - 受け入れる理由：決まりは作者の手間を省く設定で、原稿は失わない。失っても、カードや提案からすぐに作り直せる
- **配信契約（publish・同期 API・MCP）**：
  - publish バンドルには出さない。MCP のツールは読み書きしない（ライブスナップショットには載り、AI の変更を取り込んだ後も残る）
  - 同期は外した語と同じ相乗りに、新しい接頭辞を足す。サーバの改修は要らない。旧版のクライアントは知らない接頭辞を読み飛ばす（COT-59 と同じ）

## 仮定と未決事項

- **仮定**：
  - 提案の線（このまま3回・直す2回）は初期値。使ってみて変える
  - 例外を作れる項目は、言葉に結び付く項目（ら抜き言葉・同じ語の連続・表記ゆれ）だけ。一文の中の同じ助詞は、文に結び付くので対象外
  - 決まりの一覧は、作品をまたいで共有しない（作品ごと）
- **未決**：なし

## 対象外

- 作者の辞書（解析用の語の登録）
- 用語集の「作者だけ（読者に見せない）」の印
- 用語集の読みでルビを振る機能
- 全作品で共有する決まり（COT-59 の「全作品で外す」を含む）
- 決まりに沿った本文の自動の書き換え（「子供」を一括で「子ども」に替える）
- MCP から決まりを読み書きすること
- スマホでの推敲画面
