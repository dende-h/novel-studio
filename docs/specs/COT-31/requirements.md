# 要件定義 COT-31 テキストの取り込み（.txt を読み込んで話に分ける）

## 背景と目的

他のツールや「小説家になろう」「カクヨム」で書いてきた人が乗り換えるとき、いまは話を1つずつコピペするしかない。取り込めるのはコトノハの JSON バックアップだけで（`src/ui/components/ImportDialog/import-dialog.tsx:114-125` の accept が `application/json,.json`）、`docs/requirement/99-open-questions.md:18` にも「外部からのインポート」が未決で残っている。
.txt ファイルや貼り付けたテキストを読み込み、「第1話」のような見出し行で話に分け、分かれ方を確かめてから新しい作品として作れるようにして、乗り換えの手間を減らす。

## 機能要件

### FR-1 テキストファイルの読み込み（複数・文字コード自動判別）
- 受け入れ条件
  - Given 作品一覧の「データ管理」メニュー / When 「テキストから作品を作る」を選ぶ / Then 取り込みダイアログが開き、ファイル選択とドロップ領域と貼り付け欄がある
  - Given ダイアログ / When UTF-8 の .txt を3つ選ぶ / Then 3ファイルがファイル名の自然順（`2.txt` が `10.txt` より前）で一覧に並び、各ファイルに判別した文字コード（UTF-8 / Shift_JIS）が表示される
  - Given Shift_JIS で保存された .txt / When 選ぶ / Then 文字化けせずプレビューに本文が出る
  - Given CRLF 改行・BOM 付きの .txt / When 選ぶ / Then 本文の各行末に `\r` が残らず、先頭に BOM が残らない（作成後の本文テキストで確認）
  - Given UTF-8 でも Shift_JIS でも読めないファイル（画像のリネーム等） / When 選ぶ / Then そのファイルだけ「読み込めませんでした。UTF-8 か Shift_JIS のテキストファイルを選んでください」と出て、他のファイルは残る。判定は「UTF-8（fatal）で復号できればそれ、できなければ Shift_JIS で復号。どちらの結果も、置換文字 U+FFFD か、タブ・改行以外の制御文字（U+0000〜U+0008, U+000B, U+000C, U+000E〜U+001F）が1文字でも含まれていたら失敗」。Shift_JIS デコーダはほぼ任意のバイト列を黙って文字にするため、この後段の検査が必須
  - Given 読み込んだテキストの合計が 20MB を超える / When ファイルを足す・貼る / Then 「合計 20MB までのテキストを取り込めます」と出て追加されない（入力側の足切り。貼り付けも同じ上限に含む）
  - Given 作成時に組み立てた Work の JSON（UTF-8 バイト数）が 20MB を超える / When 「作品を作る」 / Then 保存せず「本文が大きすぎます。ファイルを分けて取り込んでください」と出す。保存形は行ごとにブロック化され生テキストの 2〜3 倍に膨らむため、同期の1作品上限 25MB（`functions/api/sync/work.ts:26`、JSON 平文で判定）はこの値で守る
  - 受け付ける拡張子は `.txt` だけ。ファイル選択・ドロップのどちらの経路でも拡張子で判定し、それ以外は追加せず「.txt のテキストファイルを選んでください」と出す
  - Given すでに一覧にあるのと同じ名前のファイル / When 追加する / Then 追加せず「同じ名前のファイルはすでにあります」と出す（手直しのキーに使うファイル名を一意に保つため）

### FR-2 貼り付けテキストの読み込み
- 受け入れ条件
  - Given ダイアログ / When 「貼り付け」に切り替えて本文を貼る / Then 入力が止まった時点（300ms 以内）でプレビューが更新される
  - Given 貼り付けとファイルの両方 / Then 同時には使わない。切り替えると他方の入力は保持したまま、プレビューは今見えている側の内容だけから作る

### FR-3 見出し行による分割
- 分け方（既定は「見出し行で分ける」）
  - 見出し行で分ける：ファイルごとに見出し行で分ける。見出し行はその話のタイトルになり、本文からは除く（「見出し行を本文にも残す」をオンにすると残る）。先頭の見出しより前に本文があれば、それも1話として残す（タイトルはファイル名。貼り付けなら「序」）。見出しが1つもないファイルは1話（タイトルはファイル名。貼り付けなら「第1話」）
  - ファイルごとに1話：ファイル名（拡張子なし）をタイトルにする。貼り付けでは選べない
  - 分けない：全ファイルを連結して1話にする（タイトルは作品タイトルと同じ）
- 見出し行とみなす規則（行頭・行末の空白を除いた1行が 40 文字以内で、次のいずれか）
  1. `第N話／章／節／部／回／幕／夜／日`（N は半角・全角数字か漢数字）で始まる行。続きがあれば副題として同じタイトルに含める（例「第1話　出会い」→ タイトル「第1話　出会い」）
  2. `プロローグ／エピローグ／序章／終章／幕間／間章／後日談／まえがき／あとがき` で始まる行
  3. 数字だけ、または数字＋`.．、:：` ＋空白で始まる短い行（例「1. 出会い」「１　出会い」）
  4. Markdown 見出し（`#`〜`###` ＋空白）
  5. `【…】` だけの行、`■` で始まる行
- 区切り行（既定オフ、「罫線だけの行でも分ける」で有効）：空白を除いて `-`・`=`・`ー`・`―`・`─`・`━`・`＊`・`*`・`※`・`#`・`＃` だけが3文字以上並ぶ行。区切り行自体は本文に残さず、分かれた話のタイトルは「第N話」（通し番号）
- 受け入れ条件
  - Given 「第1話　出会い\n本文A\n\n第2話\n本文B」 / When 既定の分け方 / Then 2話。タイトル「第1話　出会い」「第2話」、本文はそれぞれ「本文A」「本文B」（末尾の空行は落とす）
  - Given 「前書き\n\n第1話\n本文」 / Then 2話。1話目のタイトルはファイル名（貼り付けなら「序」）で本文「前書き」
  - Given 見出しのない本文 / Then 1話。「見出しが見つからなかったので、1話にまとめました」と案内が出る
  - Given 本文の途中に「＊＊＊」の場面転換がある / When 「罫線だけの行でも分ける」がオフ / Then そこで分かれない。オンにすると分かれる
  - Given 「吾輩は第1話を読んだ。」のように行の途中にある語 / Then 見出しにしない
  - Given 本文中の「第１話」（全角数字）・「第一話」（漢数字） / Then どちらも見出しになる
  - Given 2ファイル（それぞれ見出し付き） / Then ファイル順に、ファイルごとの分割結果が連なる

### FR-4 プレビュー
- 受け入れ条件
  - Given 読み込み済み / Then 右側（モバイルは次の段）に「N 話に分かれます・合計 M 字」と、話ごとに「タイトル・冒頭の2行・字数・分けた理由（見出し／区切り／ファイル／見出しの前）」が並ぶ
  - Given 分け方や「罫線だけの行でも分ける」を変える / Then プレビューが即座に更新される
  - Given 何も読み込んでいない / Then 「テキストを読み込むと、ここに話の分かれ方が出ます」と出る

### FR-5 プレビュー上での手直し
- 受け入れ条件
  - Given プレビューの話 / When タイトル欄を書き換える / Then 作成される話のタイトルに反映される。空にしたまま作ると「第N話」になる
  - Given 2話目以降 / When 「前の話とつなげる」 / Then その話の本文が前の話の末尾に（見出し行を本文に残す設定なら見出し行も）つながり、話数が1減る。他の話に入れたタイトルの手直しはそのまま残る（手直しは話の位置番号ではなく「元ファイル名＋開始行」で保持する）。分け方の設定を変えると手直しは解除される（設定変更で分割結果を作り直すため。プレビューに結果が即座に見えるので確認ダイアログは出さない）

### FR-6 作品の作成と遷移
- 受け入れ条件
  - Given プレビューに1話以上・作品タイトルが空でない / When 「作品を作る」 / Then 新しい Work が1つ保存され、作品一覧に出る。著者は既定でプロフィールのペンネーム（`src/ui/store/editorStore.ts:277`）。既存作品は変わらない
  - Given 作品タイトルが空 / Then 「作品を作る」は押せない。既定値はファイルなら先頭ファイル名（拡張子なし）、貼り付けなら「取り込んだ作品」
  - Given 作成後 / Then ダイアログに「N 話で「タイトル」を作りました」と出て、「執筆を始める」で執筆画面（`#/write`）へ、「閉じる」で一覧に戻る
  - Given 作成中（大きな本文） / Then 「作品を作る」は二重に押せない
  - Given ゲスト（未ログイン）・無料会員 / Then 同じように使える（取り込みに会員判定はない。`src/ui/Root.tsx:437-480` で Library に認証ガードなし）

### FR-7 記法の扱い
- 受け入れ条件
  - Given 本文に `｜吾輩《わがはい》` `漢字《かんじ》` `《《強調》》` / When 作成 / Then 執筆画面の本文に同じ文字列が出る（`parseEpisodeBody` → `blocksToNotation` の往復で変わらない）
  - Given なろう式の傍点 `｜字《・》` / Then ルビ「・」として入る（傍点への変換はしない。仕様として明記）
  - Given 全角スペースの字下げ / Then そのまま残る

## 非機能要件

- 性能：上限いっぱい（生テキスト 20MB・500話程度）でも、設定変更からプレビュー更新まで 1 秒以内（分割は行単位の正規表現のみ・パース（`parseEpisodeBody`）と JSON サイズ判定は作成時に1回）。貼り付け欄の変更は 300ms デバウンス
- オフライン：ブラウザ内で完結する。通信しない
- アクセシビリティ：ファイル一覧とプレビューの更新は `aria-live="polite"` で読み上げる。ドロップ領域はキーボードで「ファイルを選択」できる
- プライバシー：取り込んだ本文は端末内（IndexedDB）にだけ保存される。公開（コトノハ-grove-）・同期・バックアップは既存作品と同じ扱いで、取り込み自体は何も送らない

## 後方互換性チェック（CLAUDE.md の各項目）

- スキーマ：変更なし。作る Work は既存 `WorkSchema` の範囲（`id/title/episodes/author?/updatedAt`）。`format` は付けない（小説）
- 旧形式の読み出し：該当なし（新しいレコードを書くだけ）
- 表示先の維持：該当なし（欄の移動・統合なし）
- 部分更新で他の欄を落とさない：該当なし（新規作成のみ。`importWorks` は id 単位の上書きだが、新しい `crypto.randomUUID()` の id なので既存作品に当たらない）
- 削除は明示操作だけ：該当なし。取り込みで何も消さない。失敗時も既存作品に触れない
- 配信契約（publish・同期 API・MCP）：変更なし。1作品 25MB の同期上限（`functions/api/sync/work.ts:26`。JSON 平文のサイズで判定）に収まるよう、組み立てた Work の JSON バイト数が 20MB を超える取り込みは保存しない（FR-1）。生テキストではなく保存形で測るのは、ブロック化で 2〜3 倍に膨らむため

## 仮定と未決事項

- 仮定：入口は作品一覧の「データ管理」メニュー。既存の「バックアップを取り込み」とは別の項目・別のダイアログにする（JSON と .txt を1つのダイアログに混ぜると、既存ダイアログの文言「JSON を選んでください」と役割がぶつかる）
- 仮定：見出し行は本文から除いてタイトルにする（既定）。残したい人のためにトグルを置く
- 仮定：先頭の見出しより前の本文は捨てずに1話として残す（利用者の文章を暗黙に消さない）
- 仮定：複数ファイルはファイル名の自然順。並べ替え UI は作らない
- 仮定：Shift_JIS 判別は「UTF-8 として厳密に復号できなければ Shift_JIS」の2段階。EUC-JP・UTF-16 は対象外（読めなければエラー文言）
- 未決：なし（レビューで仮定を検証する）

## 対象外

- 既存作品への話の追加取り込み
- 脚本形式での取り込み
- ファイル順の手動並べ替え
- `.md` など `.txt` 以外の拡張子（必要なら `.txt` に変えて取り込める）
- EUC-JP・UTF-16 のテキスト
- なろう式傍点 `｜字《・》` の傍点への変換
- 話の前書き・後書き（なろうの欄）の分離
