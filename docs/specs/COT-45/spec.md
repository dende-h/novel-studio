# 集中モードとタイプライタースクロール 仕様書（COT-45）

- 要件: COT-70 ／ 設計: COT-71 ／ プロトタイプ: `docs/specs/COT-45/prototype.html`（ローカル）
- 状態: 独立レビュー通過（Round 1、blocker/major 0）

## 何を作るか
本文以外を隠す集中モードと、入力行を中央に保つ切替を作る。ゲストを含めて誰でも使える。原稿の保存方式は維持する。

## 振る舞い
- FR-1: 話のツールバーの「集中モード」またはAlt+Shift+Fで出入りする。周辺のパネル・プレビュー・記法・文字数・脚本チェックを隠す。本文、終了操作、追従切替、全画面、保存状態を残す。終了で元の表示に戻し、textarea・選択・draft・undoを保持する。IME中、repeat、ダイアログ中、別画面ではキーを無効にする。Escapeは候補、脚本、ブラウザの既存操作に譲る。
- FR-2: 全画面は集中時のボタンから明示的に開始する。対応しない環境では入口を隠す。拒否しても集中と本文を保持する。外部終了は表示に反映し、本機能が開始した全画面だけを集中終了・離脱時に解除する。F11を管理しない。
- FR-3: 「入力行を中央に保つ」は集中と独立。入力確定・キャレット移動・折返し・幅や文字サイズ変更で、行中心を可視本文中心±1行高に合わせる。先頭末尾と空本文は表示paddingで対応する。IME・範囲選択・readOnly・非フォーカスでは移動しない。手動スクロールは次の入力/キャレット操作まで維持する。
- FR-4: 既存dirty/statusに従う保存状態を小さく常設し、スマホでも文字を残す。既存保存エラー通知を隠さない。
- FR-5: 初期値は両方オフ。端末にそれぞれ記憶し、全画面は記憶しない。通常の記法バーは集中時に隠し、@候補は一時表示する。スマホでは可視領域から操作列・候補バーを除いて中央を決める。ゲスト・無料・有料・オフラインで同じ挙動。

## 追加・変更仕様（利用画面のレビュー反映）
- FR-6: 通常表示の集中・追従ボタンはダッシュの右に置く。選択時の緑背景を使わない。
- FR-7: 集中時は右上の「表示」から記法・ショートカットと操作ボタンを別々に表示/非表示にできる。設定は端末に記憶する。操作を隠しても「表示」メニューと保存状態を残し、メニューから復帰・終了できる。
- FR-8: 本文の入力欄を横書き/縦書きに切り替えられる。プレビューとは独立し、切替で同じtextarea、本文、選択、undoを維持する。縦書きでは右から左に列が進み、追従は入力列を左右の中央に保つ。通常のホイール操作で列方向へ読み返せる。
- FR-9: 集中時は横幅の上限をなくし、プレビューを隠した全領域を使う。スクロールバーは画面端の細い淡色表示にする。
- 詳細と確認画像は `refinement.md`。

## 画面
`prototype.html`でPCと幅393pxの現状/変更後を比較できる。現状画像は`screens/writer-desktop.png`と`writer-mobile.png`。集中時は本文を全幅で表示し、PC左右36px、スマホ24px。最小操作列は常設し、スマホは最大2行。ダークは既存トークンを使う。

## 実装の骨格
| ファイル | 責務 |
|---|---|
| App.tsx / AppShell | 集中表示の適用条件、周辺の非表示、元の表示状態と同じtextareaの保持 |
| EditorPane / 新規use-typewriter-scroll | IME・選択の調停、rAFで計測、textareaのscrollTopのみ補正 |
| TopAppBar / 新規SaveStatus | 現行保存表示を共通化 |
| 新規use-writing-mode | 端末設定、ショートカット、全画面の状態と所有管理 |
| index.css / CODEMAP | 余白と幅、構成の記録 |

詳細のパス・変更起点・提案シグネチャはdesign.md。新規依存なし。既存useLocalFlagは一方向のため変更しない。新設定キーはns-writing-focus/ns-writing-typewriter（'1'/'0'）。Work/Episodeなどのスキーマは変更しない。

## テスト
フックで保存不可・キー除外条件・全画面拒否/外部終了を固定する。UIで同じtextarea、dirtyと保存状態、候補、readOnlyを確認する。実寸e2eで中央位置、手動スクロール、出入り後のundo、表示復帰、reload後の設定と本文を検証する。
iOS/Android実機でソフトキーボード・IME・回転を検証し、10万字の計測負荷も記録する。typecheck/test/lint/buildと対象e2eを通す。

## 守ること
未保存draftを切替で作り直さない。周辺の既存データは復帰できる形で隠す。設定は同期・バックアップ・publish・MCPへ載せない。保存経路はsetDraftと既存autosaveを使う。

## やらないこと
自動全画面、OS設定、行強調、会員制限や原稿形式の変更。実機検証はアプリ実装時に行う。
