# COT-45 実装・検証メモ

## 実装した動作
- 集中モードとAlt+Shift+F。IME変換中・キーリピート・ダイアログ中は切り替えない。
- 本文textareaを維持したまま周辺の表示を切り替える。選択、未保存本文、undo、元の表示面とパネルを保持。検索の入力や脚本チェックの開閉もDOMを保って復帰する。
- 集中時の保存状態と終了操作を常設。全画面は明示操作で開始し、外部終了・集中終了・遅延完了を扱う。
- 入力行の中央追従。空・先頭・末尾・折返し・文字サイズ・幅・候補バーに対応。IME・範囲選択中・readOnlyでは中央へ動かさない。手動スクロールは次の本文操作まで維持。
- 端末設定はns-writing-focus/ns-writing-typewriter（1/0）。既存useLocalFlagの契約、作品データ、同期契約は変更なし。
- スマホはvisualViewportへレイアウトを合わせ、集中時は通常の記法バーを隠す。

## 設計から具体化した点
- SaveStateの定義はSaveStatusへ移設し、TopAppBarから再exportして既存importを維持した。
- 操作列はWritingModeControlsを通常/集中表示で共有し、集中時の操作列は画面のErrorBoundaryの外に置いた。
- 座標取得にcreateCaretMeasurerを追加。段落ごとのDOMを再利用し、変わった段落だけを再組版する。単発のgetCaretCoordinatesは既存動作のまま。
- 端末の文字サイズ・テーマ変更を監視し、追従を再計測する。計測用DOM、observer、rAFは追従オフ/unmountで破棄する。

## 10万字の計測
Chromium headless / 幅800pxのtextarea、100,000字（短い段落を改行で区切る）に25回入力。
- 初期の単発計測器：同じ原稿内の位置を25回計測してp95 70.7ms。
- 再利用ミラー：同じ原稿内の位置変更はp95 5.9ms。初回の段落DOM準備を含む最大217.5ms。
- ネイティブ入力を25回行い、各入力の描画後に再利用ミラーの座標取得を計測：p95/max 2.4ms。
- 原稿全体のvalueを同期的に25回差し替えて直後に計測すると、textarea本体の再組版待ちを含みp95 132.6ms。上の2.4msは入力から描画までの総遅延を示す値ではない。
初回準備と極端な長段落では待ちが生じうる。実機の入力遅延は未測定。
