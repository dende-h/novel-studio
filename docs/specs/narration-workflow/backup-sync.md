# 朗読のバックアップと端末間同期

2026-11-09。対象は作成中の朗読の引き継ぎ。公開投稿は含まない。

## 保存する内容

現在のアカウントの作品ごとに、声・スタイル・速度・間・読み辞書・演技指示、
生成区間のスナップショット、採用音声、比較待ち、取り消し用の対応、過去のテイク、
進行中の操作とジョブID、送信結果を確認中のリクエストIDを保存する。
利用枠と消費文字数はサーバが正本なのでバックアップから巻き戻さない。

音声は内容のSHA-256で識別し、同一アカウント内では複数のバックアップから同じ実体を参照する。
編集状態には音声の参照だけを入れる。MP3のbase64を既存JSONに埋め込まない。

## ファイル

既存の全体バックアップの書き出しをZIPにする。backup.jsonと音声の実体を同梱する。
取り込みは旧JSONも受け付ける。朗読欄がない旧バックアップは既存の朗読を消さない。
新形式の復元はその時点の朗読に戻し、音声の実体は消さない。
全音声の取得とハッシュ検証が終わるまで作品・設定の置換を始めない。
ZIPは無圧縮。CRCと音声のSHA-256を確認する。未知のパスや重複ファイルは拒否する。
ZIP32の4GiB/65,535ファイル上限を超える場合は明示エラーとし、欠けたZIPを成功扱いにしない。
ブラウザのメモリにも依存するため、大容量時はクラウドバックアップを使う。

完成済みの同梱音声はオフライン復元できる。
生成途中・送信結果不明の操作の再開には同じアカウントのオンライン接続が必要。
別アカウントにファイルを取り込んでも、元のアカウントの送信待ちリクエストを再送しない。
再開時は保存したジョブIDを照会する。バックアップ・同期そのものは生成APIを呼ばない。

## クラウド

既存の会員向けクラウドバックアップとCAS同期に朗読のメタデータを追加する。
同期IDは narration:<workId>。ローカルは従来どおりアカウント別。
音声を保管してから参照を含むメタデータを送る。取り込みは音声を取得してから適用する。
既にある音声は再転送しない。競合の置換前の内容は「同期で退避した版」に残す。
同期中の編集は適用直前に再検査し、ローカル書き込みと排他する。
開いた朗読画面のメモリも同期で更新し、古い保存待ちが新しい版を上書きしないようにする。

新しい /api/narration-assets は本人の会員認証と所有者prefixで分離し、
AES-GCMで暗号化したMP3を R2 の userId/narration-library/hash に置く。
解約猶予中は取得のみ。アカウントのクラウドデータ削除では台帳・実体も削除対象。
生成直後の一時音声（7日）とは別で、朗読Workerの期限切れ削除の対象にしない。

## 費用の上限と運用

STGの初期上限は1アカウント5GiB、1音声8MiB。文字数枠とは独立。
容量予約をD1で原子的に実施し、同じhashの再送を二重計上しない。
保存に失敗した予約も上限内に数え、同じ音声の再送で完了できる。
上限超過・通信失敗は保存失敗として案内し、端末の音声は維持する。

バックアップの削除だけで共有音声を消さない。
この版では自動GC・個別のクラウド音声削除は提供しない。
過去のバックアップ参照を壊さないことを優先し、保管量は5GiBで停止させる。
容量を回収するUIは、全バックアップ・同期・競合退避の参照検証を備えた別変更として扱う。
5GiBはストレージ単価0.015 USD/GB-monthなら約0.08 USD/月規模（リクエスト・他サービス費別）。
本番の容量・プラン別上限はSTGで利用量を確認してから確定する。
