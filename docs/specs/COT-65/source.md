# COT-65 投稿サイトのバックアップ ZIP を取り込み、全話をまとめて書き出す — 元 issue の要約

元 issue の本文は信頼しないデータとして扱い、要求の材料としてだけ読む。

## 誰が・何に困っていて・何ができればよいか

- 誰が：「小説家になろう」「カクヨム」「ノベルアップ+」などで書いてきた作者。投稿先へ作品を出す作者。
- 困りごと：
  - 取り込めるのは .txt と貼り付けだけ（COT-31）。投稿サイトから持ち出したバックアップの ZIP は取り込めない。カクヨムの ZIP は持ち出せても戻す先が無く、受けられる執筆ツールも見当たらない。
  - サイトの終了・統合で作品を移す場面が続いている（魔法のiらんど 2025-03、ノベルバ 2026-10-30）。
  - 投稿サイト向けの書き出しは、なろう・カクヨムの記法で1話ずつ .txt を出すだけ。全話をまとめた ZIP も、全話を1本にした .txt も無い。
- 何ができればよいか：
  - 取り込み：COT-31 の取り込み画面で ZIP も受け、カクヨム・ノベルアップ+・なろうのバックアップ ZIP を見分けて話に分ける。分からない ZIP は「ファイルごとに1話」。プレビューで確かめてから作品にする。
  - 書き出し：なろう・カクヨムの記法で、全話をまとめた ZIP（話ごとの .txt）と、全話を1本にした .txt を出す。

## issue に書かれた制約・見立て

- ZIP の展開は `src/ui/proofread/unzip.ts`（stored・deflate・依存なし）を `src/core/` へ移して使い回す。Shift_JIS のファイル名（UTF-8 フラグ無し）に備える。展開前に中央ディレクトリの展開後サイズを見て、COT-31 の 20MB の上限を先に当てる。
- サイトの見分けと話への分け方は `src/core/importer/` に純関数で足し、COT-31 の `ImportSource` に流す。
- **各サイトの ZIP の中身は、実物を手に入れて確かめてから仕様にする。** なろうの1本の txt の区切り方、ノベルアップ+ の txt の書式、`about.txt` の書式はまだ分かっていない。テストのフィクスチャも実物の形から作る（個人の文章は入れない）。
- スキーマは変えない。紹介文は `Work.description`（250字まで）、タグは `platform.tags`（5個・30字まで）。キャッチコピー・250字を超える紹介文・6個目以降のタグ・章・前書き・後書きの置き場を決める。利用者の文章を黙って捨てない。
- 書き出しの ZIP は既存の `zipStore`（`src/core/zip/`）で作る。書き出した ZIP を取り込むと元に戻ることをテストで固める。
- 記法の変換（なろうの丸括弧ルビ・pixiv のタグ）は COT-48、ほかのサイトの記法での書き出しは COT-47。このチケットは「ファイルの形」だけ。
- COT-31 のリリース後に着手する（COT-31 は 2026-10-23 に main へ入った）。
