# 要件定義 — COT-65 投稿サイトのバックアップ ZIP を取り込み、全話をまとめて書き出す（なろう・カクヨム・ノベルアップ+）

> **状態：カクヨム（FR-3）と小説家になろう（FR-5）は実物の ZIP で確かめた（2026-10-25・`samples.md`）。ノベルアップ+（FR-4）は実物が無く仮。** ノベルアップ+ は実物が届くまで見分けを実装せず、FR-6（見分けられない ZIP）として扱う。カクヨムの紹介文・キャッチコピー・タグの見出し名と、なろうの前書きの見出し名は、設定のある作品で確かめるまで仮。

## 背景と目的

投稿サイトで書いてきた作者が作品を丸ごとコトノハへ移すには、いまは .txt を1話ずつ用意するか、貼り付けるしかない（取り込みは .txt と貼り付けだけ `src/ui/components/TextImportDialog/source-pane.tsx:72`）。サイトが出すバックアップの ZIP をそのまま受けて話に分ければ、移す手間が一度で済む。
逆向きに、投稿先へ出すときも、いまは1話ずつ .txt を書き出すしかない（`src/ui/components/ExportDialog/export-dialog.tsx:313-319`）。全話をまとめた ZIP と、全話を1本にした .txt を出せるようにして、1話ずつ読み込むサイトにも、1本を受けてサイト側で分けるサイトにも出しやすくする。

## 機能要件

### FR-1 ZIP を受ける
- ファイル選択の `accept` を `.txt,.zip` にし、ドロップでも .zip を受ける。ドロップ領域の案内は「.txt（UTF-8・Shift_JIS・EUC-JP・JIS）・複数可、または投稿サイトのバックアップ ZIP（1つ）・合計 20MB まで」。読めないときの文言（COT-31 の `unreadable`）も「UTF-8・Shift_JIS・EUC-JP・JIS のテキストファイルを選んでください」に直す
- ZIP を入れると、一覧には ZIP の名前が1行で出て、その下に「カクヨムのバックアップとして読みました（12話）」のように見分けた結果を出す（見分けられなければ「ZIP の中の .txt 12 件を読みました」）
- ZIP は1回に1つ。すでに .txt か ZIP が入っているときに ZIP を足すと、足さずに「ZIP は1つずつ取り込めます。いま入っているファイルを外してから選んでください」と出す。ZIP が入っているときに .txt を足しても同じ
- 受け入れ条件
  - Given 取り込みダイアログ / When .zip を選ぶ / Then ZIP の名前と見分けた結果が一覧に出て、プレビューに話が並ぶ
  - Given .txt が1つ入っている / When .zip をドロップ / Then 足されず、上の案内が出る（.txt は残る）
  - Given ZIP を入れた / When ✕で外す / Then 一覧とプレビューが空に戻り、.txt も ZIP も選べる
  - Given 貼り付けに切り替える / Then ZIP は残したまま（COT-31 の切り替えと同じ）、プレビューは貼り付けだけから作る

### FR-2 安全な展開と文字コード
- 展開の前に中央ディレクトリだけを読み、次のどれかなら展開しない（理由は一覧の行に出す）
  - 展開後の合計が 20MB を超える：「中身が大きすぎます。合計 20MB までの ZIP を取り込めます」
  - 暗号化されている（汎用ビットフラグの bit 0）：「パスワード付きの ZIP は取り込めません」
  - 圧縮方式が stored・deflate 以外：「この ZIP の形式には対応していません」
  - 中に .txt が1つも無い：「ZIP の中にテキストファイル（.txt）がありません」
  - ZIP として読めない：「ZIP として読めませんでした」
- 取り出す対象は .txt だけ。フォルダ・`__MACOSX/`・`.DS_Store`・画像などは読み飛ばし、件数を「.txt 以外の 3 件は読み飛ばしました」と出す
- ファイル名：UTF-8 フラグ（bit 11）があれば UTF-8、無ければ UTF-8 として正しければ UTF-8、そうでなければ Shift_JIS として読む。フォルダの階層は名前の一部として保ち（並び順に使う）、表示はファイル名だけ
- 本文の文字コード：各 .txt を次の順で判定する（COT-31 の `decodeTextFile` を広げる。.txt を直接入れたときも同じ）
  1. ESC（0x1B）に続く `$B` `$@` `(B` `(J` の並びがあれば ISO-2022-JP（JIS）として復号する
  2. UTF-8（fatal）で復号でき、`looksLikeText` を通れば UTF-8
  3. Shift_JIS と EUC-JP の両方で復号し、`looksLikeText` を通ったものから、点数の高いほうを選ぶ。点数は「ひらがな（U+3041〜U+309F）の数 − 置換文字 U+FFFD の数」。同点なら Shift_JIS。漢字やカタカナは数えない（半角カナの Shift_JIS を EUC-JP で読むと漢字の並びになるため）。EUC-JP の日本語を Shift_JIS で読むと「､｢､､」のようにひらがなが 0 になり、半角カナだけの Shift_JIS はどちらもひらがな 0 の同点で Shift_JIS になる。どちらかを先に試して決めることはしない
  - どれでも読めない .txt はその1件だけ「読めませんでした」として除き、ほかは取り込む
- 受け入れ条件
  - Given 中央ディレクトリで展開後 25MB の ZIP / Then 展開せず（`DecompressionStream` を呼ばず）、上限の案内が出る
  - Given UTF-8 フラグの無い ZIP に Shift_JIS のファイル名「第1話.txt」 / Then 名前が「第1話.txt」と読める
  - Given EUC-JP の .txt を含む ZIP / Then 文字化けせず読め、文字コードの印に「EUC-JP」と出る
  - Given ISO-2022-JP（JIS）の .txt / Then 文字化けせず読め、印に「JIS」と出る
  - Given Shift_JIS の .txt（COT-31 のフィクスチャ） / Then いまと同じく Shift_JIS と判定される
  - Given 半角カナだけの Shift_JIS の .txt（バイト列 `B1 B2 B3 B4 B5 B6 0A C3 DE B1 B2`＝EUC-JP でも漢字として読めてしまう並び） / Then Shift_JIS と判定される
  - Given 画像と .txt が入った ZIP / Then .txt だけが話になり、読み飛ばした件数が出る
  - Given 暗号化された ZIP / Then 理由が出て、ほかの状態は変わらない

### FR-3 カクヨムの ZIP（実物で確認済み。形は `samples.md`）
- 見分け：ZIP の直下に `about.txt` と、`episode_` ＋4桁の数字の .txt が1つ以上ある
- 話：`episode_NNNN.txt` を番号の順に1話ずつ。各 txt の `【タイトル】` の次の行が題名、`【本文（N行）】` の次の行から N 行ちょうどが本文（本文の中の `【…】` の行で切れない）。`【公開状態】` は読まない（下書きの話も公開済みの話も同じに取り込む）。`【本文（N行）】` が無い・行数が足りない txt は、見出しの後ろを全部本文にして、その話に「本文の行数が合いませんでした」と印を出す
- 章：`about.txt` の `【目次】` の `§ ` で始まる行が章。続く `  M. 話の題名` の M（作品の通し番号）が、`episode_` の番号に対応する。章の題名は FR-7 の規則で添える。目次に無い話・目次にあって txt が無い話は、txt のほうを正とする
- 作品情報：作品タイトルは `about.txt` の `【タイトル】`。`【作者名】` は `@` で始まるアカウントの ID なので著者には使わない（著者の欄はいまのままペンネームを既定にする）。`【キャッチコピー】` `【紹介文】` `【タグ】` は、実物（設定の無い作品）には無かった。見出しがあれば FR-7 で扱い、無ければ何もしない（**見出しの名前は未確認**）。ほかの見出し（連載状態・ジャンル・イメージカラー・日時・文字数）は取り込まない
- 受け入れ条件
  - Given 章ありの ZIP（目次に `§ 第一章　仮の章`・1話・2話、`§ 第二章　です`・3話）/ Then 3話。題名は「第一章　仮の章　／　第1話」「第2話」「第二章　です　／　第3話」、本文は各 txt の本文の行
  - Given 章なしの ZIP（目次が `1. 第1話` から字下げなし）/ Then 3話。題名は「第1話」「第2話」「第3話」
  - Given `【本文（5行）】` の本文に `【回想】` で始まる行を含む txt / Then その行も本文に入る（5行ちょうど）
  - Given 作品タイトル / Then 作品タイトルの欄の既定値が about.txt の `【タイトル】` になる
  - Given about.txt の `【作者名】` が `@foo` / Then 著者の欄は `@foo` にならない（ペンネームのまま）

### FR-4 ノベルアップ+ の ZIP（仮）
- 見分け：`episode_` ＋5桁の数字の .txt が1つ以上あり、`about.txt` が無い（カクヨムは4桁＋`about.txt`。issue の記述による。**実物は未確認**）
- 話：番号の順に1話ずつ。txt の中の「章タイトル・話タイトル・前書き・後書き・公開日時」を読み分け、題名は話タイトル、章と前書き・後書きは FR-7、公開日時は取り込まない
- 作品情報：作品情報のファイルがあれば題名・紹介文・タグを読む（FR-7）
- **確定に要る実物の情報**：txt の中の各項目の書き方、作品情報のファイルの名前と書式。実物が届くまでは、ノベルアップ+ の見分けは実装せず、FR-6（見分けられない ZIP）として扱う
- 受け入れ条件（実物で書き直す）
  - Given `episode_00001.txt`〜`episode_00003.txt` の ZIP / Then 番号順に3話

### FR-5 小説家になろうの ZIP（実物で確認済み。形は `samples.md`）
- 見分け：ZIP の中に、中身に `【Nコード】` の見出しと `エピソード1開始` の区切りの行がある .txt が1本ある（名前は Nコード＝`N`／`n`＋4桁＋英字1〜2文字であることが多いが、名前では決めない。名前を変えた txt でも見分ける）
- その1本のほかに .txt があれば、話にはせず、一覧の行に「ほかの .txt 2 件は取り込みません（ファイル名）」と出す
- なろうの txt を .txt として直接入れたとき（ZIP から出して入れた場合）：中身が見分けの条件（`【Nコード】`＋区切りの行）に合えば、その .txt はなろうの ZIP と同じに扱う（一覧の行に「小説家になろう」のバッジ、作品情報・著者の既定値も同じ）。そのとき .txt はそれ1本だけ。ほかの .txt がすでに入っているか、あとから足そうとしたら、足さずに「小説家になろうのバックアップは、1本だけで入れてください」と出す
- 次の txt は取り込まず、その行に理由を出す（1本の txt がそのまま1話になり、ユーザID や評価が本文に入るのを防ぐ）
  - `【ユーザ情報】` の見出しがあるのに、区切りの行が1つも無い（.txt でも ZIP の中でも）：「小説家になろうのバックアップとして読めませんでした。ダウンロードし直したファイルを入れてください」
  - 見分けの条件に合う txt が2本以上ある ZIP：「小説家になろうのバックアップが2つ入っています。作品ごとに ZIP を分けて入れてください」
- 区切り：`-` 25個・半角空白・`エピソードN開始`・半角空白・`-` 25個 の行。最初の区切りより前が作品情報、区切りから次の区切り（最後は `【免責事項】`）までが1話
- 1話の中：`【第N章】` の次の行が章の題名（章の頭の話にだけある）、`【エピソードタイトル】` の次の行が題名、`【前書き】`（**実物に無く未確認**。あれば）から次の見出しまでが前書き、`【本文】` から `【後書き】` か `【リアクション】` までが本文、`【後書き】` から `【リアクション】` までが後書き。`【リアクション】` 以降はその話の外（取り込まない）。本文の中の行は、行頭が上の見出しの語と完全に一致する1行だけを見出しとみなす
- 作品情報：`【タイトル】` を作品タイトルの既定値、`【作者名】` を著者の欄の既定値（空でなければ。ペンネームより優先する。利用者が著者の欄を先に打っていたら上書きしない。ZIP を外したらペンネームに戻る）、`【あらすじ】`（次の見出しまで・複数行）を紹介文、`【キーワード】`（半角空白区切り）をタグとして FR-7 で扱う。`【作品に含まれる要素】` はネタ帳のメモにだけ残す
- **取り込まないもの（個人の情報・他人の反応）**：`【ユーザ情報】`（ユーザID・ユーザ名）、`【評価】`、`【収益情報】`、各話の `【リアクション】`、`【免責事項】`、受付・開示の設定と日時・話数
- 検算：`【掲載エピソード数】` と区切りの数が違えば、プレビューに「ファイルの話数（13）と、読み取れた話の数（12）が違います」と出す（作品は作れる）
- 下書き・フリーメモ：実物の ZIP には入っていなかった（公開済みの話だけ）。別の txt として入っていた場合は、FR-6 と同じく読み飛ばさずに一覧に出す（話にはしない）（**未確認**）
- 受け入れ条件
  - Given 13話・章2つ（1話目に `【第1章】`、10話目に `【第2章】`）の txt / Then 13話。1話目と10話目の題名に章の題名が添わる
  - Given 5話目に `【後書き】` がある / Then 5話目の本文の後ろに「（後書き）」の行と後書きが入る。後書きの前の `【リアクション】` の件数は入らない
  - Given 作品情報 / Then 作品タイトル・著者の既定値が `【タイトル】` `【作者名】`。あらすじは先頭 250 字が作品情報へ、キーワード 10 語は先頭 5 語がタグへ、残りとあらすじの全文と「作品に含まれる要素」はネタ帳のメモへ
  - Given 取り込んだ作品とネタ帳のメモ / Then ユーザID・評価・収益・リアクションの文字列がどこにも入っていない
  - Given なろうの txt と、ほかの .txt 1件が入った ZIP / Then なろうとして読み、ほかの .txt は話にせず「ほかの .txt 1 件は取り込みません」と出る
  - Given なろうの txt の名前を `backup.txt` に変えた ZIP / Then なろうとして読める
  - Given なろうの txt を .txt として直接入れる / Then なろうとして読み、ユーザID・評価が本文に入らない。著者の既定値は `【作者名】`
  - Given なろうの txt を直接入れたあとに、別の .txt を足す / Then 足されず「…1本だけで入れてください」と出る。逆の順でも同じ
  - Given なろうの txt と別の .txt を同時に選ぶ（ドロップ・選択とも）/ Then 復号が済んだ時点で、なろうと分かった行を外して「…1本だけで入れてください」と出し、ほかの .txt は残す。なろうの txt を2本同時に選んだときも、2本とも外して同じ案内を出す。なろうの txt を1本だけ選んだときはなろうとして読む。一覧に読めなかった（エラーの）行があるときも、ほかの行があるとみなす。なろうの txt の読み込み中に別の .txt を足したときは、足した側を断る
  - Given `【ユーザ情報】` はあるが区切りの行が無い txt / Then 取り込まれず、上の理由が出る
  - Given なろうの txt が2本入った ZIP / Then 取り込まれず、上の理由が出る
  - Given 著者の欄に「月見」と打ってから、なろうの ZIP を入れる / Then 著者は「月見」のまま。著者の欄を触らずに ZIP を入れると `【作者名】`、ZIP を外すとペンネームに戻る
  - Given 章が1つだけの ZIP（先頭の話にだけ `【第1章】`）/ Then 1話目の題名だけに章の題名が添わる（「章の題名を話の題名に添える」をオフにすれば添わらない）
  - Given 章をすべて消した ZIP（`【第N章】` が無い）/ Then 13話の題名は `【エピソードタイトル】` のまま。「章の題名を話の題名に添える」のスイッチは出さない

### FR-6 見分けられない ZIP
- 中の .txt を、ZIP 内のパスの自然順に並べ、COT-31 の `ImportSource` として扱う（1ファイル＝1ソース）
- 分け方の既定は「ファイルごとに1話」。COT-31 と同じく「見出し行で分ける」「分けない」も選べる
- 題名はファイル名（拡張子なし）。ZIP から来た txt に限り、先頭の「番号＋区切り（`_` `-` `.` 空白）」は落とす（例 `001_坂.txt` → 「坂」）。番号だけの名前（`001.txt`）は落とさない。.txt を直接入れたときの題名は COT-31 のまま（`2024_日記.txt` は「2024_日記」）
- 受け入れ条件
  - Given `2_b.txt` `10_c.txt` `1_a.txt` の ZIP / Then 「a」「b」「c」の順に3話
  - Given `001.txt` / Then 題名は「001」
  - Given 見分けられない ZIP / When 分け方を「見出し行で分ける」にする / Then 各 txt の中の見出し行で分かれる（COT-31 と同じ）

### FR-7 作品情報と、入りきらない文章の置き場（FR-3〜FR-5 で使う）
- 紹介文：先頭 250 字を `description`。250 字を超えたら、全文をネタ帳のメモに残す
- タグ：先頭 5 個（各 30 字まで。超えた分は切る）を `platform.tags`。6 個目以降と、切った元の語はネタ帳のメモに残す。なろうはキーワード（半角空白区切り）をタグとして扱い、「作品に含まれる要素」はメモにだけ残す
- キャッチコピー：ネタ帳のメモに残す
- ネタ帳のメモ：作品を作ったときに1件だけ作る。本文は「『<作品名>』を取り込んだときに、作品情報に入りきらなかったものです。」に続けて、キャッチコピー・紹介文（全文）・タグ（全部）を項目ごとに並べる。入りきらないものが無ければ作らない
- 章：その章の最初の話の題名の前に、章の題名を「<章の題名>　／　<話の題名>」の形で添える（2話目以降には付けない）。プレビューで外せる（「章の題名を話の題名に添える」、既定オン）
- 前書き・後書き（なろう。カクヨムには無い）：本文の前（前書き）と後（後書き）に、空行を1つ挟んで残す。前に「（前書き）」、後に「（後書き）」の行を置いて本文と見分けられるようにする。プレビューで外せる（「前書き・後書きを本文に残す」、既定オン。オフにすると捨てたことをプレビューに件数で出す）
- プレビューの上に、どこへ何が入るかを出す：「紹介文 → 作品情報のあらすじ（250字まで）」「キャッチコピー・あふれた紹介文・6個目以降のタグ → ネタ帳に1件」
- 受け入れ条件
  - Given 紹介文 400 字・タグ 7 個・キャッチコピーあり / When 作品を作る / Then `description` は先頭 250 字、`platform.tags` は先頭 5 個、ネタ帳に1件増え、そこにキャッチコピー・紹介文の全文・タグ 7 個がある
  - Given 紹介文 100 字・タグ 3 個・キャッチコピーなし / Then ネタ帳は増えない
  - Given 章「第一章　旅立ち」の最初の話「坂」 / Then 題名「第一章　旅立ち　／　坂」。同じ章の2話目は話の題名のまま
  - Given 前書きのある話 / Then 本文の頭に「（前書き）」の行、前書き、空行、本文の順。オフにすると前書きは入らず、プレビューに「前書き・後書き 4 件を外します」と出る

### FR-8 全話を ZIP で書き出す
- 「Web投稿形式」に「書き出す範囲」：この話／全話（ZIP・話ごとの .txt）／全話（1本の .txt）。既定は「この話」（いまと同じ）
- 全話 ZIP：投稿先（なろう／カクヨム）の記法で、話の順に `NNN_<話の題名>.txt`（NNN は3桁の通し番号。話が 1000 以上なら4桁）。題名のファイル名に使えない文字は `_` に置き換える（既存の `safeName` と同じ規則 `src/ui/_utils/exporters.ts:28-30`）。中身は1話ぶんの記法の本文（題名は入れない＝いまの1話の書き出しと同じ）。文字コードは UTF-8（BOM なし）・改行は LF
- ZIP の名前は「<作品名>_<narou|kakuyomu>_全話.zip」
- 受け入れ条件
  - Given 3話の作品 / When 全話（ZIP）・なろう / Then `001_<題名>.txt` 〜 `003_<題名>.txt` の3件が入った ZIP がダウンロードされ、各 txt が 1話の書き出し（`episodeNarouExport`）と同じ本文
  - Given 題名に「/」を含む話 / Then ファイル名の「/」が「_」になる
  - Given 話が1つも無い作品 / Then 書き出しを押せない（いまと同じ）

### FR-9 全話を1本の .txt で書き出す
- 話の順に、見出し行（話の題名）・空行・本文・空行2つ、を並べる
- 見出し行は、話の題名がそのまま見出し行として認識される（`isHeadingLine` が真）ならそのまま、そうでなければ「■」を頭に付ける（例「坂」→「■坂」）。見出しの規則に当たらない題名でも、取り込みで話に分かれる形にするため
- ファイル名は「<作品名>_<narou|kakuyomu>_全話.txt」
- 受け入れ条件
  - Given 題名「第1話　坂」「第2話　村」の作品 / Then 見出し行は題名のまま
  - Given 題名「坂」 / Then 見出し行は「■坂」
  - Given 書き出した1本の .txt / When COT-31 の取り込み（見出し行で分ける）に入れる / Then 話の数と本文（話の先頭と末尾の空行を除く）が元と一致する（題名は「■」が付いたものになりうる。本文に見出し行の規則に当たる行が無い場合）

### FR-10 往復
- FR-8 の ZIP を FR-6 で取り込むと、話の数・順・題名・本文の記法テキストが元と一致する（題名にファイル名に使えない文字が無い場合。比べるときは、話の先頭と末尾の空行を除く＝取り込みが落とすため `split.ts:95-101`・`build.ts:34`）
- なろうの記法では、傍点は書き出すと `｜月《・》` になり、取り込むとルビとして読まれる（`toNarou.ts:5,24-29` の「往復で恒等になる（傍点を除く）」）。そのため、なろうの往復は「ZIP の中の txt の本文」と「取り込んで分けた話の本文（`parseEpisodeBody` の前の文字列）」の一致で比べる。カクヨムは記法テキストどうし（`blocksToKakuyomu` の出力どうし）で比べる
- 受け入れ条件
  - Given ルビ・傍点・空行・字下げを含む3話の作品 / When 全話 ZIP（なろう）→ 取り込み / Then 各話について、ZIP の txt の本文と、取り込みで分けた話の本文が一致する
  - Given 同じ作品 / When 全話 ZIP（カクヨム）→ 取り込み → 作品を作る / Then 話ごとに `blocksToKakuyomu` の出力が元と一致する

## 非機能要件

- 性能：20MB の ZIP の中央ディレクトリの検査は展開前に終わる（展開しない）。展開は1件ずつ非同期に行い、画面を固めない
- オフライン：すべて端末の中で完結する
- プライバシー：ZIP の中身を外へ送らない。テストのフィクスチャに実在の個人の文章を入れない（実物の形だけを写した架空の文で作る）
- アクセシビリティ：一覧の結果・エラーは COT-31 と同じ出し方（`aria-live` の領域）
- 無料／有料・ゲスト：取り込みと書き出しはゲストを含め全員が使える（COT-31・既存の書き出しと同じ）
