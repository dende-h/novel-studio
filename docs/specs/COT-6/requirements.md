# 要件定義 — COT-6 脚本モード機能の追加

## 背景と目的
舞台・映像・ボイスドラマなどの脚本を書く作者が、小説向けの本文エディタでは柱・ト書き・セリフを書き分けにくい。
作品ごとに「形式：脚本」を選ぶと、本文の各行を**行頭の書き方だけ**で柱・ト書き・セリフとして扱い、
プレビュー・EPUB・テキスト書き出し・公開サイト（grove）で脚本の体裁になるようにする。
本文の正本は今までどおり純テキスト（記法）のままにし、スキーマ・同期・MCP・なろう往復を壊さない。

決定済み（2026-09-26 ユーザー回答）：記法＝行頭の書き方で判別／モード単位＝作品ごと／初回範囲＝エディタ＋プレビュー・書き出し・grove 公開。演出譜との連携は初回に含めない。

## 機能要件

### FR-1 作品の形式（小説／脚本）
- `Work.format` を optional で足す。値は `'novel' | 'script'`。**未設定＝小説**。
- 受け入れ条件
  - Given 形式未設定の旧作品 / When 一覧・エディタ・書き出し・同期で読む / Then 今までと同じ振る舞い（小説）
  - Given 作品情報ダイアログ / When 形式を「脚本」にして保存 / Then `format: 'script'` が保存され、以降の画面に即反映される（保存はタイトル等と同じ経路）
  - Given 脚本の作品 / When 形式を「小説」に戻す / Then `format` キーが消える（`'novel'` を書き残さない。未設定＝小説を唯一の表現にする）
  - Given 脚本の作品 / When クラウド同期・クラウドバックアップ・復元 / Then `format` が失われない（Work を丸ごと運ぶため）

### FR-2 行頭の書き方で判別する（純ロジック）
判別は `src/core/` の純関数で行い、本文には何も書き足さない。1 block（＝1行）ごとに次の順で決める。
| 種類 | 判定（純テキストで見る。柱・セリフは行頭空白を除いて見る。字下げは生の行頭で見る） | 例 |
|---|---|---|
| 空行 `blank` | 空か空白だけ | |
| 柱 `slug` | 先頭が `○`（U+25CB）または `〇`（U+3007） | `○公園（夕方）` |
| ト書き `direction`（字下げ） | **行頭が空白**（全角・半角）で始まる行。脚本の慣習どおり、字下げした行は中に「」があってもト書き | `　ベンチに座るユイ。` `　看板に「立入禁止」とある。` |
| セリフ `dialogue` | 行頭から `名前` ＋（任意で `（補足）` を 1 つ）＋（任意の空白）＋ `「` または `『`。名前は 1〜20 文字で空白・括弧・鉤括弧を含まない。補足は 1〜10 文字。名前なしで `「` から始まる行もセリフ（**話者なし**。前行の話者は継がない） | `ユイ「もう帰ろっか」` `ユイ（声）「…」` `ケン（回想）「…」` `「……うん」` |
| ト書き `direction` | 上のどれでもない | `ベンチに座るユイ。`（字下げなし） |
- 純テキストは `plainTextOfBlock`（`src/core/game/index.ts:212`）と同じ規則で作る＝ルビは親文字・`[[ユイ]]` は名前。よって `[[ユイ]]「…」` も話者ユイのセリフになる。
- 判別の順序：空行 → 柱 → 字下げ（ト書き固定） → セリフ → ト書き。
- 受け入れ条件
  - Given 上表の各例 / When 判別する / Then 表どおりの種類と話者（`ユイ`）が返る
  - Given `[[ユイ]]（声）「…」` / Then セリフ・話者 `ユイ（声）`。プレビューの話者 span は `[[ユイ]]` の参照リンクと `（声）` を両方含む
  - Given `｜結衣《ゆい》「…」` / Then セリフ・話者 `結衣`。話者 span はルビごと含む
  - Given 空白だけの行 / Then 空行（`blank`）。描画は現状どおり（クラスを付けない）
  - Given `○` の後に何もない行 / Then 柱（見出しが空でも柱）
  - Given `　看板に「立入禁止」とある。`（字下げあり・途中に「」）/ Then ト書き。話者は付かない
  - Given `　「本当に？」`（字下げした鉤括弧）/ Then ト書き（脚本ではセリフは行頭から書く。ヘルプで案内）
  - Given `ユイ（声）「…」` `ケン（回想）「…」` / Then セリフ。話者は `ユイ（声）` `ケン（回想）`（括弧込み）
  - Given `ユイ（声）（M）「…」`（補足 2 つ）/ Then ト書き（補足は 1 つまで）
  - Given `「もう帰ろっか」と言った。` のような小説の一文 / Then セリフ（話者なし）。脚本形式でない作品にはこの判別を一切適用しない
  - Given 名前部分が 21 文字以上、または空白を含む（`ユイ ケン「…」`）/ Then ト書き
  - Given 小説形式の作品 / Then 判別関数は呼ばれず、描画は現状と同一の HTML

### FR-3 プレビューで脚本の体裁に描く
- `blocksToHtml` に「脚本として描く」指定を足し、`<p>` に種類のクラスを付ける：`sc-slug` / `sc-direction` / `sc-dialogue`（話者は `<span class="sc-speaker">`）。空行は現状の `p.blank` のまま。
- 体裁（縦書き・横書き両方で崩れないよう論理プロパティで書く）
  - 柱：太字。直前に 1 行ぶんの間隔
  - ト書き：行頭を 3 字下げる（打たれた行頭空白は描画時に除き、二重字下げにしない）
  - セリフ：折り返し 2 行目以降を 3 字下げる（ぶら下げ）。話者名は太字にしない（読みの邪魔になる）
- 受け入れ条件
  - Given 脚本の作品で FR-2 の例文 / When プレビュー / Then 柱・ト書き・セリフが上の体裁で描かれ、`@参照` のリンク・ルビ・傍点は今までどおり効く
  - Given 縦書き / Then 字下げ・間隔が縦方向に正しく効く（横倒しにならない）
  - Given 小説の作品 / Then 出力 HTML が現状と 1 バイトも変わらない（回帰テストで固定）

### FR-4 エディタの挿入ボタン
- 脚本の作品でだけ、既存の「ルビ／傍点／参照」の右に **「柱」「セリフ」** を足す（PC ツールバー・狭幅の記法バーの両方）。
  - 柱：行頭に `○` を入れる（選択があれば `○選択文字`。行の途中なら行頭へ）
  - セリフ：キャレット位置に `「」` を入れ、キャレットを `「` の直後に置く（選択があれば `「選択」`）。話者名は作者が打つ。`@` サジェストは今までどおり使える
- ト書きのボタンは作らない（何も付けない行がト書き。説明はヘルプとⓘで補う）。
- 新しいショートカットは足さない（既存 B/I/K と衝突させない）。
- 受け入れ条件
  - Given 小説の作品 / Then ボタンは 3 つのまま
  - Given 脚本の作品・PC 幅 / Then ツールバーに 5 つ並ぶ。Given スマホ幅で textarea にフォーカス / Then 記法バーに 5 つ並び横スクロールで届く
  - Given `ユイ` の直後にキャレット / When セリフ / Then `ユイ「」` になりキャレットは `「` と `」` の間

### FR-5 書き出し
- EPUB：各話 XHTML に FR-3 のクラスを出し、`style.css` に体裁を足す。小説の作品は出力が変わらない。
- なろう・カクヨム：脚本の作品では **ト書き行の行頭空白を取り除いてから全角空白 3 つを付ける**（字下げの有無によらず、ト書きはすべて 3 字下げ＝プレビューと同じ見え方）。柱・セリフは打たれたまま。小説の作品は変わらない。
- AI 向けテキスト（`workAiTextExport`）と MCP の `get_work` は**正規化しない**（AI が空白を書き戻して増えるのを防ぐ）。`blocksToPlainText` 自体は変えない（利用者向けの出口が無い）。
- **フォルダ書き出し（zip）は変えない**。本文はロスレスな正本記法のまま（`src/core/folder/index.ts:5-9`）。manifest には author・表紙と同じく `format` も載せない（正本の往復は bundle が担う）。
- 受け入れ条件
  - Given 脚本の作品 / When EPUB / Then XHTML に `sc-*` クラスがあり、`style.css` に対応ルールがある
  - Given ト書き `　ベンチに座る。`（全角空白 1 つ）/ When なろう書き出し / Then `　　　ベンチに座る。`（3 つ）
  - Given ト書き `ベンチに座る。`（字下げなし）/ When なろう書き出し / Then `　　　ベンチに座る。`
  - Given ト書き `　　　　ベンチに座る。`（4 つ）/ Then `　　　ベンチに座る。`（3 つに揃う）
  - Given 小説の作品 / Then 各書き出しの出力が現状と同一

### FR-6 公開バンドル（grove）
- 脚本の作品を投稿するときだけ `work.format: 'script'` を載せ、契約版を **v7** で名乗る。小説の作品は今までどおり（`format` を載せず版も上げない）。
- 受け入れ条件
  - Given 小説の作品 / When バンドルを組む / Then `format` キーが無く schemaVersion は現状の選び方のまま
  - Given 脚本の作品 / Then `work.format === 'script'` かつ `schemaVersion === 7`（素材や公開状態の有無に関わらず 7）
  - Given 脚本の作品を送り、grove が `unsupported-schema-version`（`supported < 7`）を返す / Then 「公開先がまだ脚本の体裁に対応していません。作品情報で形式を小説にしてから、もう一度お試しください。」を返す（既存の音声・サウンドノベル向け案内を出さない）
- 依存：grove 側（novel-platform）で v7 を受けて脚本の体裁で表示する実装が先。**grove が v7 を受けるまで leaf 側の v7 送信をリリースしない**（409 で投稿できなくなるため）。

### FR-7 既存データと契約を壊さない
- 後方互換性チェック節のとおり。加えて、脚本形式でも本文は純テキストのままなので、演出譜の `blockId` アンカー（`src/core/game/index.ts:50`）と `reconcileBlockIds` はそのまま効く。

### FR-8 切替口・一覧・ヘルプ
- 作品情報ダイアログに「形式」（小説／脚本の 2 択）を足す。ラベル横にⓘ（`FieldHelp`）で 3 つの判別ルールを説明する。ダイアログの説明文は「作品の情報を編集します。EPUB やコトノハ-grove- に反映されます。」に改める（現状は EPUB 限定の文言）。
- ライブラリのカードと行に、脚本の作品だけ「脚本」バッジを出す（「N話」バッジの隣）。
- ヘルプページに「脚本を書く」節を足す（判別ルール・ボタン・書き出しでの体裁）。
- 受け入れ条件
  - Given 作品情報ダイアログ / Then 形式の初期値が現在の形式（未設定＝小説）
  - Given 形式だけ変えて保存 / Then タイトル・著者・あらすじ・表紙・platform は据え置き
  - Given 脚本の作品 / Then カード・行に「脚本」バッジ。小説の作品には出ない

### FR-9 MCP
- `set_work_meta` に `format`（`'novel' | 'script'`）を足す。`'novel'` はキー削除。
- `get_work` と `list_works` の出力に、脚本の作品だけ `形式: 脚本` の行を足す。`get_work` はさらに判別ルール 1 行（`柱=○で始まる行 / セリフ=名前「…」 / ほかはト書き`）を添える。
- `set_episode` の説明文に「脚本の作品ではこの書き方で本文を書く」旨を足す。同じ説明文にある廃止済みの「行頭＊でシーン区切り」は要求外の小修正として併せて消す（`functions/api/_lib/mcp-server.ts:164`・同じ行を触るため分けない）。
- 受け入れ条件
  - Given `set_work_meta {format:'script'}` / Then 作品が脚本になり他の欄は据え置き。`{format:'novel'}` でキーが消える
  - Given 脚本の作品 / When `get_work` / Then 本文は打たれたまま（空白の正規化なし）で、先頭に形式の行がある

## 非機能要件
- 判別は 1 block あたり O(行長)。プレビューは既存の `useMemo` の中で毎打鍵に走るので、正規表現は行頭だけを見る。
- アクセシビリティ：クラス付けのみで DOM 構造は `<p>` のまま。話者の `<span>` に role は付けない。
- 公開されるもの：`format` は作品のメタで、作者だけの情報ではない（grove に送ってよい）。

## 後方互換性チェック（CLAUDE.md の各項目）
- スキーマ：`Work.format` を `.optional()` で追加。削除・必須化なし。旧レコードは `parse` を通る（回帰テストで固定）。
- 旧形式の読み出し：未設定＝小説として読む。変換・マイグレーションなし。
- 表示先の維持：既存欄の表示場所は変えない。形式は作品情報ダイアログ・カード・ヘルプに新しく出す。
- 部分更新で他の欄を落とさない：`updateWorkMeta` はスプレッドで既存を据え置く（`src/ui/store/editorStore.ts:504-514`）。`format` の削除は `coverImage: ''` と同じ「明示の削除」パターンで扱う。MCP の `set_work_meta` も渡した項目だけ。
- 削除は明示操作だけ：本文・話・作品を消すコードパスは足さない。
- 配信契約（publish・同期 API・MCP）：publish は v7 を「使うときだけ名乗る」。同期は Work を丸ごと運ぶので変更なし。MCP は入力を optional で足すだけ。旧クライアント（`format` を知らない版）が同期で Work を読んでも `WorkSchema.parse` は unknown key を落とさず通す（Zod の `z.object` は既定で strip。**strip されて保存し直されると `format` が消える**——要確認事項として設計で扱う）。

## 仮定と未決事項
- 仮定：柱の記号は `○` に限る（`▲` `■` などの派生記号は初回では扱わない）。
- 仮定：セリフの話者名は 20 文字以内・空白なし。補足（`（声）` `（M）` `（回想）`）は名前の直後に 1 つまで・10 文字以内。
- 仮定：脚本ではセリフを行頭から書き、字下げした行はすべてト書き（日本のシナリオ慣習）。
- 仮定：脚本でも組み方向（縦／横）は作者の設定に従う。
- 未決 U-1：旧クライアント（`format` を知らない版）が同期経由で Work を保存し直すと `format` が落ちる可能性。Zod `z.object` の strip 挙動による。設計で `passthrough` 相当の対処が要るか確認する。
- 未決 U-2：grove 側の v7 対応のリリース順（grove が先）。novel-platform リポに issue を切る。

## 対象外
- 演出譜（サウンドノベル）の話者判別を脚本ルールに合わせること（後続 issue）
- 話ごとの形式切替
- 柱・セリフの専用スキーマ（Block に kind を持たせる案）
- PDF・縦書き専用の脚本レイアウト（原稿用紙風）
