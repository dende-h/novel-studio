# 要件定義 — COT-40 推敲画面を執筆から切り離し、指摘ごとに「直す／このまま」を選べるようにする（形態素解析つき）

## 背景と目的

COT-30 で入れた小説の推敲チェックは、エディタの下に常に出ている。書いている最中もノイズになり、作者がわざとそう書いた箇所にも出続ける。
推敲は、作者が推敲したいときに開く専用の画面で行う。指摘ごとに「直す」か「このまま」かを作者が選び、「直す」にしたものだけを執筆画面に出す。
あわせて形態素解析（品詞の解析）を端末内で動かし、正規表現では作れない指摘と、文章の傾向の分析を足す。

## 機能要件

### FR-1 執筆画面から小説の推敲チェックを外す

- 受け入れ条件
  - Given 小説の作品で話を開いている / When 本文を表示する / Then エディタの下に「推敲チェック」の欄は出ない（幅を問わない）
  - Given 脚本の作品 / When 本文を表示する / Then 「脚本の書式チェック」は従来と同じ文言・件数・項目で出て、候補を押すと該当行が選択される
  - Given 小説の作品 / When 本文を入力する / Then 推敲ルールと表記ゆれの集計は執筆画面では走らない（App の `variantBase` 計算を含む）。「直す箇所」の照合（FR-6）だけが走る

### FR-2 推敲画面の入口

- 受け入れ条件
  - Given 無料会員か有料会員で、小説の作品を開き、幅が広い画面（`narrow` でない） / When サイドナビを見る / Then 「本文を書く」の直下に「推敲」の行がある
  - Given 上の状態で本文に未保存の編集がある / When 「推敲」を押す / Then 先に保存してから推敲画面に移る。保存に失敗したら移らず、トースト「保存できませんでした。下書きは残っています。もう一度お試しください」を出す（書き出し・公開と同じ文言）
  - Given ゲスト／脚本の作品／幅の狭い画面のどれか / When サイドナビを見る / Then 「推敲」の行は無い
  - Given 推敲画面を開いている / When 画面幅を狭くする / Then 本文の画面へ戻る（演出エディタと同じ）
  - Given 推敲画面 / When サイドナビの「本文を書く」を押す / Then 執筆画面に戻る

### FR-3 推敲画面の構成（本文は読むだけ）

- 受け入れ条件
  - Given 推敲画面を開いた / Then いま開いている話が対象になる。話は画面内の選択で切り替えられる
  - Given 推敲画面 / Then 本文は段落ごとに読み取り専用で表示され、入力欄（textarea）は無い。ルビは親文字、傍点・`[[参照]]` は文字だけで表示する（`plainTextOfBlock` と同じ文字列）
  - Given 指摘がある / Then 本文の該当文字列に印が付く。未判断は波線、「直す」は塗り。「このまま」は印を付けない
  - Given 推敲画面 / Then 右側に「指摘」と「分析」の切り替えがあり、「指摘」には「未判断 N」「直す N」「このまま N」の絞り込みがある
  - Given 指摘の一覧で1件を押す / Then 本文の該当段落が見える位置まで送られ、その指摘の印が強調される。本文の印を押すと一覧の該当する指摘が選ばれる
  - Given 「確認する項目」を開く / Then 項目ごとのオン／オフを切り替えられる。項目は COT-30 の7つに「一文の中の同じ助詞」「ら抜き言葉」を足した9つ。表記ゆれの自動発見（FR-8a）は「表記ゆれ」のスイッチで辞書の表記ゆれと一緒に切り替わる。オフの項目の指摘は一覧にも本文にも出ない
  - Given 推敲画面を開いた / Then 「確認する項目」の欄は開いていて、どの項目も選ばれていない。一覧には「上の「確認する項目」から、確かめたい項目を選んでください」と出る。選んだ項目だけの指摘が出て、選んだ項目は端末に残る（2026-10-14 のユーザー要望で、既定の「すべてオン」から変更）
  - Given 項目のチップにホバーするかフォーカスする / Then その項目が何を探すかの説明が出る
  - Given 話が空 / Then 「この話にはまだ本文がありません」と出る。Given 指摘が0件 / Then 「確認する項目では、気になる箇所は見つかりませんでした」と出る

### FR-4 指摘ごとの判断（直す／このまま）

- 受け入れ条件
  - Given 未判断の指摘 / When 「直す」を押す / Then その指摘は「直す」に移り、執筆画面の「直す箇所」に出る（FR-6）
  - Given 未判断の指摘 / When 「このまま」を押す / Then その指摘は「このまま」に移り、次に推敲画面を開いても未判断には出ない
  - Given 「直す」か「このまま」の指摘 / When 「未判断に戻す」を押す / Then 判断が消え、未判断に戻る
  - Given 未判断の一覧に、同じ項目・同じ文字列の指摘が同じ話に2件以上ある / When そのうち1件で「同じ指摘をすべてこのまま（N件）」を押す / Then N件すべてが「このまま」になる
  - Given 推敲画面でいま開いている話の「直す」の指摘 / When 「本文で直す」を押す / Then 執筆画面に戻り、本文の該当文字列が選択される（FR-6 の探し方と同じ）
  - Given 推敲画面で別の話（執筆画面で開いていた話とは違う話）を選んでいる / When その話の「直す」の指摘で「本文で直す」を押す / Then その話を執筆画面で開いてから、該当文字列を選択する
  - Given 判断した指摘 / When 本文の別の段落を編集・挿入・削除する / Then 判断はその指摘に付いたまま残る（段落 ID・項目・文字列・出現順で結び付く）
  - Given 同じ段落に同じ項目・同じ文字列の指摘が2つある / When 1つ目だけを「このまま」にする / Then 2つ目は未判断のまま残る

### FR-5 判断の保存と同期

- 受け入れ条件
  - Given 判断をした / When ページを再読み込みする / Then 判断は残っている
  - Given 同期できるアカウント（自動同期が有効） / When 別の端末で同じ作品を開く / Then 判断が同じ状態で見える
  - Given 同じ話の判断を2つの端末で変えてから同期した / Then 新しいほう（`updatedAt` が新しい記録）を採る。負けた側の判断は同期の退避一覧に載せない（退避一覧は全種類で20件までなので、ほかの退避を押し出さないため。原稿・プロット等の退避は従来どおり）
  - Given クラウドバックアップ・手動のバックアップ書き出し / When 書き出して復元する / Then 判断も戻る
  - Given 作品をゴミ箱から完全に削除する（手動・30日期限） / Then その作品の判断も消える。ゴミ箱に移すだけなら残る
  - Given 判断を保存しても / Then `Work`・`Episode`・`Block` の保存物は変わらない（判断は本文の外）
  - Given 判断だけを変えた / Then 同期の送信の契機が起きる（演出譜と同じ「保存で同期を促す」包み方）。自動クラウドバックアップの静止判定にも数える

### FR-6 執筆画面の「直す箇所」

- 受け入れ条件
  - Given 小説の話に、まだ直っていない「直す」の判断が1件以上ある / When 執筆画面を表示する（PC・スマホとも） / Then ツールバー右側の操作群の先頭に「直す箇所 N」が出る。0件なら何も出ない
  - Given 「直す箇所 N」を押す / Then 一覧が開き、項目ごとに項目名・該当文字列（前後を少し添える）・説明が出る。各項目は「その箇所へ移る」ボタンと「外す」ボタンを持つ（キーボードの Tab で両方に届く）
  - Given 一覧の項目で「その箇所へ移る」を押す / Then 一覧が閉じ、本文の該当文字列が選択状態になり、見える位置へ送られる。探し方は (1) 判断した段落のプレーンな文字列（`plainTextOfBlock`）で、判断した出現（その文字列の、段落の中での通し番号の出現）の位置を求める (2) その位置を、記法つきの行の位置に移して選ぶ。ルビの読み・記法の記号の中は選ばない (3) 位置を移せない（参照の中など）なら、その行全体を選び、トースト「その箇所だけを選べなかったため、段落全体を選びました」を出す。ほかの段落は探さない
  - Given 一覧が開いている / When Esc を押すか一覧の外を押す / Then 一覧が閉じ、Esc のときは「直す箇所」ボタンにフォーカスが戻る
  - 「判断した出現」は、判断した時点でその段落のプレーンな文字列に現れる同じ文字列（指摘かどうかを問わない）の中での通し番号で覚える。数えるときは1文字ずつずらして探し、重なり合う出現もそれぞれ数える（「ご…ご…ご」の「ご…ご」は2つ）
  - Given 本文を直して、判断した段落の中のその文字列の数が、判断した出現の通し番号（1つ目なら1、2つ目なら2）より少なくなった（字下げの指摘は、段落の頭が指摘時の文字で始まらなくなった）/ When 入力する（保存を待たない） / Then その項目は一覧から消え、件数が減る。判断の記録は消さない
  - Given 段落「鳥が飛んできた。彼にもできた。」で、後ろの「できた」だけが指摘され「直す」にした / When 後ろの「できた」を「出来た」に直す / Then 「直す箇所」から消える。直す前に「その箇所へ移る」を押すと、後ろの「できた」を選ぶ
  - Given 段落「「ここから見れるよ」と言ったが、私には見れなかった。」で、地の文の「見れ」（ら抜き）を「直す」にした / When 地の文を「見られなかった」に直す / Then 「直す箇所」から消える。直す前は地の文の「見れ」を選ぶ
  - Given 段落「ご…ご…ごめん」で、三点リーダーの2つの指摘（どちらも文字列は「ご…ご」で位置が重なる）のうち2つ目だけを「直す」にした / Then 直す前から「直す箇所」に1件出て、「その箇所へ移る」は2つ目（3文字目の「ご」から。0始まりの位置で 2〜5 の手前まで）を選ぶ。2つ目の「…」を「……」に直すと消える
  - Given 判断した文字列と同じ文字列を、同じ段落の判断した箇所より前に書き足した・消した / Then 通し番号がずれ、隣の出現を選ぶ・直っていないのに消えることがある（原稿には影響しない。推敲画面で見直せる）
  - Given 同じ段落に「。」」が2つあり、1つ目を「このまま」、2つ目を「直す」にした / When 2つ目を直す / Then 「直す箇所」は0件になり、推敲画面でも「直す」は0件、残った「。」」は「このまま」のまま
  - Given 同じ段落の「。」」2つを両方「直す」にした / When 1つ目だけ直す / Then 「直す箇所」は2件から1件になる
  - Given 同じ段落に同じ文字列の「直す」の判断がある / When 「その箇所へ移る」を押す / Then それぞれの判断の通し番号の出現を選ぶ
  - Given ルビの読みに同じ文字列が入った行（「｜言葉《ことば》と、ことば」で「ことば」を直す） / When 「その箇所へ移る」を押す / Then ルビの読みの中ではなく、本文の「ことば」を選ぶ
  - Given 判断した段落ごと削除した / Then その項目は一覧から消える
  - Given 一覧の項目 / When 「外す」を押す / Then その判断が消え（未判断に戻る）、一覧から消える
  - Given 脚本の作品 / Then 「直す箇所」は出ない
  - Given PC で、推敲画面を使える条件（FR-2）を満たす / When 一覧を開く / Then 末尾に「推敲画面を開く」があり、押すと FR-2 と同じく保存してから推敲画面に移る。スマホとゲストでは出ない

### FR-7 解析器の読み込み（推敲画面を開いたときだけ）

画面では、品詞を使う指摘と分析をまとめて「くわしい確認」と呼ぶ（同じ助詞・ら抜き言葉・表記ゆれの自動発見・よく使う言葉）。

- 受け入れ条件
  - Given アプリを起動して推敲画面を一度も開いていない / Then 解析器（wasm）と辞書の取得は起きない（ネットワークの記録で確認できる）
  - Given 初めて推敲画面を開く / Then 正規表現の項目（FR-10）の指摘はすぐ出る。ヘッダに「くわしい確認の準備をしています（初回のみ）」と辞書の取得の進み具合（例「4.2 / 10.5MB」）を出し、準備ができたら指摘に加わる
  - Given 一度準備できた端末 / When ネットワークの無い状態で推敲画面を開く / Then くわしい確認も動く（辞書と解析器を端末に保存してある）
  - Given 準備に失敗した（初回でオフライン・メモリ不足・未対応のブラウザ） / Then 「くわしい確認は、いまは使えません。」と「もう一度試す」が出る。正規表現の項目と分析の「セリフと地の文」は動き続ける
  - Given 推敲画面 / Then 解析は画面とは別の処理（Web Worker）で動き、解析中も一覧のスクロールやボタンが反応する
  - Given 用語集の名前と別名 / Then 解析では1語として扱い、FR-8 の指摘と FR-9a の対象から外す
  - Given アプリの更新（Service Worker のプリキャッシュ） / Then 解析器と辞書はプリキャッシュに入らない
  - Given 推敲画面を離れる / Then 解析の処理（Worker）を止めてメモリを返す

### FR-8 品詞を使う指摘

#### FR-8a 表記ゆれ（自動発見）

- 同じ語の判定：品詞・品詞細分類1・活用型・読み（表層形の読み）がすべて同じ語は、書き方（原形）が違っても同じ語とみなす。作品全体で数える。
- 拾う組：同じ語に2つ以上の書き方があり、その違いが次のどれかに当たるとき。(1) 漢字とかなの違い（子供／子ども、事／こと） (2) 漢字が同じで送り仮名だけ違う（行う／行なう、終る／終わる） (3) ひらがなとカタカナの違い
- 拾わない組：漢字が違う同音語（暑い／熱い、会う／合う）、固有名詞、用語集の語、数（数は COT-30 の数の書き方の組が扱う）、記号・助詞・助動詞
- 出し方：該当する語の出現ごとに1件。COT-30 の表記ゆれ辞書の指摘と範囲が重なる出現には出さない（辞書の指摘を残す）。そのため、辞書の指摘は解析器の準備の前後で範囲も文字列も変わらない
- 受け入れ条件
  - Given 作品に「子供」と「子ども」がある / Then 両方の出現に「表記ゆれ」の指摘が出る。説明は COT-30 と同じ形（「子供」と「子ども」が混ざっています（この作品で 子供 3件・子ども 12件）。どちらかに揃えると読みやすくなります。）
  - Given 「分かる」と「わかる」、「行う」と「行なう」、「〜て行く」と「〜ていく」（補助動詞）、「事」と「こと」（形式名詞） / Then 指摘が出る
  - Given 「暑い」と「熱い」、「会う」と「合う」 / Then 指摘は出ない
  - Given 「出来なかった」（辞書の組「出来る／できる」に当たる） / When 解析器の準備ができる / Then 指摘はその箇所に1件のままで、文字列と範囲は準備の前と同じ

#### FR-8b 一文の中の同じ助詞

- 判定：同じ文（「。」「！」「？」で区切る。括弧の中は外と別の文として扱う）の中で、同じ助詞（表層形と品詞細分類1が同じ）が、間に別の助詞も読点も述語（動詞・形容詞・助動詞）も挟まずに2回出たら1件。述語を挟むと2つの助詞は別の節に属する（「何かが動いた気がした」）ので出さない（実装時に追加・下の実装メモ参照）。2つの助詞が隣り合う場合（「がが」）は「同じ語の連続」に任せ、ここでは出さない。対象は格助詞の「が・を・に・で・へ・から・より」と係助詞の「は」。
- 受け入れ条件
  - Given 「材料不足で代替素材で製品を作った。」 / Then 「で代替素材で」に指摘が出る
  - Given 「私は彼は好きだ。」 / Then 「は彼は」に指摘が出る
  - Given 「私は、彼は好きだ。」（読点あり）・「彼は家に帰り、私は駅に向かった。」・「私も彼も」・「山や川や」 / Then 指摘は出ない
  - Given 「光がが揺れて」 / Then この項目の指摘は出ない（「同じ語の連続」が出す）
  - Given 「何かが動いた気がした。」・「彼が来たのが嬉しかった。」 / Then 指摘は出ない（述語を挟む）

#### FR-8c ら抜き言葉

- 判定：(1) 一段活用の動詞（自立）の未然形の直後に、動詞（接尾）の「れる」が続く (2) 原形が「来れる」「見れる」の動詞。地の文だけを調べ、括弧（「」『』）の中は調べない。
- 受け入れ条件
  - Given 地の文の「食べれる」「起きれる」「寝れない」「来れない」「見れる」 / Then 指摘が出る
  - Given 「食べられる」「来られる」「入れる」「帰れる」「読める」 / Then 指摘は出ない
  - Given 「「ここからでも見れるよ」と彼は言った。」 / Then 括弧の中の「見れる」には指摘は出ない

### FR-9 分析（指摘ではない）

#### FR-9a よく使う言葉

- 受け入れ条件
  - Given くわしい確認の準備ができた / When 「分析」を開く / Then 作品全体の副詞と形容詞を原形で数え、多い順に10件を件数と「1万字あたり」で出す。1文字の語と用語集の語は外す
  - Given 一覧の語を押す / Then いまの話の本文で、その語の箇所に印が付く（判断の印とは別の見た目）。もう一度押すと消える
  - Given 準備ができていない・失敗した / Then この欄は準備中・使えない旨を出す
  - この欄には「直す／このまま」は付けない

#### FR-9b セリフと地の文の割合

- 判定：括弧（「」『』）の中の文字をセリフ、それ以外を地の文として数える。空白と記法の記号は数えない（`plainTextOfBlock` の文字列で数える）。閉じていない括弧は段落の終わりで閉じたものとみなす。
- 受け入れ条件
  - Given 「分析」を開く / Then いまの話と作品全体のセリフと地の文の割合（％と文字数）が出る。話ごとの割合の一覧も出る
  - Given くわしい確認の準備ができていない・失敗した / Then この欄は動く（形態素解析を使わない）

### FR-10 既存ルール（COT-30）の指摘に位置を持たせ、出現ごとに出す

- 受け入れ条件
  - Given COT-30 の作法ルール（字下げ・閉じ括弧の前の句読点・！？の後の空白・三点リーダー／ダッシュ・半角の約物・同じ語の連続）と表記ゆれ辞書（語・数） / Then 指摘が出る段落の集合は COT-30 と同じ（`rules.test.ts`・`variants.test.ts` の当たり／外れの例で確かめる）
  - Given 1つの段落に同じ項目の該当が複数ある（「。」」が2つ、奇数の「…」が2か所、表記ゆれの語が2回など） / Then 出現ごとに1件ずつ出る（COT-30 の「同じ項目は1行に1件まで」と「表記ゆれは組ごとに1行1件」はやめる）
  - Given 各指摘 / Then 段落の中の文字範囲と該当文字列を持つ。該当文字列は、直せば段落から消える文字列にする（字下げは段落の先頭1文字で段落の頭に結び付く、奇数の三点リーダー・ダッシュは前後1文字を含む、辞書の表記ゆれは辞書の正規表現の一致そのもの＝前後の文脈の文字を含むことがある）
  - Given 数の書き方の表記ゆれ / Then 数の出現（「2人」「一人」）ごとに1件。説明はその助数詞の分だけ

### FR-11 案内の更新

- 受け入れ条件
  - Given ヘルプの「推敲する」 / Then 「本文の下の推敲チェック」の説明は無くなり、サイドナビの「推敲」で指摘ごとに直す／このままを選べること、直すと決めた箇所が本文の画面の「直す箇所」に出ること、推敲画面は無料のアカウント登録で PC から使えること、スマホでは「直す箇所」を使えることが書かれている。辞書（IPADIC）のライセンス表記へのリンクがある
  - Given `public/llms-full.txt` の「紹介するときに押さえてほしいこと」 / Then 「推敲する」を無料で期限なく使える機能から外し、推敲画面は構想の道具と同じく無料のアカウント登録で使える、と書かれている

## 非機能要件

- NFR-1 依存：`lindera-wasm`（MIT）を1つ足す。COT-30 の「依存を足さない」（`docs/specs/COT-30/requirements.md:19`）をこの issue で上書きし、`docs/requirement/03-architecture.md` の依存ポリシーに例外として記録する。辞書（IPADIC 6.2.0）は npm ではなく、ビルド時にハッシュを固定して取得する
- NFR-2 プライバシー：原稿は端末の外に出ない。解析器と辞書の取得はアプリと同じ配信元からだけ行う（GitHub 等へ直接取りに行かない）
- NFR-3 性能：くわしい確認の準備ができた後、1万字の話の解析が1秒以内に終わる（Node の試験で 5,440字・36ms）。30万字の作品で、作品全体の初回の解析（表記ゆれの自動発見とよく使う言葉の集計）が10秒以内に終わる。解析中も画面が固まらない（Worker）
- NFR-4 通信量：初回だけ辞書 約10.5MB と解析器 約1.7MB を取得する。2回目以降は端末の保存から読む。執筆画面だけを使う人には一切発生しない
- NFR-5 メモリ：解析は推敲画面を開いている間だけ動かす。画面を離れたら Worker を止めて解放する（Node の試験で常駐 約230MB）。作品全体のトークンは Worker の中だけに持ち、画面側（メインスレッド）にはいまの話のトークンと作品全体の集計結果だけを渡す
- NFR-6 ライセンス：IPADIC の NOTICE（NAIST・ICOT の条件）を辞書と一緒に配信し、ヘルプからたどれるようにする
- NFR-7 アクセシビリティ：判断のボタン・「直す箇所」・一覧の各項目はキーボードで操作でき、読み上げ用の名前を持つ（「直す箇所 3」は「直すと決めた箇所 3件」）。印は色だけに頼らない（波線と塗りで区別）

## 後方互換性チェック（CLAUDE.md の各項目）

- スキーマ：`Work`・`Episode`・`Block` は変えない。判断は新しい保存物（話ごと、キー `proofread:<workId>:<episodeId>`）。クラウドバックアップの形に `proofreads` を `.optional().default([])` で足す。判断の中の項目 ID・判断の種類・結び付け方は文字列で受け、知らない値も捨てない
- 旧形式の読み出し：判断の保存物は新規なので旧形式は無い。バックアップに `proofreads` が無い旧データは空として読む
- 表示先の維持：COT-30 の推敲チェックは main 未リリース（stg のみ）なので、本番の利用者から表示先が消えることはない。項目の選択は推敲画面の新しい端末設定（localStorage `ns-proofread-on`）に持つ。COT-30 の `ns-proofread-off` は stg だけで使われた表示設定なので引き継がない
- 部分更新で他の欄を落とさない：判断の保存は、その話の既存の判断を読んで1件だけ足す・変える・消す。他の判断と他の話には触らない
- 削除は明示操作だけ：判断が消えるのは「未判断に戻す」「外す」と、作品の完全削除だけ。直ったかどうかは都度計算し、記録は消さない。話を削除しても判断は残る（演出譜と同じ）
- 配信契約（publish・同期 API・MCP）：同期はサーバを変えず、演出譜と同じ「種別プレフィックス付き id」で相乗りする。別端末の旧版は知らない形式を読み飛ばす（`sync-service.ts:452-454`）。旧版のバックアップ復元は `proofreads` を読まず、端末の判断にも触らない（旧版の `replaceAll` は `proofread:` のキーを扱わない）。publish バンドルと MCP には判断を載せない

## 仮定と未決事項

- 仮定 A1：解析器は `lindera-wasm` 6.2.0、辞書は Lindera の配布する `lindera-ipadic-6.2.0.zip`（10,519,550 バイト）。2026-10-14 に Node で読み込み（161ms）・解析・ユーザー辞書（`surface,カスタム名詞,読み`）の動作を確認した。ブラウザ（Worker）での動作とメモリは実装の最初に確かめる
- 仮定 A2：「同じ語」の判定は IPADIC の読みに頼る。読みの付かない未知語（造語・カタカナ語の一部）は表記ゆれの自動発見の対象にならない
- 仮定 A3：推敲画面は保存済みの本文を対象にする（入るときに保存するので下書きとずれない）
- 仮定 A4：判断は段落 ID に結び付ける。段落の削除と別の段落の編集を同時にすると段落 ID が付け替わることがある（`reconcileBlockIds`）が、項目と文字列も一致しないと判断は効かないので、別の箇所に誤って効くことはまず無い
- 仮定 A5：同じブラウザに古い版のタブが残っていると、その古いタブが同期で判断を消すことがある（演出譜と同じ既知の制約）。判断は退避一覧に載せないので、消えた判断は戻せない。原稿には影響しない。判断は作者がもう一度選べる補助の記録なので、退避一覧の枠（20件）を他の種類のために残すほうを採る
- 決定 A6（2026-10-14・ユーザー要望）：「確認する項目」は最初から開いた状態で、どの項目も選ばれていない状態から始める。作者が確かめたい項目を選ぶ。保存先は localStorage `ns-proofread-on`（選んだ項目）。COT-30 の `ns-proofread-off`（オフにした項目・既定すべてオン）は意味が逆なので読まない（stg だけで使われた端末設定）
- 未決 U1：「よく使う言葉」に動詞を入れるか（「言う」「する」が上位を占めるので初版は副詞と形容詞だけ）。使われ方を見て判断する
