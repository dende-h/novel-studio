# 掲示板の通知とイベントの仕様案

2026年11月26日。掲示板を開いていない間の新着に気づけるようにし、利用者がお題や交流会を立てて、期間を確認しながら参加できるようにする。今ある掲示板の公開閲覧、記名投稿、返信、通報を土台にする。

## 掲示板の通知

### 画面と通知対象

- ログイン中の共通ヘッダーにベルを置く。未読のあるスレッド数をバッジで表示する。同じスレッドの新着が複数あっても一覧では1行にまとめ、上限表示は `99+`。通知がないときはベルだけを表示する。集中モードのヘッダーは現行どおり隠れる。
- ベルを押すと、デスクトップではヘッダーから一覧、モバイルでは画面に収まるパネルを開く。各行はスレッド名、新着の種類、投稿者の表示名、時刻を表示する。本文の抜粋は載せない。選ぶと該当スレッドと投稿へ移動する。「すべて既読」「通知設定」「掲示板へ」も置く。
- 既定の「掲示板の新着」では、ほかの人が立てた公開スレッドと、ほかの人による公開返信を知らせる。通知対象は「設定 → 通知」で「掲示板の新着」「自分に関係する新着」「オフ」から選ぶ。関係するものは自分のスレッド／書き込んだスレッドへの新着、自分の投稿への返信、参加中イベントの日時変更・中止。重なる場合も1件にする。
- 自分が行った操作、いいね、投票、投稿の編集、通報、非表示・削除済みの内容は通知対象から除く。イベント公開は新規スレッドとして通知する。日時変更・中止は参加者に通知する。単なる参加・取り消しは参加者一覧にだけ反映する。
- 未ログインでも掲示板とイベントを閲覧できる。ベルと通知設定はアカウントに紐づける。通知はLeaf内の画面表示のみ。音なしで、ブラウザの通知権限も使わない。

### サイレントモード

- サイドバーの「通知を24時間オフ」で、すべてのアプリ内通知表示を一時停止する。ヘッダーのベルとバッジ、開いている通知一覧、掲示板内の未読バッジをすぐに隠す。イベントの日時変更・中止の通知も対象に含める。
- 停止中はサイドバーの同じ場所に「通知を再開」を表示する。終了日時はその操作の横にだけ表示する。オンにした時点から24時間で自動解除し、途中でも「通知を再開」で解除できる。停止状態と終了時刻は同じアカウントの端末に反映する。
- 停止中の新着は履歴に残し、停止操作では既読にしない。再開時は、「設定 → 通知」で選んでいた通知対象に従って未読を表示する。掲示板を自分で開いて読んだ投稿は通常どおり既読になる。
- 開いている画面では終了時刻に通知を再取得する。再読み込みや画面への復帰時にも再確認する。停止前から進行していた取得の応答でバッジを戻さない。停止・再開の保存が失敗した場合は元の状態に戻し、操作箇所で失敗を伝える。

### 未読の数え方

- 初めて通知を有効にした時点より後を対象にする。掲示板一覧やベルを開いただけでは既読にしない。通知から移動した先や通常の掲示板から開いた先で、該当スレッドの内容を正常に表示できたら、表示した範囲まで既読にする。既存の `#/board/<threadId>` に任意の `?post=<seq>` を加え、一覧外なら対象投稿を含むページを取得する。
- 既読はアカウント単位で保存する。スレッド別の投稿・イベント変更の読み取り位置と「すべて既読」の位置を持ち、より大きい位置だけを保存する。「すべて既読」は画面に返した一覧の上限までを対象とし、別端末の古い操作や表示後に来た新着で位置が戻ったり先に進みすぎたりしない。
- 非表示または削除になった投稿は未読・一覧から外す。スレッドごと非表示になった場合も同様。非表示解除後は過去の新着として扱い、既読位置より後にある場合だけ再表示する。既読の通知履歴と未読は状態を区別して表示し、当面は直近30日分を表示対象とする。
- ログイン時とアプリが前面に戻ったときに取得し、前面にいる間は約60秒ごとに通知の設定・バッジを更新する。サイレントモード中の定期取得はモード状態だけに絞る。ベルを開いたら一覧を取得する。非表示タブは定期取得を止める。切断時は直近表示を維持し、失敗をきっかけに既読にしない。アカウント切り替え時は前のアカウントの表示と応答を破棄する。

### 実装

現行の未読は掲示板内の「自分の書き込み」タブにあり、端末の `ns-board-seen` と `bumpedAt` で推定する。新設後は同じ通知結果を掲示板内でも使い、共通ヘッダーと掲示板で別々に既読を管理しない。「自分の書き込み」は投稿履歴の入口として残す。[掲示板の既存仕様](../requirement/09-board.md) · [既存バッジ](../../src/ui/components/BoardPage/board-page.tsx) · [共通ヘッダー](../../src/ui/components/AppShell/app-shell.tsx)

| 対象 | 実装 |
| --- | --- |
| 新着の記録 | D1に単調増加ID付きの `board_activity`。投稿・返信は `post_id` 単位で一意に記録。レコードには時刻・スレッドID・投稿ID（あれば）・行為者ID・種類を持たせ、表示名とスレッド名は取得時に結合する。投稿と新着は同じD1バッチで確定する。イベントの日時変更・中止も設定更新と同じバッチに入れる。 |
| 状態の保存 | `board_notification_state` にユーザーごとの通知対象・全体の既読位置・サイレントモードの終了時刻 `silent_until`（epoch ms、解除時は `null`）を保存する。`board_thread_reads` に投稿とイベント変更それぞれの既読位置（`user_id, thread_id` を一意にする）。古い返信ページに最新のイベントカードが出ても、未表示の新しい返信を既読にしない。別途アカウント別の通知コピーを作らず、共通の新着から閲覧可能な行を抽出する。 |
| API | `GET /api/board/notifications?summary=1` で件数、`GET /api/board/notifications` で一覧と既読用の上限。`POST /api/board/notifications/read` は全体またはスレッド単位の確認済み上限を、サーバーが発行したアカウント・画面範囲に紐づく値で受け取る。`PUT /api/board/notifications/settings` は通知対象の設定更新。`PUT /api/board/notifications/silent` で24時間停止、`DELETE` で途中解除。概要APIは停止中も `silentUntil` とサーバー時刻を返し、未読の集計と通知一覧の取得は省く。一覧・概要・各操作はサーバー時刻でモードの有効性を判定する。スレッド詳細APIは表示した投稿・イベント状態に対応する上限を返す。既存のClerk認証と非キャッシュレスポンスを使う。 |
| 読取と描画 | `Root` 側でアカウントごとの状態を保持し、既存の `TopAppBar` にベルを付け、`SideNav` にサイレントモードの切り替えを置く。設定画面では通知対象を変更できる。DBで期間、閲覧可否、関係の有無、既読位置を条件にする。スレッド当たり最新の未読を優先し、最新順にページを取得する。30日を超えた活動の削除は初期実装の前提にせず、件数を計測して保管期間を決める。 |

通知対象を算出するとき、他の人が直後に書いた返信を自分の返信や更新時刻で打ち消さない。参加や自分の投稿を起点に関係対象へ切り替わった場合は、その時点より後の新着を数える。設定画面の「オフ」から有効に戻したときは再有効化時点から始める。通知用の一覧、既読更新、参加のAPIではアカウントIDをクライアントの値から受け取らず認証結果で確定する。

## イベント

### 開催・参加の画面

掲示板に「イベント」を追加する。「イベントを作る」で空欄から始めるか、「お題で書く」「感想交換」「執筆会」のひな形を選ぶ。ひな形は説明欄に編集可能な案を入れる。開催者が入力するのはタイトル、説明、開始日時、終了日時。開始は「今すぐ」を選択できる。公開後はイベント固有の共有URLを使える。

イベントは掲示板スレッドとして表示する。スレッド冒頭に日付、状態、開催者、参加人数、「参加する」ボタンを置き、説明の下に参加者と掲示板の返信を並べる。作品は、参加時または参加後に公開作品のURLを任意で1件登録できる。本文・Leafの非公開作品・連絡先へのアクセスは発生させない。参加情報の公開範囲（掲示板のペンネームと任意で登録するリンク）はボタンのそばに示す。

| 状態 | 表示と操作 |
| --- | --- |
| 開催前 | 「開催前」、開始と終了。公開時点から参加・参加取り消しができる。 |
| 開催中 | 「開催中」、終了日時と残り時間。終了時刻の前まで参加・取り消し・作品URL変更ができる。 |
| 終了 | 「終了」。参加・URL変更は締め切り、参加結果とスレッドを閲覧できる。自分の作品URLの削除と参加の公開表示の取り下げができる。 |
| 中止 | 「中止」。新規参加を停止し、説明と中止のお知らせを残す。既存の参加者は作品URLの削除と参加取り消しができる。 |

日時は入力・表示とも日本時間（JST）を明示し、D1はepoch msで保存する。開始 < 終了が必須。「今すぐ」の開始はサーバー時刻。予約した開始と終了の比較・参加可否はサーバー側の時刻で判定する。`now < 開始` は開催前、`開始 ≤ now < 終了` は開催中、`終了 ≤ now` は終了。状態を切り替える定期ジョブは不要。開始前は開始・終了を変更でき、開始後は終了を将来の時刻に変更できる。終了時刻に達したイベントは再開・中止ができない。中止は開催前か開催中に、主催者または運営が確定する。中止した企画をやり直す場合は、新しいイベントを立てる。

- 一覧は「開催中」「開催前」「終了・中止」。開催中は終了が近い順、開催前は開始が近い順、終了・中止は最近のものから表示する。自分が参加したイベントに絞る選択肢を置く。
- 無料のログイン済みユーザーが、掲示板のペンネームを設定して開催・参加できる。1人1イベント1参加。主催者も参加ボタンを押した場合に数える。主催者は内容・期間の編集と中止、運営は既存のモデレーションからスレッドの非表示・ロックと参加リンクの非表示ができる。投稿禁止中は新規開催・参加・リンク変更を制限し、本人の参加取り消しとリンク削除は可能とする。終了・中止後の取り下げは公開の参加人数にも反映する。
- 作品URLは認証情報を含まないHTTP(S)のみ受け付け、登録時に本文を取得せず、ホスト名の分かるリンクとして表示する。コトノハ-grove-の公開作品や他サイトの作品を選べる。参加者表示は通常投稿と同様に現在のペンネームを使う。退会済み・非表示の参加行は公開一覧と人数から除く。
- 運営が作品URLを非表示にすると、同じ参加者の同じ正規化済みURLが対象になる。本人がそのURLを削除すると公開リンクと本人向けの非表示表示が消える。受付中に別のURLへ変更しても、元のURLの非表示は引き継がない。参加を取り消して再参加した場合も、登録先のURLごとに判定する。同じURLを登録し直したときは、運営が解除するまで非表示を維持する。
- 文面の作り方や参加方法の参考。カクヨムは作品単位で登録し、ノベルアップ＋は指定タグを使う。Leafでは作品URLがなくても「参加する」で参加登録できる。[カクヨムの自主企画](https://kakuyomu.jp/help/entry/user_events) · [ノベルアップ＋の自主企画](https://novelup.plus/help/category/user-event)


### SNSでの共有

- イベント詳細と作成完了画面に「共有」を置く。共有メニューには「リンクをコピー」を常に表示する。端末の共有メニューが使える場合は、企画名・開催期間・共有URLを渡す。コピーもできない環境ではURLを選択してコピーできるようにする。[端末の共有メニュー](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share)
- 本番の共有URLはイベントごとに固定の `https://cotonoha-leaf.org/events/<threadId>` とする。ステージングの共有URLは `https://stg.novel-studio-b2m.pages.dev/events/<threadId>` とする。訪問者はログインせずにタイトル、説明、開催期間（JST）、受付状況を確認できる。「イベントを見る」で掲示板の該当スレッドに入り、返信も閲覧できる。「参加する」「返信する」でログインやペンネーム設定が必要になった場合は、完了後に同じイベントの操作へ戻す。参加・投稿は本人が確定する。
- SNSに貼ったときは、企画名、開催期間、Leafの共通画像をカードに表示する。カードには参加者名、返信、参加者の作品URLを載せない。日程変更・終了・中止後もURLは維持し、リンク先で最新状態を表示する。削除・非表示になったイベントのURLは `404` とし、企画名などを含まない案内を返す。SNS側に保存された過去のカードは更新に時間がかかる場合がある。[Open Graphの仕様](https://ogp.me/)

### ゲスト投稿の検討

初回は、SNSから来たゲストにも企画の詳細と返信を公開し、参加登録と書き込みは無料アカウントと掲示板のペンネームで行う案を推奨する。匿名の書き込みは参加のハードルを下げる一方、SNSから誰でも来られる場では、なりすましや連投への対処、投稿者本人による削除、通知バッジに載る新着の管理が難しくなる。

公開後は、共有ページから参加ボタンまで進んだ割合、ログイン後に参加を完了した割合、参加の手間に関する声を見て判断する。ログインが障害だと分かった場合の試行案は、主催者が有効にしたイベントへのゲスト返信だけを対象にする方式。ゲスト表示、投稿回数の制限、公開前の承認を設けて、参加しやすさと運用負担を確かめる。掲示板全体へのゲスト投稿を開放するかは検討事項として残す。

### 実装

| 対象 | 実装 |
| --- | --- |
| スレッド | 既存の `BoardKind` に `event` を追加し、本文・返信・通報は同じスレッドを使う。`board_events`（`thread_id` 主キー）に `starts_at`、`ends_at`、`cancelled_at`、`updated_at` を持つ。作成時のスレッド、本文、イベント行、新着を一つのD1バッチに入れる。作成リクエストIDを主催者単位で一意にし、応答が途切れて再試行しても同じイベントを返す。 |
| 参加 | `board_event_participants`（`thread_id, user_id` を一意）に参加時刻・任意のURL・参加取り消しとモデレーション状態を保存する。参加は対象イベントが公開かつ受付中であることを含む条件付きINSERT／UPDATE。二重送信でも人数が増えず、参加と中止・締切が競合してもDBで決まる。人数は有効な参加行から集計する。 |
| APIと権限 | 既存のスレッド作成・詳細・一覧にイベント情報を追加。`PATCH /api/board/events?thread=…` で日時・中止、`PUT /api/board/events/participation?thread=…` で参加／URL更新、`DELETE` で本人の参加取り消し。参加者一覧はページ化し、自分の参加状態・参加人数はスレッド詳細に返す。認証・投稿制限の既存経路を再利用する。参加リンクの通報は、既存の通報画面とキューに参加行を対象として追加する。 |
| 共有URL | Pages Functions の `GET /events/<threadId>` で公開されているイベント情報を取得し、Open Graph・Xカードのメタデータを含むHTMLと、`/#/board/<threadId>` へのリンクを返す。共有URL、canonical、OGPのURL・画像、Xカードの画像は、本番では正規ドメイン、固定のステージングホストではステージングのドメインで生成する。未公開・非表示・削除の判定は掲示板と共用する。公開ページには閲覧者ごとの情報を含めず、企画名・説明などの入力はHTML用にエスケープする。 |
| 削除と非表示 | 一般参加者がいる公開イベントを主催者が取り下げるときは中止にする。運営による非表示は、イベント一覧・通知・参加者一覧のすべてに反映する。完全削除や退会の既存処理を確認し、追加行の参照と公開表示も同じ経路で処理する。 |

## 実装順と受け入れ条件

1. **通知の初回**は新着記録、ベル、一覧、通知設定、サイレントモード、スレッドへ移動、既読同期。ほかの人が投稿したら次回更新でバッジが付き、自分の投稿、非表示・削除済みの投稿、ログアウト後の状態からは付かない。複数端末で既読が一致する。複数投稿・同時刻・同じスレッド・一覧のページ境界・確認直前の新着をテストする。サイレントモードは即時の表示消去、再読み込み・別端末での設定反映、24時間後の自動解除、途中解除、解除後の未読復帰、通知対象の設定が「オフ」の場合をテストする。
2. **イベントの初回**は作成、公開一覧、開催前・開催中・終了・中止、参加・取り消し、任意の作品URL、SNS向け共有URL、参加者への日程変更・中止の通知。既存の掲示板から開催・参加・返信ができる。JSTの日付またぎ、開始時刻と締切一致、同時参加、二重クリック、中止と参加の競合、運営非表示を確認する。共有URLは未ログインでの閲覧、SNS向けHTML、端末共有とコピー、ログイン後の復帰、終了・中止後の表示、非表示後の `404` を確認する。
3. **次の候補**は、よく使う企画の複製、開催前のリマインド、個別スレッドのフォローとミュート。初回はお題のひな形と参加ボタンで企画を回せる状態を優先する。最初の運用例は「週末の千字小説」とし、外部に投稿した作品も任意のURLで持ち寄れる。


## 反映時の確認

- D1 の `0001`〜`0015` が適用済みの環境に `0016_board_notifications_events.sql`、`0017_board_event_link_moderation.sql` の順で適用してから Pages を更新する。既存の書き込みから通知履歴は作らない。
- 作品URLの非表示は参加者と正規化済みURLの組み合わせで保持する。同じURLを削除して登録し直しても非表示を維持し、別のURLには引き継がない。移行時点で非表示のURLと通報記録を保持する。
- 実際の Clerk 退会を掲示板に反映するには、環境ごとの Clerk で `user.deleted` を Leaf の `/api/webhooks/clerk` へ配信し、そのエンドポイントの署名シークレットを Pages の `CLERK_WEBHOOK_SECRET` に設定する。退会した人のペンネームは伏せ、公開参加と本人の通知状態を削除する。
