# 要件定義 — COT-30 小説の推敲チェック（表記ゆれと原稿の作法）

## 背景と目的

小説（通常モード）を書く利用者が、脱稿前の推敲で「原稿の作法」と「表記ゆれ」を自分で確認したい。
いまアプリ内で機械的な確認ができるのは脚本モードの書式チェックだけで（`src/core/script/proofread.ts:36`・表示は `src/ui/components/EditorPane/editor-pane.tsx:413-443`）、小説の作法ルールは `tools/novel-textlint/` にあるがアプリの外にあり、利用者は使えない。
脚本と同じ見せ方で小説にも確認候補を出し、候補を押すと該当行へ飛べるようにする。AI にも外部にも原稿を出さず、端末の中だけで完結させる。

## 機能要件

### FR-1 小説のエディタに「推敲チェック」を出す

- 受け入れ条件
  - Given 形式が小説の作品で話を開いている / When 本文を表示する / Then エディタ下部に「推敲チェック（確認候補 N件）」の `<details>` が出る。N はオンの項目で見つかった候補の数
  - Given 形式が脚本の作品 / When 本文を表示する / Then 従来の「脚本の書式チェック」が出て、推敲チェックは出ない（脚本の挙動は変わらない）
  - Given 本文が空 / Then 「推敲チェック（確認候補 0件）」と出て一覧は空。例外は出ない
  - Given 候補が 0 件 / Then 一覧は空で、説明文だけ出る
  - Given モバイル（lg 未満）で「本文」の面を開いている / Then 同じ `<details>` が本文の下に出る。textarea にフォーカスしている間は記法バー（`fixed`・`notation-bar.tsx:24`）が下端を覆うので、候補を見るには一度本文の外を押す（現状の脚本と同じ。`screens/editor-script-mobile.png` は本文の外を押した状態）
  - Given ゲスト・無料・有料のどの状態でも / Then 同じように使える（脚本の書式チェックと同じく会員判定なし）

### FR-2 原稿の作法ルール（純 TS）

本文を行（block）ごとに検査する。対象文字列は記法を解いたプレーン文字列（ルビは親文字、傍点は本文、`[[参照]]` は名前）。空行と空白だけの行は検査しない。

| 項目ID | 名前 | 検出 | メッセージ（案） |
|---|---|---|---|
| `indent` | 字下げ | 行頭が全角空白でも開き括弧でもない。許可する行頭文字は `　「『【〈《（(“"‘'［[〔｛{—…―–＊｜`（`.textlintrc.novel.json` と同じ。`＊` は場面転換、`｜`・`《` はルビ・傍点、`[` は参照） | 段落の頭は全角空白を1つ空けるのが一般的です。会話文（「）はそのままで構いません。 |
| `punct-before-close` | 閉じ括弧の前の句読点 | `[。、][」』）]` | 閉じ括弧の前の句読点（。、）は付けないのが一般的です。 |
| `space-after-exclamation` | ！？の後の全角空白 | `[！？]` の直後が、全角空白・半角空白・`！？`・三点リーダー `…`・ダッシュ `―`・閉じ括弧（`」』）〕】〉》`）・行末のどれでもない | 「！」「？」の後ろは全角空白を1つ空けるのが一般的です。閉じ括弧の前は要りません。 |
| `leader-odd` | 三点リーダー・ダッシュ | `…` の連続が奇数個 / `―` の連続が奇数個 / `・` が 2 つ以上連続 | 三点リーダー（…）は2つ単位（……）で使うのが一般的です。／ ダッシュ（―）は2つ単位（――）で使うのが一般的です。／ 中黒（・・・）ではなく三点リーダー（……）を使うのが一般的です。 |
| `halfwidth-punct` | 半角の約物 | 日本語の文字（ひらがな・カタカナ・漢字・々・ー）に隣接する半角 `!?` または `,.` | 和文では感嘆符・疑問符は全角（！ ？）を使います。／ 和文では句読点（、 。）を使います。 |
| `successive-word` | 同じ語の連続 | (a) 助詞 1 文字の重複 `がが／をを／でで／にに／とと／のの`。ただし常用語に当たる並びは直前・直後で外す：`ものの`（もの＋の）、`ひとと`・`っとと`（人と・ちょっと）、`なにに`（何に）、`までで`（まで＋で）、`とともに`。`はは・もも・ねね・ここ・へへ` は語なので対象外 (b) 2〜6 文字の同じ文字列が隣り合い、その文字列に漢字が 1 文字以上含まれる（例「言った言った」「今日は今日は」）。ひらがな・カタカナだけの繰り返し（どきどき・ますます・ところどころ）は擬音・畳語なので対象外 | 同じ語が続いています（がが）。打ち間違いでなければ、そのままで構いません。（括弧内は当たった文字列） |

- 受け入れ条件
  - Given `tools/novel-textlint/fixtures/novel-good.txt` の本文 / When 検査する / Then 候補は 0 件（ルビ `｜宮森《みやもり》`・傍点 `《《だれかいる》》`・`＊`・「待って！　すぐ終わるから」を誤検知しない）
  - Given `fixtures/novel-bad.txt` の本文 / Then 2 行目 `punct-before-close`、3 行目 `indent`、4 行目 `halfwidth-punct`、7 行目 `successive-word`（がが）と `leader-odd`（…1つ）が出る。AI 常套句の行（5・6 行目）は出ない
  - Given 行頭が `[[宮森]]` や `＊` や `……` / Then `indent` は出ない
  - Given 「待って！」（行末）、「待って！」（閉じ括弧前）、「！？」、「待って！……」、「嘘だ！――」 / Then `space-after-exclamation` は出ない
  - Given 「ものの」「ひとと目が合った」「なにに使う」「までで良い」「彼とともに」「どきどき」「どきどき胸が」「ますます強く」「きらきら光る」「ところどころ」 / Then `successive-word` は出ない。Given 「言った言った」「今日は今日は」「光がが」 / Then 出る
  - Given 同じ行に複数の項目が当たる / Then 項目ごとに 1 件ずつ出る（同じ項目は 1 行に 1 件まで）
  - Given 本文を変えない / Then 検査は入力の `Block[]` を書き換えない（`proofread.test.ts:6-12` と同じ固定）

### FR-3 記法を誤検知しない

- 受け入れ条件
  - Given `｜親《よみ》`・`《《傍点》》`・`[[参照]]`・`[[｜言葉《ことば》]]` を含む行 / Then 記法の記号（`｜《》[]`）が原因の候補は出ない。検査はプレーン文字列に対して行う

### FR-4 表記ゆれ（作品全体で数え、いまの話の行を候補にする）

- 組み込み辞書（初版・`src/core/proofread/variants.ts`）。1 組＝同じ語の書き方の集合。各書き方は「表示名＋正規表現」で定義し、活用語は語幹で、「事・時・所・物・様・位」のように熟語に化ける字は前後の文脈（直前の活用語尾や直後の助詞）で縛る。熟語は除外パターンで外す。組の一覧は design.md「表記ゆれ辞書（初版）」に置く（出来る／できる、事／こと、時／とき、言う／いう、ている／て居る、ない／無い、ため／為、よう／様、くらい／位、まで／迄、ほど／程、さらに／更に、すでに／既に、すべて／全て、ちょうど／丁度、あなた／貴方、子ども／子供、きれい／綺麗、たくさん／沢山、さすが／流石、ところ／所、もの／物、いただく／頂く、ください／下さい、いたす／致す、ある／有る、よい／良い／いい、僕たち／僕達、私たち／私達、彼ら／彼等、とにかく／兎に角、どこ／何処、なぜ／何故、ぜひ／是非、ほとんど／殆ど、しばらく／暫く、ますます／益々、だんだん／段々、やはり／矢張り、ちょっと／一寸、めったに／滅多に）
- 数の書き方：助数詞ごとに別の組にする（`numeral:人`・`numeral:年` …）。各組で `[0-9０-９]+`＋助数詞 を「算用」、`[一二三四五六七八九十百千]+`＋助数詞 を「漢数字」として数え、同じ助数詞で両方あるときだけ候補にする（「2026年」と「一人」のように助数詞が違う使い分けは拾わない）。助数詞＝人・つ・日・年・月・回・本・枚・匹・個・歳・時・分・階・度・番・台・冊・杯・件・名・歩・秒。数詞でない熟語（十分（じゅうぶん）・何分・数分・大分・半分・随分・当分・多分・自分・気分・一時的・三分の一 のような分数）は除外する。1 行に数の組が複数当たるときは 1 件にまとめる
- 受け入れ条件
  - Given 作品に「出来る」と「できる」が両方ある / When いまの話に「出来る」の行がある / Then その行が候補になり、メッセージは「「出来る」と「できる」が混ざっています（この作品で 出来る 3件・できる 12件）。どちらかに揃えると読みやすくなります。」の形
  - Given 作品全体で 1 つの書き方しか使っていない / Then 候補は出ない（統一されている語は拾わない）
  - Given いまの話にはどちらも無いが、他の話で混ざっている / Then いまの話では候補は出ない（飛び先が無いため）
  - Given いまの話を編集中で未保存 / Then 件数はいまの話は編集中の本文、他の話は保存済みの本文で数える
  - Given 「仕事」「事件」 / Then 「事／こと」の候補は出ない（除外パターン）
  - Given 「2人」と「三人」が作品にある / Then 数の書き方の候補が出る。メッセージは「数の書き方が算用数字と漢数字で混ざっています：人（2人・三人／算用 4件・漢数字 2件）。」の形。同じ行に「年」の混在もあれば「人（…）・年（…）」と 1 件にまとめる
  - Given 作品に「2026年」と「一人」しかない / Then 数の書き方の候補は出ない（助数詞が違う）
  - Given 「十分に休んだ」「三分の一」「自分」 / Then 数の書き方には数えない
  - Given 「飛んできた」「急いできた」「仲良く」「彼らしい」「書いたし」「聞いたして」「泣いたせいで」「聞いたすぐ後」 / Then 出来る／できる・良い／よい・彼ら／彼等・いたす／致す の候補は出ない（辞書の文脈条件）。Given 「できた」と「出来た」、「お願いいたします」と「致します」 / Then それぞれ候補が出る
  - Given 「動くことが」と「動く事が」 / Then 事／こと の候補が出る（五段動詞の終止形の後ろも数える）
  - Given 1 行に同じ組の語が複数回ある / Then その組につき 1 行 1 件
  - Given 100 話・各 1 万字の作品 / Then 他の話の集計は話ごとにキャッシュし、自動保存（編集静止 800ms ごと）で `work.episodes` が作り直されても、編集していない話の集計は再計算しない。入力のたびに再計算するのはいまの話の分だけ（体感で入力が引っかからない）

### FR-5 候補を押すと該当行を選択する

- 受け入れ条件
  - Given 候補一覧 / When 「N行：…」を押す / Then textarea にフォーカスし、N 行目の全体が選択される（脚本と同じ `setSelectionRange`）
  - Given モバイル / Then 同じ。フォーカスで記法バーが出て一覧が隠れるのは現状の脚本と同じ（FR-1 参照）

### FR-6 項目ごとにオン／オフ

- 受け入れ条件
  - Given 推敲チェックを開いている / Then 「確認する項目」として 7 つの切替（字下げ／閉じ括弧の前の句読点／！？の後の空白／三点リーダー・ダッシュ／半角の約物／同じ語の連続／表記ゆれ）が並ぶ。既定はすべてオン
  - When 項目をオフにする / Then その項目の候補が一覧から消え、見出しの件数も減る
  - Given 別の作品を開く・再読み込みする / Then オン／オフは保たれる（localStorage `ns-proofread-off`）
  - Given localStorage が使えない（プライベートモード） / Then すべてオンとして動き、切替は再読み込みまでの間だけ効く。例外は出ない
  - 切替は `aria-pressed` 付きのボタン。1 つ 44px 以上の高さ（既存の候補ボタン `min-h-11` と同じ）

## 非機能要件

- NFR-1 新しい依存を足さない。ルールは `src/core/proofread/` の純 TS
- NFR-2 ネットワークを使わない。原稿は端末の外に出ない
- NFR-3 誤検知した候補をそのままにしても、保存・書き出し・公開のどれも止めない（候補は助言であり制約ではない。`proofread.ts:35` と同じ方針）
- NFR-4 候補の計算は同期で、いまの話 1 万字で体感の遅れがない（脚本の書式チェックが入力のたびに `useMemo` で走っている現状と同程度）
- NFR-5 アクセシビリティ：候補・切替はすべてボタン。色だけで状態を伝えない（`aria-pressed`）

## 後方互換性チェック（CLAUDE.md の各項目）

- スキーマ：変更なし。`Work`・`Episode`・`Block` に欄を足さない。設定は localStorage
- 旧形式の読み出し：該当なし（読み取り専用の純関数。`sceneBreak` の旧ブロックは `BlockSchema` の preprocess で空段落になるので検査対象外）
- 表示先の維持：既存の「脚本の書式チェック」の表示は変えない。小説の `<details>` は新規追加
- 部分更新で他の欄を落とさない：該当なし（本文を書き換えない。候補を押しても選択するだけ）
- 削除は明示操作だけ：該当なし
- 配信契約（publish・同期 API・MCP）：変更なし。候補は保存物に入らない

## 仮定と未決事項

- 仮定 A1：オン／オフは端末単位（localStorage）で、作品や同期には乗せない。表示の好みであり、テーマ設定と同じ扱い。作品単位にしたい要望が出たら `Work` に optional 欄を足す
- 仮定 A2：表記ゆれは組み込み辞書と数の書き方だけ。利用者定義の組は次段
- 仮定 A3：「同じ語の連続」は形態素解析なしの近似。擬音・畳語を拾わないよう、かなだけの繰り返しは対象外。助詞の重複は常用語（ものの・ひとと・なにに・までで・とともに）を個別に外す
- 仮定 A4：表記ゆれの集計範囲は「作品全体」、候補の表示は「いまの話」。ほかの話の該当行には飛べない（その話を開けば出る）
- 仮定 A5：脚本モードの表示には項目オン／オフを付けない（issue の対象は小説）
- 未決 U1：表記ゆれ辞書の初期語彙は上記で始めるが、利用者の作風（旧仮名・時代物）で誤検知が増える組があれば外す。リリース後に判断

## 対象外

- AI 常套句の検出、形態素解析による厳密な連続語検出、利用者定義の表記ゆれ組、連続句読点・長音・マイナス記号のルール、脚本モードへの項目オン／オフ、本文の自動修正（`--fix` 相当）
