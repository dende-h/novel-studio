# 要件定義 — COT-59 本文の固有名詞を拾って用語集への登録を勧め、解析辞書に今の言葉を足す

## 背景と目的

小説の作者は、登場人物・地名・造語を用語集に登録するために、本文を見返して一つずつ拾っている。推敲画面（COT-40）はすでに作品全体を形態素解析しているので、その結果から「本文に出てくるのに用語集に無い名前」を一覧にし、名前・読み・分類が入った状態で登録できるようにする。あわせて解析辞書に今の言葉を足し、名前の拾い漏れと誤りを減らす。AI での判定は今回入れない（2026-10-18 ユーザー決定）。

## 機能要件

### FR-1 今の言葉を足した辞書を配る

推敲画面で読み込む辞書を、SudachiDict（Apache-2.0）の普通名詞を足して作り直した IPADIC に替える。

- 足す語の選び方（試作で決めた線。変えるときは FR-1 の受け入れ条件を回し直す）：
  - 元は SudachiDict の small と core の語彙のうち、普通名詞（一般・サ変可能・形状詞可能）
  - いまの IPADIC が、その語を「辞書に無い語を含む形」「固有名詞を含む形」「1字ずつの漢字2〜3個」に割るものだけを足す
  - 外す：ひらがなだけの語、3字以下のカタカナ語（ただし core にある3字の語は入れる）、Sudachi の重みが0の行
- 品詞は IPADIC の 名詞,一般／名詞,サ変接続／名詞,形容動詞語幹 にそろえる。読みは Sudachi の読み（カタカナだけのとき）を入れる
- 受け入れ条件
  - Given 推敲画面を開いた / When 「コーヒーをテーブルに置いて、スマートフォンを見た。」を解析する / Then 「スマートフォン」が1語の 名詞,一般 で、人名（姓）が出ない
  - Given 同じ / When 「スマホのガチャでコスパのいい課金をした。」「既読スルーされたまま」「王都グランヴェルの城門を、黒鉄騎士団が固めていた。」を解析する / Then スマホ・ガチャ・コスパ・既読スルー・王都・黒鉄がそれぞれ1語で、「王」「都」が人名にならない
  - Given 既存の品詞ルールのテスト文（`src/core/proofread/morph/__fixtures__/samples.json` の23文） / When 新しい辞書で解析する / Then 表層形の区切りがすべて今の辞書と同じ
  - Given 架空の名前61個（一覧は design.md 付録 A・フィクスチャ `fictional-names.json`）を「「待って」<名前>は振り返った。<名前>の声が響く。」に入れた文 / When 新しい辞書で解析する / Then 名前と表層形が同じトークンが出る名前の数が、今の辞書の数（試作で55個。実装の最初に今の辞書で数えてテストに固定する）以上
  - Given ビルドする / When `pnpm build` / Then 辞書の zip は 13MB 以下で、Service Worker のプリキャッシュに入らない（`scripts/check-precache.mjs` が通る）
  - Given 前の版の辞書をキャッシュに持つ端末 / When 推敲画面を開く / Then 新しい辞書を1回だけ読み込む。新しい辞書が使えるようになったら、前の版のキャッシュを消す（辞書のファイル名を変えれば、既存の `analyzer.worker.ts:66-69` が URL の違うキャッシュを消す）
  - Given ヘルプを開く / When 推敲の説明を読む / Then IPADIC に加えて SudachiDict（Apache-2.0）と UniDic（BSD）のライセンス表記へのリンクがある

### FR-2 名前の候補を作る

作品全体のトークンと本文の記法から、名前の候補を作る。

- 手がかり（どれか1つで候補になる）：
  - **辞書に無いカタカナ語**：カタカナの名詞が続く区間で、辞書に無い語か固有名詞を含むもの。続いた区間全体を1語にする（例：グランヴェル、リリアーナ）
  - **1字ずつに割れた漢字**：1字の漢字の名詞が2〜3個続く区間（数・接尾・代名詞・非自立は除く）。例：朔夜、湊斗
  - **敬称の前**：「さん・様・ちゃん・くん・君・殿・氏」（IPADIC の 名詞,接尾,人名）の前の名詞の区間。ただし区間が辞書にある一般の語1つだけのとき（店員さん・お客様など）は除く。漢字1字の名前（澪ちゃん）は、よく敬称が付く一般の語の除外リストに無ければ候補にする。辞書に無い語（リリアーナ様）は除かない
  - **辞書の固有名詞**：IPADIC が 名詞,固有名詞 とする2字以上の、辞書にある語（例：宮森、新宿）
  - **ルビ**：ルビを振った語。ただし辞書の1語で、ルビが辞書の読みと同じもの（難しい漢字の読み仮名）は除く。例：黒鉄《くろがね》は候補、憂鬱《ゆううつ》は除外
  - **用語集に無い `[[ ]]`**：本文で `[[ ]]` を付けたのに用語集に無い名前
- 「辞書にある語」は原形が `*` でないトークン、「辞書に無い語」は原形が `*` のトークンを指す。辞書に無い語にも品詞の細分類（固有名詞,組織 など）が付くことがあるが、当てにならないので分類の推定には使わない
- 候補にする回数：本文の文字列として作品全体で **2回以上** 出る語。ルビと `[[ ]]` の手がかりがある語は1回でも出す
- 除く：用語集の名前と別名（前後の空白を除いて一致）、FR-5 で外した語、1字の語（敬称の前の漢字1字を除く）、数だけの語
- 分類の推定（迷うときは未設定）：
  - 人物：敬称の前の語、または辞書にある人名
  - 場所：辞書にある地域、または後ろに 名詞,接尾,地域（駅・町・市・国 など）が付く語
  - 組織：辞書にある組織
  - 辞書に無い語は、敬称と接尾の手がかりが無ければ分類を付けない
- 読みの推定（ひらがな。わからなければ空）：
  - ルビの読み
  - 辞書の1語の読み（カタカナをひらがなに直す）
  - カタカナだけの名前は、その名前をひらがなに直したもの
  - 1字ずつに割れた漢字は、つなげた読みが当てにならないので空にする
- 受け入れ条件（テストの試し文は design.md のテスト計画に置く）
  - Given 「リリアーナ様」「アルヴェインが叫んだ」をそれぞれ2回含む作品 / When 候補を作る / Then リリアーナ（人物）とアルヴェイン（分類なし）が候補になる。辞書に無い語に付いた細分類で、アルヴェインに分類が付かない
  - Given 「妹ちゃんが来た。」「妹ちゃんは眠い。」 / When 候補を作る / Then 妹は候補にならない（除外リスト）
  - Given 「朔夜は湊斗の手を取った。」「朔夜の声は震えていた。」「湊斗、行こう」 / When 候補を作る / Then 朔夜と湊斗が候補になり、読みは空
  - Given 「佐伯先輩と宮森さんは」「宮森さんは生徒会長」 / When 候補を作る / Then 宮森が人物・読み「みやもり」で候補になり、佐伯（1回だけ）は候補にならない
  - Given 「店員さんに聞いた。」「店員さんが笑った。」 / When 候補を作る / Then 店員は候補にならない
  - Given 本文に `|黒鉄《くろがね》` が1回、`|憂鬱《ゆううつ》` が1回 / When 候補を作る / Then 黒鉄（読み「くろがね」）だけが候補になる
  - Given 用語集に「リリアーナ」（別名「リリィ」）がある / When 候補を作る / Then リリアーナもリリィも候補にならない
  - Given 本文に `[[シェリス]]` が1回あり、用語集に無い / When 候補を作る / Then シェリスが候補になる
  - Given 「スマートフォン」を2回含む本文（FR-1 の辞書） / When 候補を作る / Then スマートフォンは候補にならない
  - Given 回数が同じ候補が複数 / When 並べる / Then 回数の多い順、同じなら `localeCompare(…, 'ja')` の順（かなは五十音順。読みの分からない漢字の名前は文字の順）

### FR-3 「分析」に「用語集に無い名前」を出す

- 推敲画面の「分析」タブの先頭に「用語集に無い名前（作品全体）」の欄を置く。既存の「よく使う言葉」「セリフと地の文」はその下に残す
- 各行：名前、推定した分類（あれば）、回数、出てくる話の数、「用語集に登録」「外す」
- 名前を押すと、いま開いている話の本文の出現箇所に点線の枠が付く（「よく使う言葉」と同じ印。どちらか一方だけを選べる）
- 受け入れ条件
  - Given 前回の解析結果がまだ無く、くわしい確認の準備中・作品全体の解析中 / When 「分析」を開く / Then 「くわしい確認の準備ができると表示します。」と出る
  - Given くわしい確認が使えない（辞書を読めない・メモリ不足） / When 「分析」を開く / Then 「くわしい確認は、いまは使えません。」と出る。ルビと `[[ ]]` だけの候補も出さない（手がかりの半分だけを見せて誤解させない）
  - Given 候補が0件 / When 「分析」を開く / Then 「用語集に無い名前は見つかりませんでした。」と出る
  - Given 候補がある / When 名前を押す / Then この話の本文にある出現のうち、指摘の印と重ならないものすべてに点線の枠が付き、もう一度押すと消える（重なる箇所は、先に始まる印だけを描く。「よく使う言葉」と同じ重ね方・`proofread-text.tsx:23,41-50`）。この話に出てこない名前なら、一覧の下の補足が「この話には出てきません。」に替わる
  - Given 作品全体の解析が済んで一覧が出ている / When 用語集に登録したり、用語集が変わったりして、くわしい確認が作り直される / Then 作り直しの間も前回の一覧を出し続ける（いまの用語集と外した語で絞る）。準備中の表示は、前回の結果が無いときだけ
  - Given 「よく使う言葉」の語を選んでいる / When 名前を押す / Then 言葉の選択が外れ、名前の印だけになる
- ゲストと、スマホの幅：推敲画面そのものが出ない（COT-40 のまま）。この欄だけの扱いは無い

### FR-4 用語集に登録する

- 「用語集に登録」を押すと、既存の登録フォーム（`GlossaryEntryForm` の新規作成・見出し「用語集に登録」・確定ボタン「作成」）が、名前・読み（推定できたとき）・カテゴリ（推定できたとき）を入れた状態で開く（現状：`screens/glossary-quick-create-desktop.png`）
- 受け入れ条件
  - Given 候補「宮森」（人物・みやもり） / When 「用語集に登録」→フォームの「作成」 / Then 用語集に 名前「宮森」・読み「みやもり」・カテゴリ「人物」の項目ができ、推敲画面のまま一覧から宮森がすぐ消える。残りの候補は出たまま（くわしい確認の作り直しを待たない・FR-3）
  - Given 候補を作成で登録した / When ダイアログが閉じる / Then キーボードのフォーカスは、消えた行の次の行の名前のボタンへ移る（次が無ければ前の行、どちらも無ければ欄の見出し）
  - Given 「用語集に登録」でダイアログを開いた / When 「キャンセル」で閉じる / Then フォーカスはその行の「用語集に登録」へ戻る
  - Given フォームで名前を「宮森 透」に直して作成 / When 作成する / Then 用語集には直した名前で入る。「宮森」は用語集の名前と一致しないので、一覧に残る（別名に足すかは作者が決める）。フォーカスはその行の名前のボタンへ戻る
  - Given すでに同じ名前の項目がある / When 作成する / Then フォームは閉じず、既存の重複エラーを出す（いまのフォームの動き）
  - Given フォームを開いた / When 「キャンセル」 / Then 用語集は変わらず、一覧もそのまま
  - Given 推定した分類が無い候補 / When 「用語集に登録」 / Then カテゴリは「未分類」のまま開く

### FR-5 候補から外す・戻す

- 「外す」を押すと、その語は一覧から消える。欄の下の「外した語（N）」を開くと外した語が並び、「戻す」で一覧に戻る
- 外した語は作品ごとに保存し、作品と一緒に同期・バックアップする（推敲の「直す／このまま」と同じ扱い・2026-10-18 ユーザー決定）
- 受け入れ条件
  - Given 候補「新宿」（実在の地名） / When 「外す」 / Then 一覧から消え、「外した語（1）」に出る。フォーカスは次の行の名前のボタンへ移る（次が無ければ前の行、どちらも無ければ欄の見出し）。再読み込みしても外れたまま。有料の同期が動いていれば、別の端末で同期したあとも外れたまま
  - Given 外した語「新宿」 / When 「戻す」 / Then 一覧に戻る（回数の条件を満たしていれば）
  - Given 外した語が本文から無くなった / When 「外した語」を開く / Then その語も並ぶ（勝手に消さない）。「戻す」で記録から消える
  - Given 外した語の記録が壊れていて読めない / When 推敲画面を開く / Then 外した語は無いものとして一覧を出し、壊れた記録は同期で他の端末の記録を上書きしない

## 非機能要件

- **NFR-1 性能**：30万字の作品で、候補づくりが解析全体に足す時間は 200ms 以内（Worker の中・試作の端末で計測）。推敲画面の操作を止めない
- **NFR-2 プライバシー**：候補づくりは端末の中だけで行い、本文を外へ送らない。外した語の記録は、推敲の判断と同じく有料の同期とクラウドバックアップに乗る（公開バンドル・grove・MCP には出さない）
- **NFR-3 オフライン**：辞書をキャッシュに持っていれば、オフラインでも候補を作れる
- **NFR-4 アクセシビリティ**：各行のボタンは「宮森を用語集に登録」「宮森を外す」のように、名前を含めて読み上げられる。名前の選択は `aria-pressed` で伝える。行が消えたとき（外す・登録）は、フォーカスを次の行の名前のボタンへ移す（FR-4・FR-5）

## 後方互換性チェック（CLAUDE.md の各項目）

- **スキーマ**：
  - 用語集・作品・話のスキーマは変えない
  - 外した語は新しい kv レコード（作品ごとに1件）に置く。新設なので核の欄（`workId`・`updatedAt`・語の `text`・`at`）は必須にする（`updatedAt` は同期の LWW に要る）。今後足す欄は `.optional()` にする
  - バックアップの器に欄を足すときは `.optional().default([])` にする
- **旧形式の読み出し**：新しいレコードは今回から。旧版の端末やバックアップには無いので、無ければ外した語なしとして読む
- **表示先の維持**：「分析」の既存の欄（よく使う言葉・セリフと地の文）は残す。辞書を替えても、指摘の種類と表示先は変わらない
- **部分更新で他の欄を落とさない**：
  - 登録は既存の `addGlossaryEntry` を使い、用語集の既存の項目には触れない
  - 外した語の更新は、そのレコードだけを書き換える
- **削除は明示操作だけ**：
  - 外した語は「戻す」を押したときだけ記録から消す
  - 作品をゴミ箱から完全に消したときは、推敲の判断と同じく一緒に消す
  - 辞書のキャッシュを消すのは、利用者のデータではなく配布物の差し替え（前の版のキャッシュだけ）
- **配信契約（publish・同期 API・MCP）**：
  - publish バンドルと MCP には出さない
  - 同期は、推敲の判断と同じ相乗りの方式に新しいキーを足す。旧版のクライアントとサーバが知らないキーをどう扱うかは、design.md の「データモデル」で確認する
- **辞書の差し替えと既存の判断**：
  - 解析の区切りが変わると、品詞を使う指摘（表記ゆれの自動発見・一文の中の同じ助詞・ら抜き・よく使う言葉）の出方が少し変わることがある
  - 保存済みの「直す／このまま」は消さない。対応する指摘が出なくなった判断も記録には残る（COT-40 の扱いのまま）

## 仮定と未決事項

- **仮定**：
  - 「2回以上」の線、敬称の除外リスト、足す語の選び方は試し文で決めた値。実際の原稿で外れが多ければ、design.md のテストの試し文を足して調整する
  - 推定した分類は、登録フォームの初期値にすぎない。作者が直せる
  - 候補の上限は設けず、回数の多い順に全件出す（右の欄はスクロールする）
- **決定（2026-10-18 ユーザー回答）**：
  - **U1 外した語は作品と一緒に同期・バックアップする**（推敲の判断と同じ）
  - **U2 辞書は、作るスクリプトをリポジトリに置き、手元で作った zip をこのリポジトリの GitHub Release に置く**。`fetch-dict.mjs` がハッシュを固定して取る（CI の手順は今と同じ）。Release を作るときは、改めてユーザーに確認する
- **未決**：なし

## 対象外

- AI での判定（Jev・Cloudflare Clef など）
- 候補を既存の項目の別名として足す操作
- 本文の出現を `[[ ]]` に書き換える操作
- セリフの話者の推定
- スマホでの推敲画面（COT-40 のまま PC だけ）
- 推敲画面の外（執筆画面・用語集の画面）に候補を出すこと
