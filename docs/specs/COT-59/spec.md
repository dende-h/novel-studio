# 本文の固有名詞を拾って用語集への登録を勧め、解析辞書に今の言葉を足す 仕様書（COT-59）

- 要件: COT-60（`requirements.md`） ／ 設計: COT-61（`design.md`） ／ プロトタイプ: https://claude.ai/artifact/P1qK7rsF1ADv6eL21sLh1d （非公開）・`prototype.html`
- 状態: レビュー通過（Round 3・独立レビュー）
- 土台: COT-40（推敲画面・形態素解析）

## 何を作るか

推敲画面の「分析」に、本文に出てくるのに用語集に無い名前を一覧にする。一覧から、名前・読み・カテゴリが入った状態で用語集に登録でき、名前でない語は外せる。あわせて、解析辞書に SudachiDict の今の言葉を足す。AI は使わず、候補づくりは端末の中だけで行う。

## 振る舞い

### FR-1 今の言葉を足した辞書

- IPADIC に、SudachiDict 20260723 の普通名詞のうち、IPADIC が誤って割る語（約7万語）を足して作り直す
  - 足さない語：ひらがなだけの語、3字以下のカタカナ語（core にある3字の語は足す）、重みが0の行
- 次の語が1語の名詞になり、人名に誤らない：スマートフォン・スマホ・ガチャ・コスパ・既読スルー・王都・黒鉄
- 既存の品詞ルールのテスト文（`samples.json` の23文）の区切りは変わらない
- 架空の名前61個（design.md 付録 A）で、1語のまま残る数は今の辞書以上にする（試作では55個から56個）
- 配る zip は `lindera-ipadic-6.2.0-sudachi20260723.zip`
  - 大きさは 13MB 以下
  - プリキャッシュには入れない
  - ファイル名が変わるので、端末の古い辞書のキャッシュは既存の処理が消す
- ヘルプに SudachiDict（Apache-2.0）と UniDic（BSD）のライセンス表記へのリンクを足す

### FR-2 名前の候補

- 手がかり（どれか1つで候補になる）：
  - 辞書に無いカタカナ語の区間
  - 1字ずつに割れた漢字の2〜3字の区間
  - 敬称（さん・様・ちゃん・くん・君・殿・氏）の前の区間
  - 辞書の固有名詞（2字以上）
  - 辞書の読みと違うルビ
  - 用語集に無い `[[ ]]`
- 回数の線：作品全体で2回以上出る語。ルビと `[[ ]]` の語は1回から
- 除く語：
  - 用語集の名前と別名、外した語
  - 敬称の前でも、辞書にある一般の語1つだけの区間（店員さん）と、除外リストの語（妹・客など）
  - 1字の語（敬称の前の漢字1字を除く）と、数
- 分類（迷えば付けない）：
  - 人物：敬称の前の語、または辞書にある人名
  - 場所：辞書にある地域、または後ろに「駅」などが付く語
  - 組織：辞書にある組織
  - 辞書に無い語の細分類は使わない
- 読み（ひらがな）：
  - ルビの読み
  - 辞書の1語の読み
  - カタカナの名前は、その名前をひらがなに直したもの
  - 割れた漢字は空にする
- 並び順：回数の多い順。同じ回数なら `localeCompare('ja')`

### FR-3 「分析」の欄

- 欄の場所：「分析」の先頭に「用語集に無い名前（作品全体）」を置く。既存の「よく使う言葉」「セリフと地の文」は下に残す
- 行の中身：名前と「人物・3回・1話」の形の補足。右に「用語集に登録」「外す」
- 名前を押すと、この話の出現に点線の枠を付ける
  - 「よく使う言葉」の選択とは排他
  - 指摘の印と重なる箇所は、先に始まる印だけを描く
  - この話に無い名前なら、補足が「この話には出てきません。」に替わる
- 状態ごとの表示：
  - 前回の結果が無く、準備中のとき：準備中の文言
  - 使えないとき：使えない旨の文言。ルビと `[[ ]]` の候補も出さない
  - 0件のとき：「用語集に無い名前は見つかりませんでした。」
- くわしい確認の作り直し中（用語集の変更・登録の直後）も、前回の一覧を出し続ける

### FR-4 用語集に登録

- 既存の「用語集に登録」ダイアログが、名前・読み・カテゴリ入りで開く。推定が無い項目は今と同じ空欄・未分類
- 作成すると、一覧からすぐ消える
- 名前を直して作成した場合、元の候補は一覧に残る
- 重複はダイアログに今のエラーを出す。キャンセルでは何も変わらない
- 閉じたあとのフォーカス：
  - 行が消えたとき：次の行の名前（無ければ前の行・見出し）
  - 行が残ったとき：その行の名前
  - キャンセルのとき：その行の「用語集に登録」

### FR-5 外す・戻す

- 「外す」でその語が一覧から消え、欄の下の「外した語（N）」に入る。「戻す」で一覧に戻る。フォーカスは次の行へ移す
- 本文から無くなった外した語も、勝手には消さない
- 外した語は作品ごとに保存し、作品と一緒に同期・バックアップする
- 外した語の記録が壊れていても、一覧は出す。壊れた記録で、ほかの端末の記録を上書きしない

外した語のデータ（新しい kv レコード `proofread-names:<workId>`）：

```ts
{ workId: string; words?: { text: string; at: number }[] /* 既定 [] */; updatedAt: number }
```

- 同期は推敲の判断と同じ相乗りの方式で、LWW で勝ち負けを決める
- バックアップの欄 `nameDismissals` は省略可（既定は空）。壊れた要素だけを捨てる
- 作品の完全削除で一緒に消す

## テスト

- **unit**：足す語の選び方、`pos2` と未知語の判定、FR-2 の受け入れ条件（`names.json` は実物の lindera 出力）、外した語の操作、リポジトリ、バックアップ（旧形式と壊れた要素）
- **integration**：
  - 同期（送る・受ける・消す・壊れた記録は masked）
  - 欄の状態と操作・フォーカス（`proofread-view.test.tsx`）
  - 登録の経路とフォーカス（`App.test.tsx`・実物のダイアログを通す）
- **node**：新しい辞書で FR-1 の文が1語になる。区切りは `samples.json` と一致する。61個の名前の数。zip の大きさ。ファイル名が4か所でそろう
- **e2e**：ヘルプのライセンス表記のリンク
- **手動**：30万字で足す時間とメモリ、古い辞書のキャッシュが消えること

## 守ること

- 用語集・作品・話のスキーマは変えない
- 新しいレコードの核の欄は必須、今後足す欄は optional にする
- 接頭辞は `proofread:` で始めない（`proofread-names:`）。`ProofreadRepository` の復元で消えないようにするため
- バックアップの新しい欄は省略可にし、壊れた要素で全体の復元を止めない
- 外した語は「戻す」と作品の完全削除のときだけ消す
- publish バンドル・MCP には出さない
- `samples.json` は作り直さない（今の辞書との比較の基準）
- `src/core/` は React と `src/ui/` を import しない。`src/ui/components/ui/` は編集しない

## やらないこと

- AI での判定
- 候補を既存の項目の別名として足す操作
- 本文を `[[ ]]` に書き換える操作
- 話者の推定
- スマホ対応
- 推敲画面の外に候補を出すこと
- 指摘タブの品詞を使う指摘を、作り直し中も出し続けること（COT-40 の振る舞いのまま）
