# マイクロコピーの型

UI 部品ごとの書き方。実装は既存の共通部品（`docs/CODEMAP.md` §3 のカタログ）を使う前提。

## ボタン

- 動詞で言い切る。「保存」「書き出す」「話を追加」。名詞だけで意味が通るものは名詞可
- 何が起きるか不明な丁寧語にしない（「こちらへ」✗）。1〜6文字程度を目安に
- 破壊操作のボタンは動作をそのまま書く（「削除」）。ためらわせたい気持ちを文言で盛らない
  （確認は ConfirmDialog の仕事）

## 確認ダイアログ（ConfirmDialog）

- title: 「〜しますか？」の疑問形（例:「削除しますか？」）
- description: 結果の事実を1文（例:「この操作は取り消せません」）。脅さず、事実だけ
- 実行ボタンは title と同じ動詞（「削除」）、キャンセルは「キャンセル」

## トースト（useToast）

- 完了報告は結果だけを短く（「保存しました」「書き出しました」）
- 目安は15字以内。句点は1文なら省略可。絵文字・感嘆符は使わない

## エラーメッセージ

「何が起きたか（事実）＋ 次にできること（一歩）」の2要素。原因の専門用語は出さない。

- 例:「同期できませんでした。通信環境を確認して、もう一度お試しください」
- ユーザーを責める書き方をしない(「不正な入力です」→「この形式では読み込めませんでした」)
- 原稿が失われていない場合は、その事実を先に言う（安心が最優先の情報)

## 空状態（empty state)

- 「何もない」ことではなく「最初の一歩」を書く（「最初の話を書き始めましょう」型)
- 機能説明を長々と書かない。1文＋行動ボタンで足りるのが理想

## オンボーディング・ヘルプ

- 一度に1概念。FirstRunDialog の例:「保存の仕組みを、はじめに一度だけ。」
- 仕組みの説明はユーザーの損得（原稿がどこにあるか、何をすると安全か）に翻訳して書く

## 料金・プラン

- 価格・条件は正確に、割引理由も明示（「年額 ¥4,800（月あたり400円）」）
- 無料でできることを先に、有料はその上に。無料側を貧しく見せて誘導しない
- 「登録だけで課金はありません」のような不安の先回りは積極的に書く
