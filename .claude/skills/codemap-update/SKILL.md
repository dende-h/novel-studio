# CODEMAP を最新に保つ

`docs/CODEMAP.md` は「コード調査の入口」。ここが古いと、以降の調査が全部ずれる。
**地図であって説明書ではない** — 「どこを見ればいいか」だけを載せ、実装の詳細は載せない。

## 手順

### 1. 何が変わったかを確定する

```bash
git status --short
git diff --stat HEAD          # 未コミットも含める
git diff --stat main...HEAD   # ブランチ全体（main が基点でない場合は基点を読み替える）
```

ファイル一覧だけ見て済ませない。変更の**種類**を分類する:

- **A. 構造の変化** — ファイル/ディレクトリの追加・削除・移動・改名
- **B. 契約の変化** — export された型・関数の追加/削除/改名、API エンドポイント、DB マイグレーション、ルート、環境変数、バインディング
- **C. 責務の変化** — 既存ファイルの役割が変わった、ロジックが別モジュールへ移った
- **D. コマンド/ツールの変化** — `package.json` の scripts、CI、lint 設定、依存の追加削除
- **E. 中身だけの変化** — バグ修正・スタイル調整・テスト追加

**E だけなら CODEMAP は更新しない。** 何も変えずに「更新不要」と報告して終わる。
地図をノイズで太らせないことが、このスキルの半分の仕事。

### 2. 影響する節を特定して直す

| 変更の種類 | 直す節 |
|---|---|
| 新機能・新しい関心事 | §1「◯◯を変えたい」の表に1行足す（**ここが一番使われる。優先度最高**） |
| `src/core/` のモジュール増減・export 変更 | §2 の該当表 |
| 画面・ルート・hooks・store の変更 | §3（ルート一覧・components の分類・補助ディレクトリ） |
| API・`functions/`・マイグレーション・バインディング | §4 |
| scripts・CI・lint・ツールのバージョン | §5 |
| `docs/` 配下の増減 | §6 |
| アーキテクチャの原則そのものが変わった | §0 と、対応する `docs/requirement/*.md` も直す |

### 3. 書き方の規則

- **既存の書式に合わせる**（表は表のまま、箇条書きは箇条書きのまま）。書式を勝手に作り替えない。
- **1エントリ1行**。責務は名詞句で短く。「〜する処理を行うためのモジュール」ではなく「三方向差分の純ロジック」。
- **パスは正確に**。`src/core/sync/plan.ts` のように、開けば当たる粒度で書く。
- **行数の言及は、その数字が判断材料になるファイルだけ**（`App.tsx` が 813 行など「覚悟して開け」の意味を持つもの）。飾りで足さない。
- **削除を怠らない**。消えたファイル・消えた責務の行は必ず消す。地図の嘘は、無い情報より害が大きい。
- **既存の記述の誤りに気づいたら、変更範囲外でも直す**（地図の精度が目的なので）。

### 4. 検証する

CODEMAP に書いたパスが実在することを機械的に確かめる:

```bash
# CODEMAP 内のバッククォート付きパス（リポジトリのルートディレクトリ配下）が実在するか
grep -oE '`[A-Za-z0-9_./@-]+`' docs/CODEMAP.md | tr -d '`' \
  | grep -E '^(src|functions|docs|e2e|migrations|design|public|\.claude|\.github)/' \
  | sed 's|/$||' | sort -u \
  | while read -r p; do [ -e "$p" ] || echo "MISSING: $p"; done
```

`MISSING:` が出たら直す。リポジトリのルート直下ディレクトリで始まらない表記
（`plotToPlainText.ts` のような同ディレクトリ内の列挙、`#/write` のようなルート名）は
意図的に対象外にしてあるので、そこは目視で確認する。

### 5. 報告する

CODEMAP をどう変えたかを、ユーザーへ1〜3行で伝える。
更新不要と判断した場合も、その判断と理由（「E: 中身だけの変更のため」）を伝える。

## やらないこと

- 実装の解説・使い方・設計の背景を CODEMAP に書く → それは `docs/requirement/` の仕事
- 全ファイルの網羅列挙 → 地図は索引であって目次ではない。1ファイル1行が要るのは「そこを直しに行く理由がある」ファイルだけ
- コード本体の変更 → このスキルは `docs/CODEMAP.md`（と、原則が変わったときの `docs/requirement/`）しか触らない
