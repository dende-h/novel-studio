# 用語集「人物以外」を掘る観点

場所 / 組織 / 用語（世界の仕組み・制度・概念）/ アイテム / 生物 の 1 件を掘り切るための観点表。
人物は `angles-person.md`。

器の分かれ方・書き込みの規約は
`.claude/skills/kotonaha-editing-common/references/kotonaha-mcp.md`、
問いの投げ方と反対の仕方は同 `editor-stance.md`。**ここには「人ではないもの」に固有の観点だけを置く。**

共通リファレンスに書いてあって、ここでは繰り返さないもの。読まずにこの表だけ使うと事故る。

- 何を `summary` へ、何を `author_note` へ、何を `set_world_note` / `secret` / `foreshadow` / ビートへ（§2）
- `set_world_note` は `body` を全置換する。既存を読んで、既存＋追加の全文を渡す（§5.1）
- `cast` / `place` / `line_ids` / `aliases` は配列なので、渡すと丸ごと置換になる（§5.1）
- `upsert_glossary_entry` は `name` が毎回必須。分類は 人物 / 場所 / 組織 / 用語 / アイテム / 生物 の 6 語（§5.3・§5.4）

分量は実務の頻度に合わせてある。場所と用語（仕組み）が厚く、アイテムと生物は薄い。
破綻が深いのも用語（仕組み）で、そこに §3 の紙幅を回している。

例は 2 作品から引く。ひとつは岬の灯台を舞台にした海辺の話、もうひとつは地方都市の市役所で
生活支援課に勤める主人公の話。どちらの型でも同じ枠が使えることを見せるため、両方を並べる。

## 0. 分類を問わず、掘り出す前に

### 0-1. それ自体では本文に出られない — 顔になる人を 1 人決める

人物と違って、場所・組織・仕組み・道具・生き物は、人を通してしか読者に届かない。
だから最初の問いは分類を問わず同じになる。組織の役職を 9 つ書いても、口をきくのが受付の
一人だけなら、読者が触れたのは受付一人ぶんだけになる。

> **いま分かっていること**：この項目に紐づく人物が、用語集にもビートの `cast` にも一人もいません。
>
> **見立て**：このままだと、決めたことの出口が本文にありません。読者はこの項目に直接は触れません。
>
> **問い**：この項目の顔になる人を 1 人決めてください。その場所を管理している人、その組織の窓口、
> その道具を持っている人、その生き物を追っている人。名前がなければ役職だけでかまいません。

顔が決まったら、その人物の用語集項目を作り、該当ビートの `cast` へ結ぶ。
`cast` は配列なので、**現在の登場人物の全員＋その 1 人**を並べた配列を渡す。

### 0-2. 段階公開は、守りだけでなく攻めにも使う

用語集は公開サイトへ送られ、その語が出てくる話まで読んだ読者に開く（共通リファレンス §2）。
ここから、この器でしか出てこない判断が 2 つ出る。

**守り：初出が早い項目ほど、`summary` に書けることが少ない。**
第一話で名前が出る場所の公開情報に、第三部の因縁を書けない。掘り出す前に
「この項目は何話目で開くか」を確認する理由がここにある。

**攻め：本文で説明しきれないものを、用語集に預けられる。**

> 「この仕組みの説明、いま第三話の会話で 12 行使っています。用語集の公開情報に 3 行置けば、
> その語が出た時点で読者は引けます。本文は『使って失敗する場面』だけにして、説明を
> 用語集へ逃がしませんか。知っている者どうしが説明し合う会話が消えます」

作者が「うちはまだ公開していない」と言っても、書き方は変えない。公開は後から決められるが、
書いてしまった `summary` を後から全項目ぶん点検するのは現実的でない。最初から公開前提で書く。

### 0-3. `author_note` と `set_world_note` の線

`author_note` は「この項目の裏」、`set_world_note` は「作品の法律」。同じネタバレでも置き場が違う。

- 「この灯台は、第三部で焼ける」→ 灯台の `author_note`（その項目の未来）
- 「この作品では、建物が焼けたら二度と再建されない」→ `set_world_note`（`slot: rules`・全項目に効く）

### 0-4. 本文にまだ出ていない項目

`get_work` を読めば分かることを作者に聞かない。読んだうえで見立てと推しを添える。

> **いま分かっていること**：`get_work` を見たところ、この名前は本文にまだ一度も出ていません。
> ビートの `place` にも入っていません。
>
> **見立て**：いま設定を積むと、そのぶんは読者に届かない資料になります。
>
> **問い**：出す話を 1 つ決めてから掘るか、`set_world_note` の自由枠へ寄せるか、どちらにしますか。
> 私は前者を推します。第二話の岬の場面なら、いまの流れを変えずに一度名前を出せます。

自由枠へ寄せるときは `slot: custom` に `title` を付けて書く。**`id` を渡さないと呼ぶたびに新しい枠が
増える**ので、2 回目からは `get_world` が返す `[note_id: …]` を渡す。渡し忘れると
「書けなかった素材」が 3 つ並ぶ。

### 0-5. よみと別名の運用、2 件を統合するときの順番

`reading`（よみ）は候補の絞り込みと並び順のためだけの欄で、**`[[ ]]` の解決には使われない**。
読者と作者が本文で使う表記は、すべて `name` か `aliases` に入れる。当て字の地名・生物名は、
よみを入れておかないと作者自身が候補から呼び出せない。

**2 件を統合したいときは、削除から入らない。** 片方の `aliases` にもう片方の名前を吸収させてから
（現在の全別名＋その名前の配列を渡す）、空になった項目を作者の判断で消す。
順番を逆にすると、本文の `[[旧名]]` が未解決に落ちる。

## 1. 場所

### 1-1. 最初の問い

> **いま分かっていること**：この場所は `get_plot` で 3 つのビートの `place` に入っています。
> 用語集の公開情報は「静かな港町」の一行だけです。
>
> **見立て**：3 場面ぶんの出番があるのに、書けるものが一行もありません。地図や広さから
> 埋めると、説明できるだけの場所になって描写が出てきません。
>
> **問い**：その場所に立ったとき、最初に鼻か耳に来るものは何ですか。目に見えるものは後回しでいいです。

匂いと音から入ると、本文にそのまま書ける行が最初に手に入る。

### 1-2. 続けて拾う論点

- **誰の場所か** — 日常か、入ってはいけない場所か、一度だけ行って帰る場所か。型が決まると次の問いが変わる（日常なら「そこが壊れる話はどこか」、禁域なら「破ったらどうなるか」）
- **そこでしか起きない出来事** — 別の場所へ移したら成立しなくなるものを 1 つ。答えられない場所は、名前を付けた背景でしかない
- **出入りの条件** — 鍵・金・身分・時刻・同伴者・体調のどれが要るか。そのままビートの障害になる
- **抱えている損傷** — 人が減っている、朽ちている、買い取られようとしている、水位が上がっている
- **入れ子をどこで切るか**（→ 1-3）
- **最終話でどうなっているか**（→ 1-5 兆候B で扱う）

### 1-3. 入れ子をどこで切るか

用語集は階層を持たない。町・港・灯台・灯台守の家を全部項目にすると、読者は 4 件の似た説明を引く。

> 「町・港・建物・部屋のうち、本文で人が二度以上いる単位はどれですか。項目にするのはそれだけにして、
> 上の単位は公開情報の一行目で触れるだけにしませんか。『岬の先端に立つ二階建て』の一行があれば、
> 読者は岬を引かずに位置を掴めます」

切る位置が決まったら、上の単位は `set_world_note` の `stage` に一度だけ書き、用語集からは外す。

### 1-4. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「静かな港町です」 | 「静かというのは、何の音がしないことですか。工場が止まったのか、子どもがいないのか、風がないのか。どれかで町の履歴が変わります」 |
| 「古い洋館です」 | 「古いと分かるのは、住人の誰が見たときですか。そこで育った人には古く見えないはずです。誰の目で書きますか」 |
| 「王都です。人口は 30 万で、東西に大通りが……」 | 「規模はいったん置きます。主人公がそこで一度も見ていない区画はどこですか。読者に見せない場所を決めるほうが、王都は広く感じます」 |
| 「主人公の家です」 | 「その家で、主人公が触らない物はありますか。触らない物が 1 つあれば、家が過去を持ちます」 |
| 「学校の屋上です」 | 「その屋上、いつ施錠されていますか。入れてしまう理由が要ります。開いている理由を作ると、それ自体が誰かの事情になります」 |
| 「森です。魔物が出ます」 | 「魔物を抜いて、その森を一言で言えますか。言えないなら、いまその森は『危険』という機能の別名です」 |

### 1-5. 決まったことの振り分け

`set_world_note` へ書く前に、その枠の現在の本文を `get_world` で読む。**渡した `body` で枠ごと
入れ替わる**ので、既存＋追加を組み立てた全文を渡す。以下の例は、いずれも「その全文の一部」として読む。

**用語集 `summary`（公開情報）** — 読者がその名前を本文で見た直後に読んで得をすること。

```
名前: 灯台守の家 ／ 分類: 場所 ／ 別名: 岬の家, あの家
公開情報:
岬の先端に立つ二階建て。海側の窓は塩で白く曇り、いつも潮と灯油の匂いがする。
下の階が灯台の管理小屋、上の階が住居。夜通し灯を回すため、住人は昼に眠る。
```

```
名前: 三号棟の集会室 ／ 分類: 場所 ／ 別名: 集会室
公開情報:
市営住宅三号棟の一階にある十畳ほどの部屋。長机が四つとパイプ椅子、壁に古い避難経路図。
月の第二土曜だけ自治会が使い、それ以外の日は鍵がかかっている。
```

**`author_note`（非公開）** — その場所の未来と裏。

```
作者メモ:
第三部で焼ける。焼けた跡から、床下の手紙束が見つかる（→ secret「母の出自」）。
アカリが二階へ上がらないのは、母が落ちた階段だから。本人にはまだ書かせない。
```

**`set_world_note`** — その場所を超えて効く決まり。

```
slot: stage（時代と場所）
現代日本、日本海側の県。県庁所在地から鉄道で二時間。冬は十二月から三月まで曇りが続く。
夜が早く、午後五時には店が閉まる。この暗さを全編の基調にする。
```

```
slot: rules（この作品の約束事）
建物が焼けたら再建しない。失われた場所は失われたまま話が進む。
主人公が困ったときに「たまたま開いていた場所」を出さない。入る場所には必ず入る手段を先に置く。
```

**`upsert_secret`** — その場所について読者がまだ知らないこと。

```
title: 灯台守の家の床下
truth: 母が出て行かなかったこと、そして家に留まったまま死んだこと。床下の手紙束がその証拠。
reveal_beat_id: <焼け跡のビート>
```

**`upsert_plot_beat`** — 場所は `place` に entry_id で結ぶ。配列なので、そのビートの
現在の全件＋この 1 件を渡す。結ぶと `get_plot` の各ビートに「舞台: 灯台守の家」が出る。
出るのはビートごとの一行だけで、集計はされない。何件のビートに出ているかは編集者が数える。

### 1-6. 質が落ちる兆候

**兆候A：入れ替え可能な場所** ｜ 強さ：反対する

そこで起きた出来事を別の場所へ移しても、話が成立してしまう。

> 「この港町は、いまのところ駅前でも成立します。これは反対です。港の描写が 20 行あるのに、
> その 20 行が第四話の別れの結果を何も変えていません。港でなければ起きないことをひとつ足すか、
> 舞台を駅前に変えて港を削るか、どちらかを選びませんか」

**兆候B：最終話でも冒頭と同じ姿** ｜ 強さ：反対する

昼と夜で何が違うか、10 年前と何が違うかを聞いても答えが出ない場所は、たいていここに落ちる。
変化の有無を聞くのではなく、着地だけを聞く。

> 「この場所、最終話ではどうなっていますか。冒頭と同じ姿なら、それが主人公の敗北の証か、
> 救いの証か、どちらとして書くか決めてください。ただ変わらないだけだと、読者は読み終えても
> その場所を覚えていません」

**兆候C：観光案内になっている** ｜ 強さ：気になる

`summary` が名所紹介の文体で、物語と接続していない。

> 「公開情報の 4 行、読者がこれを読んで次の話が読みたくなる箇所がありません。ここは弱いと思います。
> ただ好みかもしれません。誰かがここで何かを失った、という一行を足せますか」

### 1-7. 場所に固有の矛盾検査

- 距離と移動時間が話の都合で伸縮していないか（第二話は日帰り、第七話は一泊）。決めた側を `stage` に一行置く
- `stage` の気候・時代・交通と、`summary` の描写が噛み合っているか（冬に閉ざされる街道と、冬の往来）
- 入れ子の上の単位（町・区画）を別項目として二重に書いていないか。1-3 で切った位置に合っているか

## 2. 組織

### 2-1. 最初の問い

> **いま分かっていること**：この組織は `summary` に「町を守る自警団」とあり、ビートには
> 第二話と第六話で名前だけ出ています。主人公と会話する団員は決まっていません。
>
> **見立て**：組織図から作ると、そのほとんどが本文に出ません。主人公に何をする存在かが先です。
>
> **問い**：その組織と主人公は、どこで初めて触れますか。呼び出される、断られる、追われる、
> 雇われる、のどれに近いですか。私は「断られる」を推します。第二話でまだ主人公に味方が
> いないので、断られた側から入るほうが第六話の再訪が効きます。

### 2-2. 続けて拾う論点

- **何で食っているか** — 会費、税、寄進、上納、補助金、商い、略奪。収入源が決まると、組織が何を嫌がるかが決まり、主人公の交渉材料が生まれる
- **決定と、それに反対した人**（→ 2-3）
- **外からどう見えているか** — 頼りにされている／怖がられている／見て見ぬふりをされている。かつては前者でいまは後者、なら転落の理由が `history` に入る
- **抜けるとどうなるか** — 抜けられないなら、抜けようとした人がどうなったかを 1 例
- **守っている秘密** — 全員が知っている秘密か、上層だけが知っている秘密か
- **何人いるか**（→ 2-4）

### 2-3. 中の温度差は、決定と処遇で聞く

「方針に納得していない人は誰ですか」は人物リストを求める問いで、答えても設定が一行増えるだけになる。

> 「その組織が最後に下した決定はどれですか。その決定に、最後まで反対した人はいますか。
> 反対したあと、その人は組織に残っていますか」

決定・反対・処遇の 3 点が揃うと、そのまま場面になる。

### 2-4. 何人いるか

規模が決まっていない組織は、本文で「大勢」「幹部」「みんな」が揺れる。第二話で 5 人ほどに
見えた講が、第七話で町の全戸になっている、という壊れ方をする。

> 「その組織は何人いますか。主人公が一度に目にする最大人数でいいです。5 人ですか、20 人ですか、
> 顔が見えない規模ですか」

決まった数は `summary` に書かない（読者に人数表は要らない）。`society` に一行置いて、
本文の書き分けの基準にする。

### 2-5. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「町を守る自警団です」 | 「守っていることになっている、の間違いではありませんか。守れなかった事件が一件あると、団の顔つきが変わります」 |
| 「巨大企業です。悪の組織です」 | 「そこで働いている人の大半は普通に通勤して普通に帰るはずです。悪意ではなく、何の合理で人が死にますか」 |
| 「教団です。教義は……」 | 「教義より先に、信者が毎朝やることを 1 つ決めてください。所作が決まると教義が後から立ちます」 |
| 「主人公の敵です」 | 「その組織にとって、主人公は敵ですらないという線はありませんか。相手にされないほうが、主人公は苦しみます」 |
| 「代々続く旧家です」 | 「続いているのは何ですか。土地、名前、借金、負い目、墓。続いているものが決まると、主人公が背負うものが決まります」 |

### 2-6. 決まったことの振り分け

`set_world_note` へ書く前に、その枠の現在の本文を読む（全置換）。とくに `society` は
場所の掘り下げでも組織の掘り下げでも書きたくなる枠で、順に上書きすると先に書いたほうが消える。

**`summary`（公開情報）** — 読者がその組織の名を見たときに要る最小限。役職表は入れない。

```
名前: 灯明講 ／ 分類: 組織 ／ 別名: 講, 岬の講
公開情報:
岬一帯の漁師が入る互助の講。年に四度、灯台の油代を出し合う。
入るには家ごとの推薦が要り、抜けた家とは船を並べない。
```

現代物なら同じ枠がこうなる。読者に要るのは、窓口として何をする係かだけ。

```
名前: 生活支援課 ／ 分類: 組織 ／ 別名: 支援課
公開情報:
市役所二階の窓口。生活の相談と給付の受付を扱い、職員は八人。
相談は予約制だが、当日の飛び込みも断らない決まりになっている。
```

**`author_note`（非公開）**

```
作者メモ:
講の油代は二十年前から集まっていない。差額を出しているのは町長個人。
その理由（息子の事故の口止め）は第四部まで伏せる。→ secret「町長の負い目」
```

**`set_world_note`**

```
slot: society（人を縛るもの）
この町では、家単位で組織に属する。個人で入る・抜けるという発想がない。
「一人だけ抜ける」は、この作品では最大級の逸脱として扱う。
講の集まりは一度に多くて十五人。「大勢」と書かず、顔の見える数で書く。
```

`rules` には「組織は主人公を助けない。組織が動くのは組織の利益のときだけ」の一行が入る。
これを置くと、2-7 兆候A の検算が機械的にできるようになる。

**ビートへ** — 組織は「顔のある一人」に置き換えて `cast` に入れる。組織そのものを入れても本文は
書けない。`cast` は配列なので、そのビートの現在の全員＋その一人を渡す。

### 2-7. 質が落ちる兆候

**兆候A：主人公の都合で動く** ｜ 強さ：反対する

危機のたびに援軍を出し、必要なときに情報をくれる。

> 「この組織、いまのところ主人公の便利な後ろ盾になっています。これは反対です。第三話と
> 第五話の危機がどちらも講の到着で解けていて、主人公が自分で払った代価がありません。
> 一度でいいので、正しい理由で主人公を見捨ててもらえませんか。見捨てられて初めて、
> 読者はこの組織の原理を理解します」

**兆候B：悪であることしか設定されていない** ｜ 強さ：反対する

> 「その組織が自分たちを正しいと思っている理由を一行ください。悪だと自認している組織は、
> 読者にとって舞台装置です。理由が一行あるだけで、主人公の反論に相手が現れます」

**兆候C：勢力図が主役になる** ｜ 強さ：気になる

> 「勢力が 6 つあって、主人公はそのうち 2 つとしか関わりません。ここは弱いと思います。
> ただ群像として書きたいなら好みの範囲です。残り 4 つの抗争を本文に出せないなら、
> いまは 2 つに絞って、残りは `custom` の自由枠へ置いておきませんか」

### 2-8. 組織に固有の矛盾検査

- `history` に書いた過去の事件と、`summary` の年数・人数が一致しているか
- `society` に書いた原理と、その組織の入退の条件が食い違っていないか
- 2-4 で決めた規模と、本文の「大勢」「みんな」の書き方が噛み合っているか

## 3. 用語（世界の仕組み・制度・概念）

**仕組みのルール本体は用語集に書かない。** 用語集の `summary` に置くのは、読者がその語を本文で
見たときに要る最小限だけ。ルール・限界・代償・例外は `set_world_note` の `special` と `rules` が持つ。
理由は 2 つ。用語集は公開経路に載るので、限界と抜け道を先に読まれると仕掛けが死ぬ。
そして仕組みは複数の項目にまたがって効くので、1 項目の中に書くと参照しきれない。

### 3-1. 最初の問い — できないことから聞く

順番を守る。**できることを先に聞かない。** 先に聞くと、作者は万能に近い仕組みを作り、
あとで縛れなくなる。ただし「絶対にできないことを挙げてください」も抽象語で、作者は
「万能ではありません」としか返せない。いま止まっている場面を主語にする。

> **いま分かっていること**：第五話のビート「船が出せない」で主人公が詰まります。
> この仕組みには、いま限界も代償も書かれていません。
>
> **見立て**：限界が無いままだと、読者は第五話を読みながら「使えばいいのに」と考えます。
>
> **問い**：この仕組みを使えば、第五話の詰まりは解けてしまいますか。解けないなら、
> その理由を一行ください。解けてしまうなら、そこが最初の「できないこと」です。

答えが出たら、次は「では、できることを書いてください。いま決めた線の内側だけで」と続ける。

### 3-2. 続けて拾う論点

- **無かった頃** — その仕組みがまだ無かった頃、人はその用事をどう済ませていたか
- **代償** — 一度使うと何が減るか。体、物、関係、記憶、時間、あるいは減らない（減らない場合の追撃は 3-3）
- **誰が使えるか** — 生まれ、訓練、免許、道具のどれで決まるか。主人公は資格を持っている側か、持っていない側か。持っていない側だと話の運びが自動的に良くなることが多い
- **効かない相手・場所・条件** — あると、敵を強くしないまま緊張を上げられる
- **世に知られているか** — 日常に組み込まれている／扱えるのは限られる／実在を疑われている。この選択で本文の説明の量が決まる。日常に組み込まれているつもりで読者向けの説明を挟むと世界が薄くなる
- **誰が管理し、誰が得をしているか**（制度の場合）
- **名前を付けたのは誰か。使う人と外の人で呼び方は違うか**
- **決めた内容で、いまの葛藤が消えないか**（掘り終わりに必ず戻る。→ 3-4 の `special` 末尾）

### 3-3. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「代償はありません」 | 「代償なしで通すのはひとつの選択です。ただ、そのときは使える人が極端に少ないか、使うと誰かに知られるか、どちらかの縛りが要ります。どちらを取りますか。両方無いと、以後この仕組みが出るたびに読者は『それで全部解決するのでは』と考えます」 |
| 「魔力が減ります」 | 「魔力が減ると、その日の何ができなくなりますか。寝れば戻るなら、それは代償として働きません。戻るまでの時間を決めてください」 |
| 「使いすぎると死にます」 | 「その『使いすぎ』の線を、主人公が知っているかで意味が変わります。知っているなら計算ができ、知らないなら恐怖になります。どちらで書きますか」 |
| 「なんでもできます」 | 「では、この仕組みを持つ人がなぜ世界を支配していないのですか。支配していない理由が、そのまま『できないこと』です」 |
| 「原理は誰も知りません」 | 「知らないことにするのはいい判断です。そのぶん、知らないまま使っている人の作法が要ります。使う前に何をしますか。手順・祈り・道具・場所のどれかを決めましょう」 |
| 「昔からある制度です」 | 「昔からあるものは、当初の目的とずれて運用されているのが普通です。ずれはありますか。ずれがあれば、それを利用する人物が書けます」 |
| 「主人公だけが使えます」 | 「主人公だけが使えると、負ける理由を毎回別に作ることになります。同格の使い手を一人置くか、主人公の使い方に欠陥を置くか、どちらにしますか」 |
| 「使うと目立つので隠しています」 | 「隠しているなら、バレたときの罰を決めてください。罰が決まっていないと、隠す緊張が読者に伝わりません」 |

### 3-4. 決まったことの振り分け

**用語集 `summary`** — 読者がその語を本文で見たときに要る最小限。限界も代償も例外も書かない。

```
名前: 灯継ぎ ／ 分類: 用語 ／ 別名: 継ぎ, 火継ぎ
公開情報:
夜通し灯を絶やさないために、二人一組で交代しながら火を守る当番のこと。
組になれるのは血の繋がらない者どうしと決まっていて、組んだ相手は「灯兄弟」と呼び合う。
```

```
名前: 見守り登録 ／ 分類: 用語 ／ 別名: 登録
公開情報:
一人暮らしの高齢者が市に届け出ると、月に一度職員が訪問する制度。
本人か家族の申し出でしか始められず、断られたらそれ以上は関われない。
```

読者に要るのは、当番であること、二人組であること、呼び名がつくこと。制度なら、誰が申し込めて
何が起きるか。**それ以上は書かない。**

**`author_note`** — その語に閉じた裏。

```
作者メモ:
「血の繋がらない者どうし」という決まりは、火が血縁者を選んで襲うから。
この理由は最終部まで伏せる。→ secret「灯が血を選ぶ」
```

**`set_world_note(slot: special)`** — 仕組みの本体。できること／できないこと／代償／資格／
例外／認知度を、この 1 枠に集約する。長いほど守られなくなるので、本文で使う範囲に絞って書く。
書く前に現在の本文を読み、既存＋追加の全文を渡す（全置換）。

```
slot: special（固有の仕組み）
【灯】人の記憶を燃料に燃える火。灯にくべた者の記憶を、他の一人へ一度だけ移せる。
できないこと: 死者の記憶は燃えない。移した記憶は戻せない。火は消せない。灯台から離れると起きない。
代償: くべた記憶は本人から永久に消える。何を失ったかも思い出せない。
使える人: 資格はない。誰でもくべられる。だから危ない。くべ方の口伝を知るのは当番経験者だけ。
例外: 血縁者どうしでくべると両方の記憶が燃える（＝灯兄弟の決まりの理由）。
認知度: 実在は疑われている。年寄りは信じ、若い世代は迷信と思っている。
いまの葛藤との関係: 主人公は母の死の理由を知りたいが、死者の記憶は燃えないので灯では解けない。
灯は「知る」役に立たず、「捨てる」役にしか立たない。ここを最後まで動かさない。
```

制度でも同じ枠を同じ順で使う。「見守り登録」なら、できないこと（本人が断れば関われない）、
代償（訪問の記録が残り、断った事実も残る）、例外（民生委員経由なら本人の同意なしで一度だけ）、
そして「いまの葛藤との関係」（主人公は断られた家に入れない。制度は入る理由にならず、
断られた事実を主人公に残す装置として使う）。

**末尾の「いまの葛藤との関係」の 2 行が、この枠のいちばん働く場所になる。**
仕組みを足すたび、ビートを組み替えるたびに、ここを書き直す。

**`set_world_note(slot: rules)`** — 仕組みを跨いだ全体の縛り。

```
slot: rules（この作品の約束事）
灯の設定を、話の途中で拡張しない。新しい効果を足したくなったら、
それは special に書いた「できないこと」を削る作業になる。削るなら伏線を先に張る。
主人公の窮地を灯で解決しない。灯は問題を減らす道具ではなく、代価を払う場所として使う。
```

**`set_world_note(slot: reveal)`** — 仕組みを読者にどこまで見せるかの方針。個別の秘密は `secret` が持つ。

```
slot: reveal（何を、いつ明かすか）
灯の原理は最後まで説明しない。読者には、使われた場面の結果だけを見せる。
「できないこと」は登場人物が試して失敗する形で見せ、地の文で規則として書かない。
```

**`upsert_secret`**

```
title: 灯が血を選ぶ
truth: 血縁者どうしがくべると両方が燃える。灯兄弟の決まりはこの事故を防ぐために生まれた。
reveal_beat_id: <トウマとアカリが組もうとして拒まれるビート>
```

**`upsert_foreshadow`** — 「できないこと」を後で効かせるための布石。

```
title: 死者の記憶は燃えないこと
note: 序盤で誰かが試して失敗する場面を置き、終盤で主人公が同じ壁に当たる。
plant_beat_id: <第一部・老人が試みるビート>
payoff_beat_id: <第三部・主人公が母を求めるビート>
```

### 3-5. 質が落ちる兆候

**兆候A：限界と代償が無く、いまの問題を解決できてしまう** ｜ 強さ：止める

この領域でいちばん多く、いちばん深い。

> 「これは入れないほうがいい。入れると第五話が成立しません。この仕組みは第五話の
> 『船が出せない』をそのまま解決できて、解決しない理由がどこにもありません。読者は第五話を
> 読みながら『使えばいいのに』と考えます。使えない条件を仕組み側に足すか、第五話の問題を
> 仕組みが届かないところへ移すか、どちらを取りますか」

**兆候B：後出しの新ルール** ｜ 強さ：反対する

終盤で「実は距離を越えられる」「実は二回まで使える」が生える。

> 「第九話で灯が灯台の外で働いています。これは反対です。`special` に書いた『灯台から離れた
> 場所では起きない』と衝突していて、第三話で老人が試して失敗した場面が無意味になります。
> 拡張するなら、第三話までのどこかに匂わせる場面を先に置きましょう。伏線として
> `plant_beat_id` を第三話のビートに、`payoff_beat_id` を第九話に立てます。
> 先に置けないなら、第九話の解決を別の手に変えるほうが早いです」

**兆候C：「できないこと」に代償のない抜け道がある** ｜ 強さ：反対する

> 「『死者の記憶は燃えない』のに、第七話で死者の遺品を経由して同じ結果が出ています。
> これは反対です。抜け道があること自体はいいのですが、いまの書き方だと制限を書いていないのと
> 同じになります。抜け道にも代償を付けるか、第七話の結果を半分にするか、どちらにしますか」

### 3-6. 用語（仕組み）に固有の矛盾検査

- `special` の「できないこと」を、既出の本文が破っていないか。**破っている箇所を必ず話数で示す**
- `special` 末尾の「いまの葛藤との関係」が、現在のビート表の主要な障害と噛み合っているか。噛み合わなくなったら書き直す
- 認知度と、本文で人物が見せる反応が一致しているか。日常に組み込まれているはずの仕組みに、人物が毎回驚いていないか
- 「できないこと」の各項目に、対応する `foreshadow` があるか。無い制限は、終盤で読者に「ご都合」と読まれる

## 4. アイテム

### 4-1. 最初の問い

> **いま分かっていること**：この道具は用語集に「形見のペンダント」とあり、`author_note` は空です。
> ビートには一度も出ていません。
>
> **見立て**：形見であることは関係の名前で、まだ物語の中の仕事がありません。
>
> **問い**：それはいま誰が持っていますか。その人の手に渡った経緯は、買った、拾った、
> 譲られた、押しつけられた、のどれですか。私は「押しつけられた」を推します。
> 持ち主が捨てられない理由が最初から要りますし、押しつけた側が本文に一人増えます。

### 4-2. 続けて拾う論点

- **手放せるか。壊れるか** — 手放せない理由は物理か心理か。壊れたら話はどうなるか
- **それを欲しがっている人** — いないなら、なぜ誰も欲しがらないのか
- **使うのに要るもの** — 時間・場所・準備・同伴者。手ぶらでいますぐ使えるなら、劇の道具として弱い
- **読者が思い出す一点** — 傷、色、欠け、匂い、重さ、音のどれか。隠せる大きさかもここで決める（逃げる場面の書き方が変わる）
- **最終話でどこにあるか** — 渡す、捨てる、壊す、埋める、持っている。出口を先に決めると途中の扱いが締まる

### 4-3. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「強力な剣です」 | 「その剣を持った主人公が負ける場面は書けますか。書けないなら、剣が強いぶん、以後すべての戦闘の緊張が消えます」 |
| 「形見のペンダントです」 | 「形見であることは、本文のどの場面で効きますか。効く場面がないなら、いまは持たせるだけにして、設定は増やさないほうがいいです」 |
| 「便利な道具です」 | 「便利さは物語の敵になりやすいです。その道具を使うと事態が悪くなる場面を 1 つ作れませんか」 |
| 「魔法の鍵です。あらゆる扉を開けます」 | 「開かない扉を 1 つ決めてください。その 1 つが、たぶん終盤の扉になります」 |
| 「特に意味はない小物です」 | 「意味がないほうがいい小物もあります。ただ、用語集に登録するかは別です。本文で二度以上出るなら登録、一度きりなら登録しない、でどうですか」 |

### 4-4. 決まったことの振り分け

```
名前: 潮見の錠 ／ 分類: アイテム
公開情報:
灯台の扉に付いている真鍮の南京錠。海風で緑青が浮き、鍵を差すたびに軋む。
鍵は二本あり、当番の二人が一本ずつ持つ決まり。
```

```
名前: 合鍵の台帳 ／ 分類: アイテム ／ 別名: 台帳
公開情報:
生活支援課が預かる、市営住宅の合鍵の受け渡し記録。表紙は色あせた緑のバインダー。
持ち出しには課長の印が要り、返却まで一日でも空くと理由を書く欄がある。
```

```
作者メモ:
二本目の鍵は二十年前から行方不明。町長が持っている。
第三部で扉が内側から開いていた理由がこれ。→ foreshadow「二本目の鍵」
```

アイテムはほぼ必ず伏線になるので、`plant` と `payoff` を最初に決める。

```
title: 二本目の鍵
note: 第一部で「鍵は二本」と当番の会話に一度だけ出す。第三部で内側から開いていた扉に繋げる。
plant_beat_id: <第一部・当番の引き継ぎビート>
payoff_beat_id: <第三部・扉が開いているビート>
```

扱いの決まりが作品全体に効くなら `rules` へ（書く前に現在の本文を読む。全置換）。
「道具で問題を解決しない。持ち物は第一話で全部見せておく」のような一行がここに入る。

物の受け渡しは出来事なので、用語集ではなくビートに置く。ビートの `summary` に
「◯◯が××へ渡す」と書く。用語集の中に受け渡しの経緯を書くと、時系列が本文と切れる。

### 4-5. 質が落ちる兆候

**兆候A：ご都合の道具** ｜ 強さ：止める

窮地の直前に持っていたことが判明する。

> 「これは入れないほうがいい。入れると第六話の切り抜け方が成立しません。袋から出てきたこの
> 道具を、第一話の時点で持っていたことを読者は知りません。持たせるなら第一話で見せておきましょう。
> 見せられないなら、この場面は道具なしで切り抜けさせるほうが強くなります」

**兆候B：壊れない・失くさない** ｜ 強さ：反対する

> 「この物、全編を通して一度も持ち主の手から離れません。これは反対です。持ち続けているだけだと、
> 読者はこの物を装備品として見ます。一度奪われて取り返すか、壊れてそれでも進むか、
> どちらかを入れませんか」

**兆候C：由来が精緻で、いまの話に繋がらない** ｜ 強さ：気になる

鍛冶師の名、製作年、素材の産地が公開情報に並んでいる。

> 「由来の 6 行を、本文で誰かが口にする場面がありません。ここは弱いと思います。ただ設定として
> 持っておきたいなら好みの範囲です。この 6 行のうち、持ち主が知っていることは何行ですか。
> 持ち主が知らないことは `author_note` へ移しましょう」

### 4-6. アイテムに固有の矛盾検査

- 所在の時系列が本文と一致しているか。第 N 話で渡した物が第 N+2 話で元の持ち主の手にある、という取り違えが起きやすい
- 大きさ・重さ・隠せるかが、本文の逃走・潜入の場面と矛盾していないか
- `special` に書いた仕組みの制限を、このアイテムだけが越えていないか

## 5. 生物

### 5-1. 最初の問い

> **いま分かっていること**：この生き物は `summary` に「凶暴な魔物」とあり、第四話と第八話の
> ビートに `place` で結ばれた森が舞台として入っています。
>
> **見立て**：凶暴さは人から見た結果で、生態がまだありません。生態が決まらないと、
> 出没する場所と時刻を作者が毎回決め直すことになります。
>
> **問い**：それは何を食べますか。その餌は、この土地にありますか。寝床はどこですか。

食性と寝床が決まると、出没する場所と時刻が自動的に決まる。

### 5-2. 続けて拾う論点

- **人との距離** — 飼っている／狩る／狩られる／住み分けている／気づかれていない。かつては飼っていていまは狩られる側、なら転落の事件がある
- **数** — 一頭か、群れか、いくらでも湧くか。いくらでも湧くなら、なぜ町が滅びていないか
- **人の側の対応** — 狩ってよい時期、近づいてはいけない場所、見たときの作法、供養、届出。殺した人は咎められるか、褒められるか、何も起きないか。人の側が決まると、生き物が世界に定着する
- **遭遇の兆し** — 姿より先に何で察するか。音、匂い、鳥が黙る、水が濁る、犬が怯える
- **主人公との一件** — 群れの一匹ではなく、あの一匹として向き合う場面があるか
- **種の項目か、あの一匹か**（→ 5-3）

### 5-3. 種の項目か、あの一匹か

生物は、種の名前と個体の名前が 1 項目に同居しやすい。同居させると `[[潮鳴き]]` が
どちらを指すか本文で決まらなくなる。

> 「この項目は種の説明ですか、あの一匹ですか。両方要るなら、項目を 2 つに割って、個体のほうは
> 分類を『人物』に寄せる手もあります。アプリの画面でビートの `登場` に出てくる候補は
> 分類が『人物』の項目と、分類が空の項目だけなので、個体を出すならそちらへ寄せておくと後が楽です」

### 5-4. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「凶暴な魔物です」 | 「凶暴なのは、腹が減っているからですか、縄張りを侵されたからですか、痛いからですか。理由がある凶暴さのほうが怖いです」 |
| 「森に住む幻獣です」 | 「幻というのは、目撃例が少ないという意味ですか、実在が疑われているという意味ですか。どちらかで、町の人の反応が変わります」 |
| 「主人公の相棒の獣です」 | 「その獣は、主人公の言うことを聞かない場面がありますか。全部聞くなら、それは道具です」 |
| 「知能が高く、人語を解します」 | 「では、それは生物ではなく人物として書けるということですか。人物なら分類を『人物』に移して、人物として掘りましょう。アプリの画面でビートの `登場` に出てくる候補も、分類が『人物』の項目と分類が空の項目だけです」 |
| 「見た目は狼に似ています」 | 「似ているものを言うと、読者は狼を思い浮かべて終わります。狼と決定的に違う一点を挙げてください」 |

### 5-5. 決まったことの振り分け

```
名前: 潮鳴きの群 ／ 分類: 生物 ／ 別名: 潮鳴き
公開情報:
凪の夜だけ岬の沖に浮かぶ、掌ほどの発光する魚の群れ。
灯台の光に集まる性質があり、当番はこの群れが来た夜を「当たり夜」と呼ぶ。
獲るのは禁じられていて、網にかかったものはその場で海へ返す。
```

現代物でも枠は同じで、人の側の対応まで書くと定着する。

```
名前: トラ ／ 分類: 生物 ／ 別名: 三号棟の猫
公開情報:
三号棟の駐輪場に居ついた雉虎の猫。左耳の先が切れている（不妊手術済みの印）。
自治会が餌やりの当番を回していて、集会室の前では餌をやらない決まり。
```

```
作者メモ:
禁漁の理由は、二十年前に獲った船が全員戻らなかったから。
町の人はこの理由を口にしない（＝本文でも説明させない）。→ secret「当たり夜の船」
```

人との関わりの決まりは `society`（「海のものを獲る・獲らないの線引きが人の格を決める」）、
生態が世界の仕組みなら `special`、禁忌は `rules` へ。どの枠も書く前に現在の本文を読む（全置換）。
`society` は場所と組織の掘り下げでも書く枠なので、順に上書きすると先に書いたほうが消える。

遭遇は出来事なので、ビートを立てて `place` に生息地の entry_id を結ぶ（配列なので現在の全件＋1 件）。
個体として登場するなら `cast` に入れてよい。

### 5-6. 質が落ちる兆候

**兆候A：図鑑になっている** ｜ 強さ：反対する

体長・体重・生息域・繁殖期が並び、物語との接点がない。

> 「この 8 行は生態の記述で、これは反対です。読者が知りたいのは、近づいていいのか、逃げるべきか、
> それを見た人がどんな顔をするかで、そのどれも入っていません。8 行を 3 行に落として、
> 残りは `author_note` へ移しませんか」

**兆候B：強すぎて、勝ち方が説明できない** ｜ 強さ：反対する

> 「この生き物に、主人公はどう勝ちますか。いまの設定だと勝てません。これは反対です。
> 終盤で急に弱点が出てくるのが、いちばん読者が冷める形になります。弱点を先に足すか、
> 勝たない話にするか、決めてください」

**兆候C：生態が話の都合で変わる** ｜ 強さ：気になる

夜行性のはずが昼に出る、群れないはずが群れる。

> 「第二話では単独でしたが、第六話で群れています。どちらが本当ですか。群れることに理由が
> あるなら、それは事件なので書く価値があります。理由がないなら第六話を直しましょう」

### 5-7. 生物に固有の矛盾検査

- 活動時間・食性・生息域を、既出の本文が破っていないか
- 数と被害の規模が、町の人口・存続と矛盾していないか
- 種と個体が 1 項目に同居していないか。意思と会話があるものが「生物」に残っていないか

## 6. 掘り終えたあとの締め（分類を問わず必ず通す）

### 6-1. 呼び名を回収する

分類を問わず最後に一度だけ聞く。

> 「本文でこの項目を指す言い方を全部挙げてください。正式名称、略称、登場人物の口から出る言い方、
> 蔑称、俗称。地の文で使う標準はどれですか」

標準を `name` に、残りを `aliases` に入れる。`aliases` は配列なので、**現在の全別名＋追加ぶんを
並べた配列**を渡す。1 つだけ渡すと、それまでの別名が消えて本文の `[[ ]]` が未解決に落ちる。

### 6-2. 登録数と本文出現数を数える

用語集に 14 件あって本文に名前が出ているのが 3 件、という状態は分類を問わず起きる。
`get_plot` はビートごとに「舞台: 灯台守の家」の一行を出すだけで集計はしないので、
**数えるのは編集者の仕事**。`get_work` と `get_plot` を読んで、自分で数えてから言う。

> 「用語集の場所が 14 件あって、本文に名前が出ているのは 3 件です。残り 11 件は、いまのところ
> 作者だけが読む地図になっています。この 3 件を厚くして、残りは `set_world_note` の自由枠へ
> 移しませんか」

自由枠へ逃がすときは `slot: custom` に `title` を付ける。2 回目からは `get_world` の
`[note_id: …]` を渡す。渡さないと同じ見出しの枠が増えていく。

### 6-3. 書き込む前に、いまの本文を読み直す

`summary` はパッチの欄だが、**渡せば旧文はその内容に置き換わる**。追記のつもりで 1 行だけ渡した
結果、既存の 5 行が消える事故が起きる。`get_glossary` で現在の全文を読み、既存＋追加を
組み立てた全文を渡す。`set_world_note` の `body` も同じで、こちらは枠ごと全置換になる。

`upsert_glossary_entry` は `name` が毎回必須なので、`get_glossary` が返した名前をそのまま渡す。
表記を思い出しで書くと意図しない改名になる。`thumbnail` は MCP の引数に無いので、
コネクタ越しの書き込みで消えることはない。

### 6-4. 分類を問わない矛盾検査（この 5 つは毎回通す）

1. `get_world` の `rules` / `special` / `society` / `forbidden` と、この項目の設定が衝突していないか
2. `summary` に真相が混ざっていないか。判定はビートの前後ではなく、**その語が本文に初めて出る話**。
   その話まで読んだ読者に見せてよいものだけが `summary` に載る。真相は `author_note` と `secret` が持つ
3. 旧「詳細」欄（`body`）に昔書いたものが残っていないか。公開バンドルは `summary` と旧 `body` を
   **結合してから送る**ので、`summary` が綺麗でも旧欄の真相は公開に載る。
   `get_glossary` が返す公開情報の全文（結合後）を読んで確かめる
4. この項目を `place` か `cast` で参照しているビートが 1 つ以上あるか。0 件なら本文に出る予定がない
5. 既出の本文で使われている呼び名・俗称・蔑称が、`name` か `aliases` に入っているか

書き込んだあとは `get_glossary` と `get_plot` を読み直す。
`[未回収]` `[根なし]` `[開示未定]` が増えていないかを見る（表記の一覧は共通リファレンス §4）。
とくに `[根なし]`（回収だけあって張るビートが無い）は、掘り下げの途中でビートを差し替えたときに増える。

### 6-5. 届き先を確認して終える

> 「いま決まったことのうち、読者に届くのはどれですか。公開情報に置いた行だけが届きます。
> それ以外は、本文で誰かが言うか、やるかしない限り、読者には存在しません。届けたい 1 行を選んで、
> どの話で出すか決めましょう」

どの器にも入らないものは、いま要らない設定として保留にする。振り分けの一覧は
共通リファレンス §2、書き込みの順番と同意の取り方は同 §6。
