# 用語集「人物以外」を掘る観点

場所 / 組織 / 用語（世界の仕組み・制度・概念） / アイテム / 生物 の 1 件を掘り切るための観点表。
人物は `angles-person.md`。

器の分かれ方・書き込みの規約は
`.claude/skills/kotonaha-editing-common/references/kotonaha-mcp.md`、
問いの投げ方と反対の仕方は同 `editor-stance.md`。

## 0. 分類を問わず先にやること

### 0-1. 着手前の 2 つ

**`get_world` の `rules`（この作品の約束事）と `special`（固有の仕組み）を読む。**
既存の縛りがあるなら、これから作る項目はその中で作る。読まずに作った項目は、
あとで `rules` と衝突して丸ごと捨てることになる。

**その項目が本文に出ているかを `get_work` で確かめる。**
一度も出ていない項目を掘るときは、最初の問いが変わる（→ 0-4）。

### 0-2. 振り分けの判定（毎回この順で聞く）

| 問い | Yes なら |
|---|---|
| その文は、その 1 件の名前を引いた読者が読んで得をするか | 用語集 `summary`（公開情報） |
| その 1 件に紐づくが、いま読者に伏せているか | 用語集 `author_note`（非公開） |
| その 1 件を超えて、作品全体・他の項目にも効く決め事か | `set_world_note`（`rules` / `special` / `society` / `stage` ほか） |
| 「読者がいつ知るか」を管理したいか | `upsert_secret`（`truth` ＋ `reveal_beat_id`） |
| 「どの話で置いて、どの話で効かせるか」を管理したいか | `upsert_foreshadow`（`plant_beat_id` → `payoff_beat_id`） |
| 出来事として本文に起こす必要があるか | `upsert_plot_beat`（`place` に entry_id を結ぶ） |

迷ったら判定はひとつ。**「この文は、他の項目を書くときにも参照するか」。**
参照するなら世界観設定、その項目を読むときにしか要らないなら用語集。

### 0-3. `author_note` と `set_world_note` を混ぜないための線

`author_note` は「この項目の裏」、`set_world_note` は「作品の法律」。同じネタバレでも置き場が違う。

- 「この灯台は、第三部で焼ける」→ 灯台の `author_note`（その項目の未来）
- 「この作品では、建物が焼けたら二度と再建されない」→ `set_world_note`（`slot: rules`・全項目に効く法律）

作者が後者を用語集の公開情報に書いてしまうのが、いちばん多い事故。

### 0-4. 本文に出ていない項目に最初に投げる問い

> 「この項目、いま何話目に出ていますか。まだ出ていないなら、**出す予定の話を 1 つ**決めてから
> 中身を詰めませんか。出る場所が決まらないうちに設定を積むと、そのぶんは公開されない設定資料になります」

出す予定が無いなら、用語集に作らず `set_world_note` の自由枠（`slot: custom`）へ寄せる選択肢を出す。

## 1. 場所

### 1-1. 掘る順番と問いの文面

**① 五感の一点から入る（先に地図を描かせない）**

> 「その場所に立ったとき、**最初に鼻か耳に来るもの**は何ですか。目に見えるものは後回しでいいです」

地図・広さ・地理から入ると、作者は「説明できる場所」を作ってしまう。匂いと音から入ると、本文にそのまま書ける行が最初に手に入る。

**② 誰の場所か**

> 「その場所は、次のどれですか。
> A：主人公が毎日いる場所（日常）
> B：主人公が入ってはいけない場所（禁域）
> C：主人公が一度だけ行って、帰ってくる場所（往還）
> D：主人公が最後に辿り着く場所（終点）
> E：誰かの持ち物としての場所（他人の領域）」

選ばれた型で、次に聞くことが変わる。A なら「そこが壊れる話はどこか」、B なら「破ったらどうなるか」、C なら「行った前後で主人公の何が変わるか」、D なら「そこに至るまでに何を捨てるか」、E なら「主人公はどうやって入る許可を得るか」。

**③ そこでしか起きない出来事**

> 「その場所で起きる出来事のうち、**別の場所に移したら成立しなくなるもの**を 1 つ挙げてください」

これに答えられない場所は、名前を付けた背景でしかない。

**④ 出入りの条件**

> 「誰が入れて、誰が入れませんか。入るのに要るものは、鍵・金・身分・時刻・同伴者・体調のどれですか」

出入りの条件は、そのままビートの障害になる。

**⑤ 時間による変化**

> 「昼と夜、あるいは今と 10 年前で、その場所の何が違いますか。**同じなら『同じ』と答えてください**」

**⑥ その場所が抱えている損傷**

> 「その場所は、いま何を失いつつありますか。人が減っている、朽ちている、買い取られようとしている、水位が上がっている、誰も来なくなった、のどれかに近いですか」

無傷の場所は物語に働かない。

**⑦ 呼び名**

> 「その場所を、**登場人物はどう呼んでいますか**。正式名称と、主人公の口から出る言い方は同じですか」

別名は `aliases` に入れる。本文の `[[ ]]` が未解決に落ちるのを防ぐ実務的な効き目もある。

### 1-2. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「静かな港町です」 | 「静かというのは、**何の音がしないこと**ですか。工場が止まったのか、子どもがいないのか、風がないのか。どれかで町の履歴が変わります」 |
| 「古い洋館です」 | 「古いと分かるのは、住人の誰が見たときですか。**そこで育った人には古く見えない**はずです。誰の目で書きますか」 |
| 「王都です。人口は 30 万で、東西に大通りが……」 | 「規模はいったん置きます。主人公が**そこで一度も見ていない区画**はどこですか。読者に見せない場所を決めるほうが、王都が広く感じます」 |
| 「主人公の家です」 | 「その家で、主人公が**触らない物**はありますか。触らない物が 1 つあれば、家が過去を持ちます」 |
| 「学校の屋上です」 | 「その屋上、いつ施錠されていますか。**入れてしまう理由**が要ります。開いている理由を作ると、それ自体が誰かの事情になります」 |
| 「森です。魔物が出ます」 | 「魔物を抜いて、その森を一言で言えますか。言えないなら、いまその森は『危険』という機能の別名です」 |

### 1-3. 決まったことの振り分け

**用語集の `summary`（公開情報）へ** — 読者がその場所の名前を本文で見た直後に読んで得をすること。

```
名前: 灯台守の家
分類: 場所
別名: 岬の家, あの家
公開情報:
岬の先端に立つ二階建て。海側の窓は塩で白く曇り、いつも潮と灯油の匂いがする。
下の階が灯台の管理小屋、上の階が住居。夜通し灯を回すため、住人は昼に眠る。
```

**`author_note`（非公開）へ** — その場所の未来、その場所の裏。

```
作者メモ:
第三部で焼ける。焼けた跡から、床下の手紙束が見つかる（→ secret「母の出自」）。
アカリが二階へ上がらないのは、母が落ちた階段だから。本人にはまだ書かせない。
```

**`set_world_note` へ** — その場所を超えて効く決まり。line 単位で示すと次のようになる。

```
slot: stage（時代と場所）
現代日本、日本海側の県。県庁所在地から鉄道で二時間。冬は十二月から三月まで曇りが続く。
夜が早く、午後五時には店が閉まる。この暗さを全編の基調にする。
```

```
slot: society（人を縛るもの）
土地は買われる側。町の主要な建物はすべて外部資本の持ち物で、住民は借りて住んでいる。
「自分の場所」を持っている人物は、この作品には一人も出さない。
```

```
slot: rules（この作品の約束事）
建物が焼けたら再建しない。失われた場所は失われたまま話が進む。
主人公が困ったときに「たまたま開いていた場所」を出さない。入る場所には必ず入る手段を先に置く。
```

**`upsert_secret` へ** — その場所について、読者がまだ知らないこと。

```
title: 灯台守の家の床下
truth: 母が出て行かなかったこと、そして家に留まったまま死んだこと。床下の手紙束がその証拠。
reveal_beat_id: <焼け跡のビート>
```

**`upsert_plot_beat` へ** — 場所は `place` に entry_id で結ぶ。結んでおくと `get_plot` の出力に「舞台: 灯台守の家」が出て、場所ごとの登場回数が数えられる。

### 1-4. 質が落ちる兆候と、編集者が言うべき反対意見

**兆候A：入れ替え可能な場所**
そこで起きた出来事を別の場所へ移しても、話が成立してしまう。

> 「率直に言って、この港町は駅前でも成立します。**港でなければ起きないこと**をひとつ足すか、舞台を駅前に変えて港を削るか、どちらかを選びませんか。両方あると、港の描写ぶんだけ読者の集中が減ります」

**兆候B：地図が精緻で、主人公が行かない**
方位・距離・区画・人口が用語集に積まれているのに、本文に出るのは 2 か所だけ。

> 「用語集の場所が 14 件あって、本文に名前が出ているのは 3 件です。残り 11 件は、いまのところ**作者だけが読む地図**になっています。この 3 件を厚くして、残りは `set_world_note` の自由枠へ移しませんか」

**兆候C：場所が壊れない**
全編を通して同じ状態のまま。読者にとっては背景画のまま。

> 「この場所、最終話でも冒頭と同じ姿ですか。**同じなら、それが主人公の敗北の証か、救いの証か**、どちらとして書くか決めてください。ただ変わらないだけだと、読者は読み終えてもその場所を覚えていません」

**兆候D：名前だけが増える**
地名が 20 件あって、どれも「〜の街」「〜の森」で、読者が区別できない。

> 「地名は覚えられる数に上限があります。**主人公が二度以上足を運ぶ場所**だけ固有名を付けて、あとは『隣町』『峠』のような普通名詞に落としませんか」

**兆候E：観光案内になっている**
`summary` が名所紹介の文体。物語と接続していない。

> 「公開情報の 4 行、読者がこれを読んで**次の話が読みたくなる箇所**がありません。誰かがここで何かを失った、という一行を足せますか」

**兆候F：距離と移動時間が話の都合で伸縮する**

> 「第二話では日帰りだった岬に、第七話では一泊しています。どちらが正しいですか。決めた側を `set_world_note` の `stage` に一行で置いて、以後はそれに従いましょう」

### 1-5. 矛盾検査のチェック項目

- `get_world` の `stage` にある気候・時代・交通と、`summary` の描写が矛盾していないか（冬に閉ざされる街道と、冬の往来の描写）
- `rules` の禁止（「都合のいい偶然で助けない」等）を、その場所の出入り条件が破っていないか
- `forbidden`（やらないこと）に触れる描写を `summary` が含んでいないか
- `place` にその entry_id を持つビートが 1 つ以上あるか。0 件なら本文に出る予定がない
- その場所に関する `secret` の `reveal_beat_id` より前のビートで、`summary`（＝公開情報）がすでに真相を漏らしていないか
- `foreshadow` の `plant_beat_id` が置かれたビートの舞台と、その場所が食い違っていないか
- 既出の本文（`get_work`）で使われている呼び名が、`name` か `aliases` のいずれかに入っているか。入っていないと `[[ ]]` が未解決になる
- 別の場所の項目に、同じ地形・同じ役割が二重に書かれていないか（統合候補）

## 2. 組織

### 2-1. 掘る順番と問いの文面

**① 主人公との接点から入る（組織図から入らない）**

> 「その組織と主人公は、**どこで初めて触れますか**。呼び出される、断られる、追われる、雇われる、拒まれる、のどれに近いですか」

組織は「主人公に何をする存在か」から作る。階級表を先に作ると、そのほとんどが本文に出ない。

**② 何で食っているか**

> 「その組織の**金と人はどこから来ますか**。会費、税、寄進、上納、補助金、商い、略奪、のどれですか」

収入源が決まると、組織が何を嫌がるかが決まり、主人公が交渉する材料が生まれる。

**③ 誰が決めるか、決めた人は間違えるか**

> 「その組織で最終決定をする人は誰ですか。その人が**間違った決定をした過去**はありますか。ないなら、いま作りませんか」

**④ 中の温度差**

> 「その組織の中で、**方針に納得していない人**は誰ですか。名前がまだないなら、役職だけでいいです」

一枚岩の組織は、敵としても味方としても平坦になる。

**⑤ 外からどう見えているか**

> 「町の人はその組織を、次のどれとして見ていますか。
> A：頼りにしている
> B：怖がっているが逆らわない
> C：見て見ぬふりをしている
> D：存在を知らない
> E：かつては A だったが、いまは B」

E があるなら、その転落の理由が `history` に入る。

**⑥ 破門・脱退の条件**

> 「その組織から抜けるとどうなりますか。抜けられないなら、**抜けようとした人がどうなったか**を 1 例決めてください」

出口の設計が、そのまま終盤の緊張になる。

**⑦ その組織が守っている秘密**

> 「その組織が隠していることは何ですか。**組織の全員が知っている秘密か、上層だけが知っている秘密か**、どちらですか」

**⑧ 呼び名の運用**

> 「所属している人は自分たちを何と呼び、外の人は何と呼びますか。蔑称はありますか」

### 2-2. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「町を守る自警団です」 | 「守っていることになっている、の間違いではありませんか。**守れなかった事件**が一件あると、団の顔つきが変わります」 |
| 「巨大企業です。悪の組織です」 | 「そこで働いている人の**大半は普通に通勤して普通に帰る**はずです。悪意ではなく、何の合理で人が死にますか」 |
| 「五つの部門があり、それぞれ長がいて……」 | 「主人公が本文で会話する相手は、そのうち何人ですか。**会わない部門は、いま作らなくていい**です。会う一人を深く決めましょう」 |
| 「教団です。教義は……」 | 「教義より先に、**信者が毎朝やること**を 1 つ決めてください。所作が決まると教義が後から立ちます」 |
| 「主人公の敵です」 | 「その組織にとって、主人公は**敵ですらない**という線はありませんか。相手にされないほうが、主人公は苦しみます」 |
| 「代々続く旧家です」 | 「続いているのは何ですか。土地、名前、借金、負い目、墓。続いているものが決まると、主人公が背負うものが決まります」 |

### 2-3. 決まったことの振り分け

**`summary`（公開情報）** — 読者がその組織の名を見たときに要る最小限。役職表は入れない。

```
名前: 灯明講
分類: 組織
別名: 講, 岬の講
公開情報:
岬一帯の漁師が入る互助の講。年に四度、灯台の油代を出し合う。
入るには家ごとの推薦が要り、抜けた家とは船を並べない。
```

**`author_note`（非公開）**

```
作者メモ:
講の油代は二十年前から集まっていない。差額を出しているのは町長個人。
その理由（息子の事故の口止め）は第四部まで伏せる。→ secret「町長の負い目」
```

**`set_world_note` へ** — 組織の存在の仕方が世界の仕組みなら、そちらへ。

```
slot: society（人を縛るもの）
この町では、家単位で組織に属する。個人で入る・抜けるという発想がない。
「一人だけ抜ける」は、この作品では最大級の逸脱として扱う。
```

```
slot: rules（この作品の約束事）
組織は主人公を助けない。組織が動くのは組織の利益のときだけで、
主人公の窮地に間に合って現れることは最後までない。
```

```
slot: history（ここまでの経緯）
二十年前の転覆事故で、講は乗組員七人のうち三人しか捜さなかった。
以後、捜されなかった三家は町に残っているが、講には戻っていない。
```

**`upsert_secret` へ**

```
title: 講が捜索を打ち切った理由
truth: 沖の漁場が他県の権利になることを恐れ、事故当日に境界を越えていた事実を隠した。
reveal_beat_id: <第四部・記録が出るビート>
```

**ビートへ** — 組織は「顔のある一人」に置き換えて `cast` に入れる。組織そのものを `cast` に入れても本文は書けない。

### 2-4. 質が落ちる兆候と、編集者が言うべき反対意見

**兆候A：組織図が細かいのに、主人公が誰とも会わない**

> 「役職が 9 つ書いてありますが、本文で口をきくのは受付の一人だけです。**残りの 8 つは読者に届きません**。9 人ぶんの設定を、その受付一人の困りごとに畳み込めませんか。受付が板挟みになっているほうが、組織の大きさが伝わります」

**兆候B：組織が主人公の都合で動く**
危機のたびに援軍を出し、必要なときに情報をくれる。

> 「この組織、いまのところ主人公の**便利な後ろ盾**になっています。一度でいいので、正しい理由で主人公を見捨ててもらえませんか。見捨てられて初めて、読者はこの組織の原理を理解します」

**兆候C：悪の組織が悪であることしか設定されていない**

> 「その組織が**自分たちを正しいと思っている理由**を一行ください。悪だと自認している組織は、読者にとって舞台装置です」

**兆候D：組織名が増え、勢力図が主役になる**

> 「勢力が 6 つあって、主人公はそのうち 2 つとしか関わりません。**残り 4 つの抗争は本文に出せますか**。出せないなら、いまは 2 つに絞って、残りは `set_world_note` の自由枠に置いておきましょう。読者は勢力図を覚えるために読んでいません」

**兆候E：組織が滅びない・変わらない**

> 「終盤でこの組織はどうなりますか。**何も起きない**なら、それは主人公の行動が世界に届かなかったという話になります。それでいいなら、そう書きましょう。よくないなら、傷をひとつ決めてください」

**兆候F：組織の内部が全員同意している**

> 「この組織の中で、**主人公に同情している人**は一人もいませんか。一人いるだけで、組織の壁が厚く見えます」

### 2-5. 矛盾検査のチェック項目

- `society`（人を縛るもの）に書いた原理と、その組織の入退の条件が食い違っていないか
- `rules` に「組織は主人公を助けない」と書いてあるのに、`place` / `cast` を見ると救援のビートが立っていないか
- `history` に書いた過去の事件と、`summary` の年数・人数が一致しているか
- その組織の秘密（`secret`）を知る人物が、開示ビートより前のビートに登場して沈黙している理由が説明できるか
- 組織に関する伏線の `plant_beat_id` が、その組織が本文に初登場するビートより前になっていないか
- 用語集の他の項目（人物）の `summary` に、組織の未公開の内情が漏れていないか
- `forbidden`（やらないこと）に「章間に神視点の解説を挟まない」等がある場合、組織の説明をどこで本文に載せるかが決まっているか
- 既出の本文で使われている組織の呼び名・蔑称が `aliases` に登録されているか

## 3. 用語（世界の仕組み・制度・概念）

> ここがいちばん壊れやすい。**仕組みは用語集ではなく世界観設定で決める**のが原則で、用語集にはその名前と、読者が知ってよい範囲だけを置く。

### 3-1. 掘る順番と問いの文面

順番を守る。**できることを先に聞かない。** 先に聞くと、作者は万能に近い仕組みを作り、あとで縛れなくなる。

**① それが無かったとき、人はどうしていたか**

> 「その仕組みが**まだ無かった頃**、人はその用事をどう済ませていましたか。無かった頃がないなら、この世界は最初からそれと共にあるということでいいですか」

**② できないこと（最初に聞く）**

> 「その仕組みで**絶対にできないこと**を 3 行ください。数は 3 でなくていいので、思いつくだけ。
> とくに知りたいのは、**いまの主人公の困りごとを、それで解決できない理由**です」

これに答えられない仕組みは、書き進めた先で必ず物語を殺す。

**③ できること（境界を先に決めてから聞く）**

> 「では、できることを書いてください。②で決めた線の**内側だけ**でお願いします」

**④ 代償**

> 「一度使うと、何が減りますか。次のどれに近いですか。
> A：体（消耗・寿命・欠損）
> B：物（材料・金・道具の消滅）
> C：関係（信用・立場・誰かの死）
> D：記憶や心（忘れる・壊れる・変質する）
> E：時間（準備・待機・反動の期間）
> F：減らない（＝代償なし）」

F を選んだ場合の追撃は 3-2 に置く。

**⑤ 誰が使えるか**

> 「使える人は、生まれで決まりますか、訓練で決まりますか、免許で決まりますか、道具を持っているかで決まりますか。
> 主人公は**その資格を持っていますか、持っていませんか**」

主人公が持っていない側だと、話の運びが自動的に良くなることが多い。持っている場合は⑥⑦が必須になる。

**⑥ 例外**

> 「その仕組みが**効かない相手・場所・条件**はありますか。無いなら、ひとつ作りませんか。効かない条件があると、敵を強くしないまま緊張を上げられます」

**⑦ 世に知られているか**

> 「その仕組みは、次のどれですか。
> A：全員が知っていて、日常に組み込まれている（電気のような扱い）
> B：全員が知っているが、扱えるのは限られる（法律・医療のような扱い）
> C：噂としては知られているが、実在は疑われている
> D：一部だけが知っていて、隠している
> E：主人公だけが知っている」

この選択で、本文の説明の量が決まる。A なら説明しない。E なら主人公の驚きとして書ける。**作者が A のつもりで書きながら、読者向けに説明を挟むと世界が薄くなる。**

**⑧ それでいまの葛藤が消えないか（必ず最後に確認する）**

> 「いま決まった内容で、第○話の◯◯という問題は、**その仕組みを使えば解決してしまいませんか**。しないなら、なぜしないのか一行で言ってください」

答えられないなら、②か④へ戻る。

**⑨ 誰が管理しているか（制度の場合）**

> 「その制度を運用しているのは誰ですか。運用者は**その制度で得をしていますか**」

**⑩ 名前の来歴**

> 「その名前は誰が付けましたか。使う人と、外の人で呼び方は違いますか」

### 3-2. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「代償はありません」 | 「代償なしで通すのはひとつの選択です。ただ、そのときは**使える人が極端に少ない**か、**使うと誰かに知られる**か、どちらかの縛りが要ります。どちらを取りますか。両方無いと、以後この仕組みが出るたびに読者は『それで全部解決するのでは』と考えます」 |
| 「魔力が減ります」 | 「魔力が減ると、**その日の何ができなくなりますか**。寝れば戻るなら、それは実質的に代償として働きません。戻るまでの時間を決めてください」 |
| 「使いすぎると死にます」 | 「その『使いすぎ』の線を、**主人公が知っているか**で意味が変わります。知っているなら計算ができ、知らないなら恐怖になります。どちらで書きますか」 |
| 「なんでもできます」 | 「では、この仕組みを持つ人がなぜ世界を支配していないのですか。支配していないなら、その理由がそのまま『できないこと』です」 |
| 「原理は誰も知りません」 | 「知らないことにするのはいい判断です。そのぶん、**知らないまま使っている人の作法**が要ります。使う前に何をしますか。手順・祈り・道具・場所のどれかを決めましょう」 |
| 「昔からある制度です」 | 「昔からあるものは、**当初の目的とずれて運用されている**のが普通です。ずれはありますか。ずれがあれば、それを利用する人物が書けます」 |
| 「主人公だけが使えます」 | 「主人公だけが使えると、**負ける理由**を毎回別に作ることになります。同格の使い手を一人置くか、主人公の使い方に欠陥を置くか、どちらにしますか」 |
| 「使うと目立つので隠しています」 | 「隠しているなら、**バレたときの罰**を決めてください。罰が決まっていないと、隠す緊張が読者に伝わりません」 |

### 3-3. 決まったことの振り分け（ここは line 単位で厳密に）

**原則：仕組みのルール本体は用語集に書かない。** 用語集の `summary` に置くのは、読者がその語を本文で見たときに要る最小限の説明だけ。ルール・限界・代償・例外は `set_world_note` の `rules` と `special` が持つ。理由は 2 つ。用語集は公開経路に載る（限界と抜け道を先に読まれると仕掛けが死ぬ）。そして仕組みは複数の項目にまたがって効くので、1 項目の中に書くと参照しきれない。

**用語集 `summary`（公開情報）に置くもの**

```
名前: 灯継ぎ
分類: 用語
別名: 継ぎ, 火継ぎ
公開情報:
夜通し灯を絶やさないために、二人一組で交代しながら火を守る当番のこと。
組になれるのは血の繋がらない者どうしと決まっていて、組んだ相手は「灯兄弟」と呼び合う。
```

読者がこの語を本文で見たときに要るのは、当番であること、二人組であること、呼び名がつくこと。**それ以上は書かない。**

**用語集 `author_note`（非公開）に置くもの** — その語に閉じた裏。

```
作者メモ:
「血の繋がらない者どうし」という決まりは、火が血縁者を選んで襲うから。
この理由は最終部まで伏せる。→ secret「灯が血を選ぶ」
アカリとトウマが組めるのは、二人が兄妹でないという前提が公にされていないため。
```

**`set_world_note(slot: 'special')` に置くもの** — 仕組みの本体。できること／できないこと／代償／資格／例外／認知度を、この 1 枠に集約する。

```
slot: special（固有の仕組み）
【灯】人の記憶を燃料に燃える火。灯台の光はこれで保たれている。

できること
- 灯にくべた者の記憶を、他の一人に移せる（移せるのは一度きり、移した本人からは消える）
- 灯の届く範囲では、海が凪ぐ

できないこと
- 死者の記憶は燃えない。死んだ人間から何かを取り戻す用途には一切使えない
- 移した記憶を戻すことはできない
- 火は消せない。消えるのは燃料が尽きたときだけ
- 灯そのものを移動できない。灯台から離れた場所では起きない

代償
- くべた記憶は本人から永久に消える。何を失ったかも思い出せない
- 一度くべた者は、以後その灯の光を見ると眩暈がする（体に残る）

使える人
- 資格はない。誰でもくべられる。だから危ない
- ただし、くべ方を知っているのは灯継ぎの当番経験者だけ（手順が口伝）

例外
- 血縁者どうしでくべると、両方の記憶が燃える（＝灯兄弟の決まりの理由）

世に知られているか
- C（噂としては知られているが、実在は疑われている）。町の年寄りは信じ、若い世代は迷信と思っている。
  本文では「灯にくべる」という言い回しだけが慣用句として残っている形で出す。

いまの葛藤との関係
- 主人公は母の死の理由を知りたいが、死者の記憶は燃えないので灯では解けない。
  灯は「知る」役には立たず、「捨てる」役にしか立たない。ここを最後まで動かさない。
```

最後の「いまの葛藤との関係」の 2 行が、この枠のいちばん働く場所になる。仕組みを足すたびにここを書き直す。

**`set_world_note(slot: 'rules')` に置くもの** — 仕組みを跨いだ全体の縛り。

```
slot: rules（この作品の約束事）
灯の設定を、話の途中で拡張しない。新しい効果を足したくなったら、
それは special に書いた「できないこと」を削る作業になる。削るなら伏線を先に張る。
主人公の窮地を灯で解決しない。灯は問題を減らす道具ではなく、代価を払う場所として使う。
```

**`set_world_note(slot: 'reveal')` に置くもの** — 仕組みを読者にどこまで見せるかの方針。個別の秘密は `secret` が持つ。

```
slot: reveal（何を、いつ明かすか）
灯の原理は最後まで説明しない。読者には、使われた場面の結果だけを見せる。
「できないこと」は登場人物が試して失敗する形で見せ、地の文で規則として書かない。
```

**`upsert_secret` へ** — 仕組みのうち、読者が知らないでいる部分。

```
title: 灯が血を選ぶ
truth: 血縁者どうしがくべると両方が燃える。灯兄弟の決まりはこの事故を防ぐために生まれた。
reveal_beat_id: <トウマとアカリが組もうとして拒まれるビート>
```

```
title: 母がくべたもの
truth: 母は娘のことを灯にくべた。だから母は最期まで娘を思い出せなかった。
reveal_beat_id: <最終部・口伝を聞くビート>
keep_hidden: false
```

**`upsert_foreshadow` へ** — 「できないこと」を後で効かせるための布石。

```
title: 死者の記憶は燃えないこと
note: 序盤で誰かが試して失敗する場面を置き、終盤で主人公が同じ壁に当たる。
plant_beat_id: <第一部・老人が試みるビート>
payoff_beat_id: <第三部・主人公が母を求めるビート>
```

### 3-4. 質が落ちる兆候と、編集者が言うべき反対意見

**兆候A：限界と代償が無く、いまの問題を解決できてしまう**
最も多く、最も深刻。

> 「この仕組み、第五話の『船が出せない』という問題を**そのまま解決できます**。解決しない理由が用意されていないので、読者は第五話を読みながら『使えばいいのに』と考えます。方法はふたつあります。使えない条件を仕組み側に足すか、第五話の問題を仕組みが届かないところへ移すか。どちらを取りますか」

**兆候B：後出しの新ルール**
終盤で「実は距離を越えられる」「実は二回まで使える」が生える。

> 「第九話で灯が灯台の外で働いています。これは `special` に書いた『灯台から離れた場所では起きない』と衝突します。
> 拡張するなら、**第三話までのどこかに、それを匂わせる場面を先に置きましょう**。伏線として `plant_beat_id` を第三話のビートに立てて、第九話を `payoff_beat_id` にします。先に置けないなら、第九話の解決を別の手に変えるほうが早いです」

**兆候C：主人公が使えて、しかも上手い**

> 「主人公が最も上手く使えるという設定を、いったん外してみませんか。**下手なほうが、周りの人物に役が回ります**。いまの原稿だと、他の登場人物が主人公の技を見て驚くだけの役になっています」

**兆候D：説明が本文の会話に落ちてくる**
登場人物が読者向けに仕組みを解説する場面がある。

> 「この会話、**話している二人はどちらもこの仕組みを知っています**。知っている者どうしが説明し合うのは不自然なので、ここは説明を削って、代わりに『失敗する場面』に置き換えませんか。読者は規則を聞くより、破れた結果を見るほうが早く覚えます」

**兆候E：設定が精緻で、本文に届く場所がない**
`special` が 80 行あるのに、本文で使われるのは 1 種類だけ。

> 「`special` の 80 行のうち、本文に出ているのは冒頭の 6 行ぶんです。残りは**いま書いていない話のための設定**になっています。捨てなくていいので、`custom` の自由枠（見出し例：使っていない灯の規則）へ移して、`special` は本文で使う範囲だけにしませんか。`special` は執筆のたびに読み返す枠なので、短いほど守られます」

**兆候F：制度の名前だけがあって、運用者がいない**

> 「この制度、誰が運用しているか決まっていません。運用する側に**得をしている人**がいると、制度が急に動き出します。誰か一人、名前を付けませんか」

**兆候G：「できないこと」が実質できてしまう抜け道**

> 「『死者の記憶は燃えない』のに、第七話で死者の遺品を経由して同じ結果が出ています。抜け道は、あってもいいです。ただし**その抜け道の代償**が要ります。無いなら、それは制限を書いていないのと同じです」

**兆候H：仕組みが増える**
新しい話ごとに新しい仕組みが足される。

> 「いま `special` に仕組みが 4 つあります。読者が覚えられる仕組みは、多くて 2 つです。**主人公が代価を払う 1 つ**を残して、残り 3 つは道具（アイテム）か制度に格下げできませんか」

### 3-5. 矛盾検査のチェック項目

- `special` の「できないこと」を、既出の本文（`get_work`）のどこかが破っていないか。**破っている箇所を必ず話数で示す**
- `special` の「いまの葛藤との関係」の行が、現在のビート表の主要な障害と噛み合っているか。噛み合わなくなったら書き直す
- `rules` の「拡張しない」宣言と、直近で足した設定が衝突していないか
- 用語集 `summary` に限界・代償・例外が漏れていないか（漏れていたら `special` へ移し、`summary` は現象の記述だけにする）
- その仕組みに関する `secret` の `reveal_beat_id` より前に、`summary`（公開経路）が真相を含んでいないか
- 「できないこと」の各項目に、対応する `foreshadow` があるか。無い制限は、終盤で読者に「ご都合」と読まれる
- `foreshadow` の状態が `orphan`（回収だけある）になっている仕組み関連の項目がないか。`get_plot` の伏線行で確認できる
- `reveal` に書いた開示方針（説明しない、結果だけ見せる等）を、本文の地の文が破っていないか
- 認知度（A〜E）と、本文で人物が見せる反応が一致しているか。日常に組み込まれているはずの仕組みに、人物が毎回驚いていないか
- 資格の有無と、本文で実際に使っている人物の資格が一致しているか
- 同じ仕組みが用語集に 2 件（別名で）登録されていないか。`aliases` へ統合する

## 4. アイテム

### 4-1. 掘る順番と問いの文面

**① 誰の手にあるか、どこから来たか**

> 「それはいま誰が持っていますか。**その人の手に渡った経緯**は、買った・拾った・盗んだ・譲られた・遺された・押しつけられた、のどれですか」

譲られた・遺された・押しつけられた、は関係を持ち込むので物語向き。

**② 手放せるか**

> 「その持ち主は、それを手放せますか。手放せないなら、**手放せない理由**は物理的なものですか、心理的なものですか」

**③ 壊れるか、無くなるか**

> 「それは壊れますか。**壊れたら話はどうなりますか**。壊れないなら、なぜ壊れないのですか」

壊れないアイテムは緊張を作らない。

**④ それを欲しがっている人**

> 「その持ち主以外に、それを欲しがっている人はいますか。いないなら、**なぜ誰も欲しがらないのか**を決めてください」

**⑤ 使うときの手順と、使えない状況**

> 「使うのに、時間・場所・準備・同伴者のうち何が要りますか。**手ぶらで、いますぐ使える**なら、それは劇の道具として弱いです」

**⑥ 大きさと持ち運び**

> 「懐に入りますか。両手が要りますか。**隠せますか**。隠せるかどうかで、逃げる場面の書き方が変わります」

**⑦ 見た目の一点**

> 「読者がその物を思い出すときの**一箇所**を決めてください。傷、色、欠け、匂い、重さ、音のどれかで」

**⑧ 最後にどうなるか**

> 「その物は、最終話でどこにありますか。渡す、捨てる、壊す、埋める、そのまま持っている、のどれですか」

出口を先に決めておくと、途中の扱いが締まる。

### 4-2. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「強力な剣です」 | 「その剣を持った主人公が**負ける場面**は書けますか。書けないなら、剣が強いぶん、以後すべての戦闘の緊張が消えます」 |
| 「形見のペンダントです」 | 「形見であることは、本文の**どの場面で効きますか**。効く場面がないなら、いまは持たせるだけにして、設定は増やさないほうがいいです」 |
| 「便利な道具です」 | 「便利さは物語の敵になりやすいです。**その道具を使うと事態が悪くなる場面**を 1 つ作れませんか」 |
| 「主人公の相棒の武器です」 | 「その武器で、相棒は**誰かを傷つけたことがありますか**。あるなら、それが武器の性格になります」 |
| 「魔法の鍵です。あらゆる扉を開けます」 | 「開かない扉を 1 つ決めてください。その 1 つが、たぶん終盤の扉になります」 |
| 「特に意味はない小物です」 | 「意味がないほうがいい小物もあります。ただ、用語集に登録するかは別です。**本文で二度以上出るなら登録、一度きりなら登録しない**でどうですか」 |

### 4-3. 決まったことの振り分け

**`summary`（公開情報）**

```
名前: 潮見の錠
分類: アイテム
公開情報:
灯台の扉に付いている真鍮の南京錠。海風で緑青が浮き、鍵を差すたびに軋む。
鍵は二本あり、当番の二人が一本ずつ持つ決まり。
```

**`author_note`（非公開）**

```
作者メモ:
二本目の鍵は二十年前から行方不明。町長が持っている。
第三部で扉が内側から開いていた理由がこれ。→ foreshadow「二本目の鍵」
```

**`set_world_note` へ** — アイテムの効き方が仕組みなら `special`、扱いの決まりなら `rules`。

```
slot: rules（この作品の約束事）
道具で問題を解決しない。道具は「持っていることが誰かに知られる」ためにある。
主人公が窮地で新しい道具を取り出す展開を書かない。持ち物は第一話で全部見せておく。
```

**`upsert_foreshadow` へ** — アイテムはほぼ必ず伏線になる。`plant` と `payoff` を最初に決める。

```
title: 二本目の鍵
note: 第一部で「鍵は二本」と当番の会話に一度だけ出す。第三部で内側から開いていた扉に繋げる。
plant_beat_id: <第一部・当番の引き継ぎビート>
payoff_beat_id: <第三部・扉が開いているビート>
```

**ビートへ** — 物の受け渡しは出来事なので、ビートを立てる。`summary` に「◯◯が××へ渡す」と書く。用語集の中に受け渡しの経緯を書くと、時系列が本文と切れる。

### 4-4. 質が落ちる兆候と、編集者が言うべき反対意見

**兆候A：物語のどこでも機能しない**
登録されているが、本文で一度も持ち出されない。

> 「用語集のアイテム 11 件のうち、本文に出るのは 3 件です。**残り 8 件は読者に届いていません**。使う予定のある物だけ残して、あとは削るか `custom` の自由枠へ移しませんか」

**兆候B：ご都合の道具**
窮地の直前に持っていたことが判明する。

> 「第六話で袋から出てきたこの道具、**第一話の時点で持っていたことを読者は知りません**。持たせるなら第一話で見せておきましょう。見せられないなら、この場面は道具なしで切り抜けさせるほうが強くなります」

**兆候C：壊れない・失くさない**

> 「この物、全編を通して一度も持ち主の手から離れません。**一度奪われて、取り返す**か、**壊れて、それでも進む**か、どちらかを入れませんか。持ち続けているだけだと、読者はその物を装備品として見ます」

**兆候D：由来が精緻で、いまの話に繋がらない**
鍛冶師の名、製作年、素材の産地が用語集に並んでいる。

> 「由来が 6 行ありますが、本文で誰かがそれを口にする場面がありません。**この 6 行のうち、持ち主が知っていることは何行ですか**。持ち主が知らないことは `author_note` へ移して、公開情報は持ち主の目に見える範囲に絞りましょう」

**兆候E：持っていることのリスクがない**

> 「これを持っていると危ない、という状況はありますか。無いなら、**隠す必要のない物**です。隠さなくていい物は、読者の緊張に参加できません」

**兆候F：同じ機能の物が複数ある**

> 「この 3 つの道具、いずれも『危険を知らせる』機能です。1 つに統合しませんか。**同じ機能が複数あると、どれが使われるかを読者が予想できなくなり、緊張ではなく混乱になります**」

### 4-5. 矛盾検査のチェック項目

- `rules` の道具に関する縛り（新しい道具を出さない等）を、直近のビートが破っていないか
- そのアイテムに紐づく `foreshadow` の状態が `orphan`（回収だけある＝置き忘れ）でないか
- 所在の時系列が本文と一致しているか。第 N 話で渡した物が、第 N+2 話で元の持ち主の手にある、という取り違えが起きやすい
- `special` に書いた仕組みの制限と、そのアイテムの効果が衝突していないか（アイテムだけが制限を越えていないか）
- そのアイテムの `summary` が、`secret` の真相を先に説明していないか
- 大きさ・重さ・隠せるかが、本文の逃走・潜入の場面と矛盾していないか
- 用語集に別名で二重登録されていないか（`aliases` に統合）
- そのアイテムが登場するビートの `place` と、アイテムの保管場所が食い違っていないか

## 5. 生物

### 5-1. 掘る順番と問いの文面

**① 人との距離から入る**

> 「その生き物と人は、どういう関係ですか。
> A：飼っている・使役している
> B：狩る（食う・売る）
> C：狩られる（人が餌になる）
> D：住み分けている（互いに近づかない）
> E：気づかれていない
> F：かつて A だったが、いまは C」

**② 何を食い、どこで寝るか**

> 「何を食べますか。**その餌は、この土地にありますか**。寝床はどこですか」

生態の芯はこの 2 つ。ここが決まると、出没する場所と時刻が自動的に決まる。

**③ 数**

> 「何頭いますか。1 頭だけですか、群れですか、いくらでも湧きますか。**いくらでも湧くなら、なぜ町が滅びていないのですか**」

**④ 人はそれをどう扱っているか（制度・慣習）**

> 「その生き物について、町には決まりごとがありますか。狩ってよい時期、近づいてはいけない場所、見たときの作法、供養、届出。**人の側の対応が決まると、生き物が世界に定着します**」

**⑤ 殺せるか、殺すとどうなるか**

> 「殺せますか。殺した人はどうなりますか。**咎められますか、褒められますか、何も起きませんか**」

**⑥ 意思の有無**

> 「それは、話が通じますか。通じないなら、**人がそこに意味を読み取ってしまう**場面はありますか」

意思を持たない生き物に人が意味を読むところに、いい場面が生まれる。

**⑦ 見た目より先に、遭遇の兆し**

> 「読者がその生き物の登場を察するのは、姿より先に何ですか。音、匂い、鳥が黙る、水が濁る、犬が怯える。**兆しがあると、出てくる前が怖くなります**」

**⑧ 主人公との一件**

> 「主人公は、その生き物と**一度でも個体として向き合いますか**。群れの一匹ではなく、あの一匹として」

### 5-2. 浅い答えへの追撃

| 浅い答え | 追撃の文面 |
|---|---|
| 「凶暴な魔物です」 | 「凶暴なのは、腹が減っているからですか、縄張りを侵されたからですか、痛いからですか。**理由がある凶暴さのほうが怖い**です」 |
| 「森に住む幻獣です」 | 「幻というのは、**目撃例が少ない**という意味ですか、**実在が疑われている**という意味ですか。どちらかで、町の人の反応が変わります」 |
| 「主人公の相棒の獣です」 | 「その獣は、主人公の言うことを**聞かない場面**がありますか。全部聞くなら、それは道具です」 |
| 「大量に湧きます」 | 「湧くペースと、人が減るペースを比べてください。**町が既に滅んでいる計算になっていませんか**」 |
| 「絶滅危惧種です」 | 「保護している人がいますか。保護と、それで食っている人の利害はぶつかりますか」 |
| 「知能が高く、人語を解します」 | 「では、それは生物ではなく**人物として書ける**ということですか。人物なら分類を『人物』に移して、人物として深掘りしましょう」 |
| 「見た目は狼に似ています」 | 「似ているものを言うと、読者は狼を思い浮かべて終わります。**狼と決定的に違う一点**を挙げてください」 |

### 5-3. 決まったことの振り分け

**`summary`（公開情報）**

```
名前: 潮鳴きの群
分類: 生物
別名: 潮鳴き
公開情報:
凪の夜だけ岬の沖に浮かぶ、掌ほどの発光する魚の群れ。
灯台の光に集まる性質があり、当番はこの群れが来た夜を「当たり夜」と呼ぶ。
獲るのは禁じられていて、網にかかったものはその場で海へ返す。
```

**`author_note`（非公開）**

```
作者メモ:
禁漁の理由は、二十年前に獲った船が全員戻らなかったから。
町の人はこの理由を口にしない（＝本文でも説明させない）。→ secret「当たり夜の船」
```

**`set_world_note` へ** — 生態が世界の仕組みなら `special`、人との関わりの決まりなら `society`、禁忌なら `rules` か `forbidden`。

```
slot: society（人を縛るもの）
この町では、海のものを獲る・獲らないの線引きが人の格を決める。
禁を破った家は名指しで責められず、ただ誰も口をきかなくなる。
```

```
slot: special（固有の仕組み）
【潮鳴き】灯の光に反応して発光する。光っているあいだ、その海域では音が遠く聞こえる
（＝声が届かない）。これは灯の副作用で、独立した仕組みではない。
できないこと：捕らえても光らない。陸へ上げると即座に死ぬ。飼えない。
```

```
slot: rules（この作品の約束事）
生き物に人語を話させない。意思を持つように見える場面は書くが、
それが本当に意思だったかは最後まで決めない。
```

**`upsert_secret` へ**

```
title: 当たり夜の船
truth: 二十年前、当たり夜に沖へ出た船が戻らなかった。禁漁はその後に決まった慣習で、
理由を知る者は町長と老人二人だけ。
reveal_beat_id: <第三部・老人が話すビート>
```

**ビートへ** — 遭遇は出来事。`place` に生息地の場所 entry_id を結ぶ。生き物そのものが個体として登場するなら `cast` に入れてよい。

### 5-4. 質が落ちる兆候と、編集者が言うべき反対意見

**兆候A：図鑑になっている**
体長・体重・生息域・繁殖期が並び、物語との接点がない。

> 「この 8 行は生態の記述で、**読者がこの生き物に出会う場面で要る情報が入っていません**。読者が知りたいのは、近づいていいのか、逃げるべきか、それを見た人がどんな顔をするかです。8 行を 3 行に落として、残りは `author_note` へ移しませんか」

**兆候B：出てくるだけで、話に噛まない**
背景の動物として登場し、いなくても話が進む。

> 「この生き物、いま**話の外にいます**。ひとつだけ噛ませるなら、主人公の選択を邪魔するか、主人公が守るかのどちらかです。どちらもしないなら、用語集から外して情景描写に溶かしましょう」

**兆候C：怪物が強すぎて、勝ち方が説明できない**

> 「この生き物に、主人公はどう勝ちますか。**いまの設定だと勝てません**。弱点を足すか、勝たない話にするか、決めてください。終盤で急に弱点が出てくるのが、いちばん読者が冷める形です」

**兆候D：種族が細かく、本文に 1 種しか出ない**

> 「生物が 9 種登録されていて、本文に出るのは 2 種です。**残り 7 種は世界の広さとして働きますか**。働かないなら、`custom` の自由枠にまとめて置いて、用語集は本文に出る 2 種だけにしましょう」

**兆候E：人が驚かない**
日常にいるはずの生き物に、登場人物が毎回新鮮に反応する。

> 「町の人にとってこれは日常のはずですが、第四話でみんな驚いています。**驚くのは主人公だけ**にして、周りは平然としているほうが、その土地の暮らしが伝わります」

**兆候F：残酷さが機能していない**
食う・殺す場面があるが、誰の心も動かない。

> 「この狩りの場面、**誰かが嫌がっていますか**。全員が平気だと、読者はこの世界の倫理を測れません。一人だけ手が止まる人を置きませんか」

**兆候G：生態が話の都合で変わる**
夜行性のはずが昼に出る、群れないはずが群れる。

> 「第二話では単独でしたが、第六話で群れています。**どちらが本当ですか**。群れることに理由があるなら、それは事件です。理由がないなら第六話を直しましょう」

### 5-5. 矛盾検査のチェック項目

- `special` に書いた生態の制限を、既出の本文が破っていないか（活動時間、食性、生息域）
- 生息地として書いた場所が用語集に存在し、その場所の `summary` の環境と食性が合っているか
- `society` / `rules` に書いた人との関わりの決まりを、本文の登場人物が破っていないか。破っているなら、それが咎められているか
- 数と被害の規模が、町の人口・存続と矛盾していないか
- その生き物に関する `secret` の `reveal_beat_id` より前に、`summary` が理由を説明していないか
- `rules` の「人語を話させない」等の縛りを、会話文が破っていないか
- 遭遇ビートの `place` と生息地が一致しているか。一致しないなら、なぜそこに出たかの理由が本文にあるか
- 「人物」として書くべきものが「生物」に登録されていないか（意思と会話があるなら分類を移す）
- 本文で使われている俗称・蔑称が `aliases` に入っているか

## 6. 掘り終えたあとの共通の締め（分類を問わず必ず投げる）

**① 届き先の確認**

> 「いま決まったことのうち、**読者に届くのはどれですか**。公開情報に置いた行だけが届きます。それ以外は、本文で誰かが言うか、やるかしない限り、読者には存在しません。届けたい 1 行を選んで、**どの話で出すか**決めましょう」

**② 器の点検**

> 「決まった内容を振り分けます。
> ・この項目を引く読者に要る説明 → 公開情報
> ・この項目に閉じた裏 → 作者メモ
> ・他の項目にも効く決め事 → `set_world_note`
> ・読者がいつ知るか → `upsert_secret`
> ・どこで置いてどこで効かせるか → `upsert_foreshadow`
> ・起きる出来事 → ビート
> どれにも入らないものは、いま要らない設定です」

**③ パッチ方式の確認（MCP で更新するとき）**

`upsert_glossary_entry` は id 指定の更新なら渡した項目だけを書き換える。公開情報だけ直すつもりで `author_note` や `thumbnail` を消さないよう、**触らない欄は引数に入れない**。消したい欄だけ空文字を渡す。

**④ 世界観設定の肥大チェック**

> 「`special` が 60 行を超えました。この枠は書くたびに読み返す場所なので、長いと守られなくなります。**本文で使う範囲**だけ残して、残りは `custom` の自由枠へ逃がしませんか」
