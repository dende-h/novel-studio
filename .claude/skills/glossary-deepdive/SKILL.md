# 用語集の 1 項目を掘る

用語集の項目を 1 つ選び、編集者として問いを重ねて設定を固める。
**スコープは指定された 1 項目だけ。** ほかの項目に穴が見えても、その場で直さず §7 で申し送る。

先に読む（どちらも必読）:

- `.claude/skills/kotonaha-editing-common/references/kotonaha-mcp.md` — 器の分かれ方と書き込みの規約
- `.claude/skills/kotonaha-editing-common/references/editor-stance.md` — 編集者の立ち方と、一論点ずつ掘る進め方

掘るときの観点:

- 人物 → `references/angles-person.md`
- 場所・組織・用語（仕組み）・アイテム・生物 → `references/angles-others.md`

## 0. 対象を確定する

作者が対象を指定してくる（「ユキを掘りたい」）。**指定が無ければ聞く。推測で始めない。**
作品が複数あるなら `list_works` で `work_id` も決める。

対象が用語集にまだ無いなら、その場で作らず「新規に立てる」ことの合意を先に取る。

## 1. 前提を読む

`get_world` → `get_plot` → `get_glossary` の順。順番を変えない（理由は共通リファレンス §3）。
対象の名前が本文に既出なら `get_work` も読む。**既に書かれた本文は動かせない前提**として扱う。

読み終えたら、対象について次を頭に置く。

- 世界観設定のどのルール（`rules` / `special` / `words` / `forbidden`）に縛られるか
- どのビートに `pov` / `cast` / `place` として出るか。そこで何を担っているか
- 関わる伏線・秘密はどれか
- 本文で既に読者へ渡っている情報は何か

## 2. 棚卸しして、作者に返す

**問いを投げる前に、いま何が決まっていて何が空白かを 1 度だけ提示する。** 作者は自分の設定を覚えている
つもりで忘れている。ここで「ビートでは第三幕で裏切るのに、用語集には裏切る理由が無い」のような穴が出る。

出す形は短く。決まっていること 3〜5 行、空白と気になる点を箇条書き、そして「どこから掘るか」の提案 1 つ。

## 3. 論点を立てて、順番を決める

観点表（`references/angles-*.md`）から論点を拾い、**物語に効く順**に並べる。

1. ビートが要求しているのに設定が無いもの（いま話を止めている穴）
2. 世界観設定・ビート・伏線・本文との矛盾
3. 描写に使える具体物が無い箇所（書けない設定は無いのと同じ）
4. あると深くなる空白

順番は内部で持つだけでよい。作者に一覧を突きつけない。

## 4. 一論点ずつ掘る

`editor-stance.md` の型に従う。**1 ターンに 1 論点。** 出すのは「いま分かっていること／私の見立て／問い」
の 3 点だけ。まとめて質問を並べない。

浅い答えには食い下がる。作者が即答できない箇所こそ本当の穴なので、そこは飛ばさない。
決まったら控えて次の論点へ。

## 5. 反対する

観点表の「作品の質が落ちる兆候」に当たったら、その場で言う。追従しない。
反対するときは必ず代案とセットで出す。決めるのは作者で、編集者ではない。

## 6. 書き込む

**書く前に、何をどの欄へどう書くかを提示して同意を取る。**

振り分けの原則（詳細は共通リファレンス §2）:

| 決まったこと | 行き先 |
|---|---|
| 読者が引いて役に立つ説明 | `upsert_glossary_entry` の `summary`（**公開される**） |
| この項目に閉じた内緒（正体・後の展開） | 同 `author_note`（公開時に落ちる） |
| 作品全体のルール・仕組み・執筆の決め事 | `set_world_note`（用語集へ書かない。**`body` は全置換**） |
| 読者にいつ明かすか | `upsert_secret` |
| 布石と回収 | `upsert_foreshadow` |
| 出来事として起きること | ビート → `beat-rework` スキルへ |

`upsert_glossary_entry` はパッチ方式。触らない欄は渡さない。`aliases` は配列なので渡すと丸ごと置換になる。

`set_world_note` だけはパッチではなく **`body` の全置換**。`get_world` でその枠の現在の本文を読み、
既存＋追加を組み立てた全文を渡す。追記のつもりで一段落だけ渡すと、その枠の既存の記述が消える。

文面は `natural-japanese` の作法で書く。数行を超えるものはスキルを通す。

## 7. 検算と申し送り

`get_glossary` を読み直し、意図した欄だけが変わっていることを確かめる。
`get_plot` に `[根なし]` `[開示未定]` が増えていないかも見る。

最後に、掘っている間に見つかった**スコープ外の宿題**を渡す。

- ほかの用語集項目に波及するもの → もう一度このスキルで、対象を変えて
- 世界観設定の枠が足りない・矛盾している → `world-deepdive`
- ビートの並びを直す必要がある → `beat-rework`
- 本文の改稿が要る → `novel-writing`
