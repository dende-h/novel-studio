# novel-writing — 小説の執筆・推敲

小説の本文を対象に「執筆制約 → 機械検査（textlint） → 目視レビュー → 収束」で回すスキル。
機械が拾えるもの（原稿作法・AI 常套句）は機械に任せ、機械が拾えないもの（視点・リズム・描写の質）を
目視レビューに集中させる。

## 0. 入口の判定

- **MCP 経由（コトノハ）**: 本文を書き換える前に必ず `get_world` で作品の決め事を読む（MCP サーバの手順に従う）。
  固有名詞・設定は `get_glossary` と照合する。完成した本文は `set_episode` で反映する。
- **ローカルファイル**: 対象ファイルをそのまま扱う。novel-studio の記法（ルビ `｜親《よみ》`・傍点 `《《》》`・
  シーン区切り `＊`・`[[参照]]`）は保持する。
- **診断だけ頼まれた場合**（「読んで感想を」「AI っぽいか見て」）: 本文は書き換えず、
  §2 の機械検査と §3 のレビュー観点で所見を返す。リライトは頼まれるまでしない。

## 1. 執筆 — 制約の下で書く

新規執筆・リライトの前に `references/style-guide.md` を読む。要点——視点を1話1つに固定する、
感情を名詞で名指しせず動作・知覚で見せる、説明しすぎない、会話と地の文で情報を運び分ける、
文長と段落に意図的なムラを作る、AI 常套句（辞書が拾う）を書かない。

## 2. 検査 — textlint

```bash
pnpm --dir tools/novel-textlint install       # 初回のみ
pnpm --dir tools/novel-textlint lint:novel <ファイル>
```

MCP 経由で本文がファイルとして存在しない場合は、本文をスクラッチパッドの一時ファイルに書き出してかける。
検出されるのは①小説作法（字下げ・閉じ括弧前の句読点・三点リーダー/ダッシュの偶数・！？後の全角スペース・
半角約物）、②同語連続、③AI 常套句・翻訳調（`【要修正】` / `【要検討】` ラベル付き）。

仕分けの原則:

- **作法系（general-novel-style-ja / novel-punctuation-ja）**: 原則すべて直す。ただし作品側に別の方針
  （字下げしない等）が世界観設定やユーザー指示にあるならそちらが優先。機械修正可能なものは `--fix` でよい
- **`【要修正】`**: 原則直す
- **`【要検討】`**: 文脈で判断する。**会話文の中は登場人物の声なので、キャラ付けとして正当なら残す**。
  地の文でも1回だけの使用は許容しうる。残す場合は理由を一言添えて報告する
- 誤検知が続く語はユーザーに確認のうえ `tools/novel-textlint/dict/` の辞書を調整する（カスタマイズ手順は
  同ディレクトリの README）

## 3. 目視レビュー — 機械が見ないもの

`references/review-checklist.md` の観点で通読する。最低限、視点のブレ・時制の乱れ・設定との矛盾
（MCP なら用語集・世界観設定と照合）・感情説明への逃げ・リズムの単調さを見る。

## 4. 収束・反映

修正したら lint を再実行し、新しい検出が出なくなるまで 2〜3 を繰り返す。完了後、MCP なら `set_episode` で
反映、ローカルならファイルを保存する。作業用の一時ファイル（lint 用の書き出し等）は削除する。
報告には「機械検査で何件拾って何を直し、何を意図的に残したか」を一言含める。
