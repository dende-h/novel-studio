# 波及範囲の洗い出しと、書き込みの順番

ビートは孤立していない。1 枚動かすと、伏線・秘密・用語集・本文・幕の並びが連れて動く。
**壊れても即座にはエラーにならない**（`[根なし]` の印が静かに増えるだけ）ので、手順で防ぐ。

## 1. 触るビートごとに、つながりを全部拾う

`get_plot` の出力から、対象のビートについて次を書き出す。

| 拾うもの | `get_plot` のどこに出るか | 外したときに起きること |
|---|---|---|
| 伏線の張り手 | 伏線一覧の「張る: ビート名」 | その伏線が `[根なし]` になる |
| 伏線の回収先 | 伏線一覧の「回収: ビート名」 | その伏線が `[未回収]` に戻る |
| 秘密の開示場所 | 秘密一覧の「読者に明かす: ビート名」 | その秘密が `[開示未定]` になる |
| プロットライン | ビート行の「ライン: …」 | そのラインの筋が 1 本抜ける |
| 視点・登場・舞台 | ビート行の「視点: / 登場: / 舞台: 」 | 用語集の項目が、どこにも出てこなくなる |
| 対応する話 | ビート行の「対応話: … [episode_id: …]」 | **本文と設計がずれる** |
| 作中時間 | ビート行の「作中時間: …」 | 前後のビートとの時間関係が崩れる |
| 幕の中の位置 | ビートの通し番号 | 因果の順序が入れ替わる |
| 予定文字数 | ビート行の「予定: …字」 | 幕の分量見込みが変わる |

拾い終えたら、**逆向きにも見る**。そのビートを参照している伏線・秘密が「ほかにもないか」を、
伏線一覧と秘密一覧を上から読んで確かめる。ビート側の行には出てこない。

## 2. 本文が書かれているビートは、勝手に動かさない

次のどれかに当たるビートは、本文の改稿とセットでしか動かせない。

- `status` が `執筆中` または `済`
- 「対応話: …」が付いている

読者に既に届いている話なら、なおさら動かせない。設計を本文に合わせるほうを先に検討する。

動かす必要があるなら、作者にこう出す。

> このビートは第三話として本文が書かれています。並べ替えると本文の改稿が要ります。
> (A) ビートを動かして本文も直す、(B) ビートは動かさず、要約だけ本文に合わせる、
> (C) 本文はそのままにして、前後のビートで辻褄を作る。

黙って動かさない。

## 3. 書き込む順番

**新しいものを作ってから、参照を移して、最後に古いものを消す。** 逆順にすると壊れる。

1. `upsert_plot_beat`（`id` を渡さない）で新しいビートを作り、返る `beat_id` を控える
2. `section_id` と `index` で幕と位置を決める（同じ呼び出しで渡してよい）
3. `upsert_foreshadow` で `plant_beat_id` / `payoff_beat_id` を新しい `beat_id` へ張り替える
4. `upsert_secret` で `reveal_beat_id` を張り替える
5. `delete_plot_beat` で古いビートを消す

先に 5 をやると、3 と 4 の張り替え先を失った伏線・秘密が `[根なし]` `[開示未定]` になる。

幕を消すとき（`delete_plot_item` の `kind: section`）は、中のビートが隣の幕へ移動する。
消えるわけではないが、**幕をまたいだ位置に移るので `index` を見直す**。最後の 1 幕は消せない。

## 4. パッチ方式の落とし穴

`upsert_plot_beat` は「渡した項目だけ書き換える」。ここまではよい。
問題は配列で、**`cast` / `place` / `line_ids` は渡すと丸ごと置換**される。

```
要約だけ直したい    → work_id, id, summary の 3 つだけ渡す
登場人物を 1 人足す  → 現在の cast 全員 ＋ 1 人の配列を渡す（差分ではない）
視点を外したい      → pov に空文字を渡す
予定文字数を消したい → target_length に 0 を渡す
```

`cast` を「追加のつもり」で 1 人だけ渡すと、ほかの登場人物が全員消える。
この事故は `get_plot` を読み直すまで気づけない。

## 5. 書いたあとの検算

`get_plot` を読み直して、改修前に控えた数と比べる。

- `[未回収]` の件数が増えていないか
- `[根なし]` が新しく出ていないか（出ていたら §3 の順番を間違えている）
- `[開示未定]` が増えていないか
- 触っていないビートの「登場: 」「舞台: 」「ライン: 」が消えていないか（§4 の事故）
- 幕の通し番号が意図どおりか

増えたものがあれば直す。**直せないものは、なぜ残るのかを作者に説明する。**
「あとで直します」で終えない。

## 6. まとまった改修の前に

幕をまたぐ組み直しのように、まとまった量を書き換えるときは `create_backup` で版を作る。
cloud 会員の機能なので失敗することがある。失敗したら作者に伝えて、続けるかどうかを聞く。
