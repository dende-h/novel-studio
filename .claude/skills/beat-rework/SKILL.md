# ビートを組み直す

ほかのスキル（`world-deepdive` / `glossary-deepdive` / `story-audit`）で出た指摘を、プロット側で直す。
**ビートは伏線・秘密・用語集・本文とつながっている。** 1 枚動かすと静かに壊れるものがあるので、
このスキルの本体は「直し方」より「波及範囲の洗い出し」と「書き込む順番」にある。

先に読む（どちらも必読）:

- `.claude/skills/kotonaha-editing-common/references/kotonaha-mcp.md` — 器の分かれ方と書き込みの規約
- `.claude/skills/kotonaha-editing-common/references/editor-stance.md` — 編集者の立ち方と、合意の取り方

- `references/impact-and-order.md` — 波及範囲の洗い出しと、書き込みの順番・落とし穴
- `references/structure-angles.md` — ビートの並びを良くするための編集者の目

## 0. 何を直すのかを 1 行で確定する

「どの指摘を受けての改修か」を最初に言葉にする。ここが曖昧なまま触ると、直しが際限なく広がる。

例:「第二幕でユキが港へ戻る動機が、用語集の『船を恐れている』と食い違う」

指摘の出どころが無く「なんとなく流れが悪い」なら、まず `story-audit` で診断してから戻る。

## 1. 前提を読む

`get_world` → `get_plot` → `get_glossary` の順。
**`status` が `執筆中` / `済` のビート、`対応話` が付いているビートがあるなら `get_work` も読む。**

## 2. 波及範囲を洗い出す

`references/impact-and-order.md` の手順。触るビートごとに、次のつながりを全部拾う。

- 伏線の `張る` / `回収` にそのビートが指定されているか（外すと `[根なし]`）
- 秘密の `読者に明かす` に指定されているか（外すと `[開示未定]`）
- 属しているプロットライン
- `視点` / `登場` / `舞台`（用語集の項目）
- `対応話`（本文が既に書かれているか）と `作中時間`
- 幕の中での位置と、前後のビートとの因果

**本文が書かれているビートは、本文の改稿とセットでしか動かせない。**
動かす必要があるなら、そのことを作者に明示して判断を仰ぐ。黙って動かさない。

## 3. 直し方の案を 3 つ出して、合意を取る

書き込む前に、必ず案を提示する。粒度を変えて 3 つ。

1. **最小** — 指摘だけを消す。要約やメモの書き換えで済む範囲
2. **中** — ビートを 1〜2 枚足す・並べ替える。前後の因果を通す
3. **根本** — 幕の構成や担い手を変える。本文の改稿を伴う

それぞれ「何が良くなるか」と「何を失うか」を書く。**編集者としてどれを推すかと、その理由も言う。**
決めるのは作者。作者が別の案を出したら、それがより良ければ採る。

## 4. 書き込む

順番を守る。逆順にやると伏線が `[根なし]` になる。

1. 新しいビートを `upsert_plot_beat` で作り、返ってきた `beat_id` を控える
2. 幕の位置を `section_id` と `index` で決める
3. 伏線（`upsert_foreshadow`）と秘密（`upsert_secret`）の参照を新しい `beat_id` へ張り替える
4. 不要になったビートを `delete_plot_beat` で消す

パッチ方式の落とし穴に注意する。`upsert_plot_beat` は渡した項目だけ書き換わるが、
**`cast` / `place` / `line_ids` は配列なので、渡すと丸ごと置換**になる。触らないなら渡さない。
空文字を渡すとその項目は未設定に戻る。

要約・メモは `natural-japanese` の作法で書く。`[[用語]]` は用語集にある名前に合わせる。

## 5. 検算する

`get_plot` を読み直して、次を全部確かめる。

- `[未回収]` `[根なし]` `[開示未定]` が**改修前より増えていない**
- 元の指摘（§0 の 1 行）が消えている
- 世界観設定の `rules` / `forbidden` に反していない
- 幕をまたぐ因果が「だから／しかし」でつながっている（`references/structure-angles.md`）

増えていたら直す。減らせないなら、なぜ残るのかを作者に説明する。

## 6. 申し送り

- 本文の改稿が必要になった話 → `novel-writing`（どの話の、どこを直すのかまで書く）
- 用語集の設定を足す必要が出た → `glossary-deepdive`
- 世界観設定の枠に落とすべき決め事が出た → `world-deepdive`
