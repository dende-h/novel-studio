# X 日次投稿（機能紹介動画）

1 日 1 本、機能の使い方を字幕つきの動画で見せて X に投稿する。道具は `tools/x-tutorial/`
（詳細は同 README）。**録る・変換する・送るのはスクリプト、見て判断するのが Claude** という分担。
台本と投稿文は PR で人が承認したものだけを流し、ルーティンの中で新しい主張を書き足さない。

## 毎日の手順

### 1. 下ごしらえ

```bash
command -v ffmpeg || (apt-get update -qq && apt-get install -y -qq --no-install-recommends ffmpeg)
pnpm install --frozen-lockfile
```

apt は索引が古いと 404 で落ちるので、必ず `apt-get update` を先に回す。

### 2. 今日の動画を録る

```bash
node tools/x-tutorial/record.ts --today
```

最後の行の JSON（`id` `title` `mp4` `seconds` `postFile` `frames` `problems`）を読む。
`problems` が空でなければ投稿しない（5 へ）。

### 3. 目で確かめる（投稿の可否はここで決める）

`frames` の PNG（6 枚）を Read ですべて見る。次のどれかに当たれば投稿しない。

- 字幕・見出しカードが欠ける、はみ出す、文字化け（□）している
- アプリがエラー画面・エラートースト・想定外のダイアログを出している
- 台本の操作が効いていない（例：ルビを振ったはずのプレビューにルビが無い）
- 真っ白・真っ黒のコマがある（冒頭と締めのカード以外）

直せるのが台本の待ち時間やセレクタだけなら、直して撮り直してよい（直した内容は報告に書き、
ブランチに push して PR を出す。main に直接入れない）。アプリ側の不具合なら投稿せず報告する。

### 4. 送る

まず試運転（何も送らず、文字数・URL の有無だけを検査する）：

```bash
node tools/x-tutorial/post.ts <mp4> <postFile>
```

`ok: true` で、かつ環境変数 `X_POST_LIVE` が `1` のときだけ本番：

```bash
node tools/x-tutorial/post.ts <mp4> <postFile> --live
```

- **`--live` は 1 日 1 回だけ。** 失敗しても自動で再実行しない。投稿が通ったか分からない
  失敗（タイムアウト・5xx）は、垢のタイムラインを人が見るまで再送しない（二重投稿を避ける）
- 投稿文は台本（`scenarios/<id>.ts` の `post`）のまま送る。ここで書き換えない
- `X_POST_LIVE` が無ければ試運転のみで終える（導入直後の確認期間用のスイッチ）

### 5. 報告する

チャットに次を短く書き、動画を SendUserFile で添える。

- 今日の機能（`title`）、動画の長さ、投稿の URL（試運転ならその旨）、`uploadVia`（v2 / v1.1）
- 見送った・失敗したときは理由と、見たコマのうち問題のもの

よくある失敗と、ユーザーに頼むこと：

| 症状 | 原因 | 頼むこと |
|---|---|---|
| `api.x.com` / `upload.x.com` に繋がらない | 環境のネットワーク設定が許可していない | 環境の設定（セッションのタイトルバーの環境メニュー → Edit）の Network access で両ホストを許可 |
| 環境変数が無いと言われる | 認証情報が未設定 | 同じ設定画面の環境変数に `X_API_KEY` `X_API_SECRET` `X_ACCESS_TOKEN` `X_ACCESS_TOKEN_SECRET` |
| 401 / 403 | 鍵の誤り、アプリの権限が Read だけ、v1.1 も拒否 | X Developer Console でアプリの権限を Read and write にしてアクセストークンを作り直す |
| 402 / 429 やクレジットの文言 | 従量課金のクレジット切れ・上限 | X Developer Console でクレジットを補充、または使用上限を見直す |

鍵の値をチャットに貼ってもらうことは頼まない。

## 台本を足す・直す

`tools/x-tutorial/scenarios/<id>.ts` に `Scenario` を書き、`scenarios/index.ts` の
**末尾**に加える（途中に挟むと以降の日の順番がずれる）。守ること：

- **30〜60 秒**（上限 140 秒）。冒頭カード → 操作と字幕 → 締めカード
- 冒頭カードは `{ kicker: '使い方', title: … }`。締めカードはゲストで使える機能なら
  `{ kicker: '登録もインストールも不要', title: 'コトノハ-leaf-', foot: '無料の縦書き小説エディタ' }`、
  無料登録が要る機能（`as: 'free'`）なら kicker を `'無料のアカウント登録で使えます'` にする
- 構想の道具（プロット・アウトライン・相関図・マインドマップ）は `as: 'free'` で撮り、投稿文にも
  無料のアカウント登録で使えることを書く
- 見せたい操作の前の準備（作品・話・用語を作る等）は `setup` に置く（録画に映らない）。
  共通の操作は `tools/x-tutorial/lib/app.ts`
- 見本の物語は全動画で共通：作品「月白の庭」、灯（あかり）＝庭に迷い込んだ少女、朔（さく）＝灯の幼なじみ、
  柊（ひいらぎ）＝庭守の老人、銀の鍵
- 字幕は 1 行 30 字ほどまで。長ければ `\n` で区切る（自動では折り返さない）
- 機能の説明は**コードで確かめた事実だけ**。書き出し・公開・課金に触れるときは実装を読む
- 投稿文は `toc-copy` スキルの作法で書き、URL を入れない（1 件 $0.20・表示回数も落ちる）。
  重み付きで 280 以内（全角は 2）。`post.ts` の試運転で確かめる
- 録画は空の IndexedDB から台本自身が作品を作る。利用者のデータや本番環境には触れない
- 並びに入れる前は `node tools/x-tutorial/record.ts tools/x-tutorial/scenarios/<id>.ts` で試し撮りし、
  3 の観点でコマを見てから PR に出す
