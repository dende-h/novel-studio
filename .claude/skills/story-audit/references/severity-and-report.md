# 重大度の付け方と、所見の出し方

点検は「見つけること」より「作者が動ける形で渡すこと」で価値が決まる。
50 件の指摘を並べた報告は、0 件の報告とほとんど同じ結果になる。

## 1. 重大度の定義

| 重大度 | 定義 | 判定の目安 |
|---|---|---|
| **破綻** | このままでは話が成立しない | 直さないと先のビートが書けない。読者が「おかしい」と気づく |
| **矛盾** | 設定どうし、設定とビート、ビートと本文が食い違う | どちらかが嘘になっている。両立する読み方が無い |
| **弱点** | 成立はするが、読者が離れる | 間違ってはいないが、面白くない・分かりにくい・遅い |
| **機会** | 直さなくてよいが、やれば良くなる | いま無くても困らない。あると作品が一段深くなる |

判定に迷ったら、**「この 1 件だけを直さずに刊行したらどうなるか」**で決める。
話が破れるなら破綻、読者が引っかかるなら矛盾、読むのをやめるなら弱点、何も起きないなら機会。

**公開事故（用語集の公開情報にネタバレが入っている）は、この 4 段階の外に置いて最初に出す。**
作品の質の問題ではなく、読者に実害が出ている問題なので、重大度で相対化しない。

## 2. 出す順と、量

```
1. 公開事故            … 全件。最優先
2. 破綻                … 全件
3. 矛盾                … 全件
4. 弱点                … 重い順に 3〜5 件
5. 機会                … 3 件まで
6. 残りの一覧          … 見出しだけ 1 行ずつ
```

**量を絞ることと、言うべきことを言わないことは別。** 削るのは紙幅と順序であって、指摘そのものではない。
弱点が 20 件あるなら、5 件を本文で扱い、残り 15 件は §6 の一覧に見出しだけ並べる。
「ほかにもありますが省きます」で終わらせない。作者が拾えるように、全部の名前は残す。

## 3. 1 件の書き方

```
### [重大度] 見出し（何が起きているかを 1 行で）

**どこ** … データ上の位置（ビート名 / 用語集の項目名 / 世界観設定の枠）
**何が** … 食い違いの中身。両側を引いて並べる
**なぜ問題か** … 読者にどう見えるか。物語のどこに効くか
**案** … すぐ直せる形／構造を変える形
**引き継ぎ** … どのスキルで直すか
```

書き方の約束。

- **両側を引く。** 「矛盾しています」ではなく、「用語集には A、ビートには B」と並べる。
  作者は自分の設定を覚えているつもりで忘れている
- **なぜ問題かを、作品のどこで説明する。** 「一般に良くない」は指摘にならない
- **案は必ず 2 種類。** すぐ直せる形（要約の書き換え、1 文の追加）と、構造を変える形
  （ビートを足す、幕を組み替える）。作者がどれだけ直す気があるかは分からないので、両方渡す
- 断定できないものは断定しない。「読み落としかもしれませんが」を付けてよい。
  ただしそれを免罪符にして、曖昧な指摘を量産しない

## 4. 良いところも言う

機能している箇所は言う。理由を添えて言う。

> 第二幕の「鍵を捨てる」は効いています。ユキが自分で選んだ最初の行動で、
> しかも第三幕で拾い直せる形で捨てている。ここは動かさないほうがいい。

作者は自分の作品のどこが効いているか分かっていないことがある。
**触ってはいけない箇所を教えるのは、点検の仕事の一部。**
ただし前置きの世辞にしない。冒頭を褒め言葉で埋めない。

## 5. 報告の頭に置くもの

所見の前に、3〜4 行で全体像を渡す。

- 何を読んだか（世界観設定 N 枠、幕 N・ビート N、用語集 N 項目、本文 N 話）
- いちばん重い問題を 1 行で
- 全体としてどういう状態か（土台はできている／設計が先行して本文が追いついていない、など）

ここに前置きを書かない。「本点検では」で始めない。

## 6. 点検が扱わないこと

- **深掘り。** 1 か所を掘るのは引き継ぎ先のスキルの仕事。ここでは「掘る必要がある」と指摘するまで
- **書き込み。** 原則として器を書き換えない（例外はスキル本体の §6）
- **本文の文章の質。** 誤字・言い回し・リズムは `novel-writing` の領分。
  ここで見るのは、本文と設計の食い違いまで
